# 需求拆解：结构化分段 + 富文本编辑

> 2026-11-04 · 老大提的两条需求，先对理解、再定方案。**本文件只拆需求，不含实现结论。**
> 涉及代码：`src-tauri/src/script.rs`（切段）、`src-tauri/src/doc.rs`（docx/pptx 抽取）、
> `src/components/PrompterView.tsx`（渲染）、`src/styles.css`（排版）、
> `src/components/PasteImport.tsx`（现有唯一编辑入口）、`src-tauri/src/library.rs`（落盘）。

## 0. 一句话

这两条需求看起来是"排版变好看"和"加个加粗按钮"，实际是**一件事**：
现在"文本"这一层同时扛着三件互斥的活 —— 显示、语音对位、存档 —— 所以任何一处排版变化都会被另外两处拖住。
真设计题是**把"样式"从"文本"里剥出来，做成文本之上的一层**；剥出来之后，分段和富文本都是它的两个用法。

## 1. 现状诊断：为什么现在"挤成一团"

不是 CSS 没调好，是切段逻辑**主动把换行吃掉了**。四处叠加：

| # | 位置 | 现在做了什么 | 你看到的结果 |
|---|---|---|---|
| 1 | `script.rs` 扫描 `raw.lines()` | 连续的非空行用**一个空格**拼进同一段（`buf.push(' ')`） | 你粘贴时每一行之间的换行**全部消失**，五行并成一行 |
| 2 | 同一处 `line.trim()` | 每行首尾空白被砍掉（含全角空格） | 首行缩进、编号缩进丢失，一眼看不出层级 |
| 3 | 空行只当"分段符" | 空行本身不产生可见留白，段距固定 `margin-bottom: 16px` | 34px 字号下 16px 只有半行高，段落之间**看着还是连着的** |
| 4 | `doc.rs::tidy()` | 每个 `.docx` 段落也 `trim()`、连续空行压成一 | 从 Word 导入的稿子**在进门那一刻**格式就没了 |

补一个这次排查顺手发现的**现存缺陷**：`looks_like_heading()` 让 `# 标题` 单独成段，但那段文本里的 `#`
**没有被去掉**，渲染时连 `#` 一起显示（对位时 `#` 会被当标点丢掉，所以不算错位，只是难看且会念出来）。

## 2. 需求拆成三层

我把它拆成三个可独立验收的层，**先后顺序就是依赖顺序**：

| 层 | 内容 | 用户能感知的变化 | 依赖 |
|---|---|---|---|
| **P0 结构保真** | ① 硬换行保留（不再合并成一行）② 空行变成真实段距 ③ 行首空白保留（缩进）④ 标题行单独排版且去掉 `#` ⑤ `doc.rs` 同步（不再 trim、不再压空行） | 粘贴什么形状，读的时候就是什么形状 | 无 |
| **P1 样式层** | 选区级：加粗 / 斜体 / 下划线 / 文字色 / 背景色；样式与文本**分开存**；编辑入口升级 | 能划重点：红字＝别念、加粗＝重音、底色＝引用原文 | P0（要先有稳定的"行/段"再谈选区） |
| **P2 导入保真** | `.docx` 里的 run 属性（粗/斜/色）映射成 P1 的样式层 | 从 Word 贴进来的重点标注**不用重做一遍** | P1（否则无处安放） |

★ P2 明确**不搬**字号和字体：提词器的字号是 `--fs` 34px 再按"离当前段多远"衰减，
搬进来五档字号会让投影上出现五种大小，直接毁掉"下几个字看得清"这个第一要务。

## 3. 需要你拍板的点

| # | 问题 | 选项 | 推荐 | 依据 |
|---|---|---|---|---|
| ① | **硬换行**算"段内换行"还是"新段落"？ | A 段内 `<br>` / B 独立段落 | **A** | 段内换行不改变"上一段/下一段"的粒度和句子的切分口径，对位系统一行不用改；选 B 会让"下一段"退化成"下一行"，且每行都吃 16px 段距，反而更像散落的纸条 |
| ② | 网页/飞书复制来的**软换行**（源里每 30 字断一行）怎么办？ | A 严格按原文 / B 智能合并 / C 严格 + 一键合并按钮 | **C** | 你要的是"原样"，A 是默认；但"原样"在某些源上会变成每行一句的碎块，得给一个手动出口，且在编辑弹窗里，不占正文界面 |
| ③ | **样式粒度**：整段 / 任意选区？ | A 整段 / B 选区 | **B** | 你的原话是"对所有的文字进行编辑"；且"划重点"天然是选区动作。整段可以视为选区的一种特殊情况，不用两套 |
| ④ | **编辑在哪发生**？ | A 升级现有"粘贴/编辑"弹窗为富文本 / B 正文区直接所见即所得 / C 另开编辑窗口 | **A** | 现有弹窗已经是"改稿"的唯一入口（同一件事只准一支按钮）；B 与"单击跳读""拖选复制"直接打架，还要新增阅读/编辑模式开关；C 是又一层窗口 |
| ⑤ | **样式存哪**？ | A sidecar（`<id>.style.json`） / B 稿件升级成单文件 JSON | **A** | 现在 pasted 稿是 `scripts/<id>.txt`。sidecar 不动文本文件 ⇒ 老的 .txt 仍可被任何编辑器打开、文件来源的稿子也能挂样式；B 要迁移所有历史稿并破坏"纯文本"这个逃生口 |
| ⑥ | **颜色**给到什么程度？ | A 几个语义预设 / B 自由取色器 / C 预设 + 自由 | **C** | 预设覆盖 90% 场景（重点/次要/警示/高亮底），自由色兜住剩下 10%。★ 深色主题下自由色可能不可读 ⇒ 需要"深色模式自动提亮"这条兜底 |
| ⑦ | **P2（docx 保真）**这一轮做不做？ | A 做 / B 下一版 | **B** | P0+P1 已经是这轮的全部工作量（要动渲染三条既有链路 + 存储 + 编辑器）。docx 的 run 属性解析是独立一块，塞进来会让这一轮没有可交付的中间态 |

**必答的只有 ①②④**，其余三个如果你没意见我就按推荐走。

## 4. 必须守住的既有判据（这一轮最容易撞的）

1. **样式不得改变文本**。对位靠 `offset_in_sentence`（字符下标）+ `charIndexAt`（UTF-16 累加）
   ⇒ 一旦"加粗"实现成**引入或隐藏可见字符**（典型：把 Markdown 的 `**` 藏起来），
   显示文本 ≠ 原文，高亮会差位、点句会跳错。样式只能做成 `<span style>` 这一层。
2. **层次做在段落上，不做在句子上**（字号用 `font-size` 不用 `transform`）。
   加粗会不会改行宽？会轻微改，但那是用户自己的选择；**字号仍然只有 `--fs` 一个源**。
3. **一屏字数会变**。段距从 16px 变成真实空行后，可视行数减少 ⇒ 锚点 `anchor=0.36` 的手感要重测，
   不能改完不试。
4. **当前句的卡拉OK三段**（`.sung / .singing / .unsung`）与用户自设颜色会**叠在同一串字上**，
   优先级必须定死：**正在念的那个字 > 用户颜色 > 已读/未读**（否则"念到哪"会被颜色盖掉）。
5. **隐身不能破**。编辑态发生在被投屏的那块窗口上 —— 要确认编辑时光标/选区不会漏进采集
   （现有隐身的机制是 `WDA_EXCLUDEFROMCAPTURE`，理论上覆盖整窗，但改版后要真机验一次）。
6. 硬门槛照旧：`cargo test --lib` 118 passed、六道静态门槛、tsc 零错。
   `script.rs` 是纯函数层 ⇒ 分段规则必须先写成单测，再改渲染。

## 5. 验收标准（可检查，不是"看着还行"）

| 项 | 怎么验 |
|---|---|
| 结构保真 | 造一份含 3 个空行、2 处缩进、5 处硬换行的样例 → 段落数 = 4，行数/缩进与原样逐字符一致（单测焊死） |
| 标题 | `# 季度复盘` 显示为「季度复盘」且字号/位置与正文有层级差 |
| 样式持久 | 加粗 + 一处红字 → **关掉应用重开**仍在（含从历史里重新载入） |
| 不掉对位 | 全套样式加满后，用示例稿跑跟读，逐字高亮仍然对齐；点任意句能跳对地方 |
| 三档主题 | 深色 / 浅色 / 磨砂三档下红字与底色都可读（出三张图） |
| 老稿兼容 | 升级前存在的 `.txt` 历史稿仍能载入、仍能编辑、样式层为空不报错 |

## 6. 明确不做（避免范围滑走）

- 不做"字号 / 字体 / 行距"的逐段自定义 —— 与 `--fs` + 距离衰减的整套排版判据冲突。
- 不做表格、图片、分栏。
- 不做"导出回 .docx"。
- 不把样式写进 `.txt`（会污染纯文本，且破坏"拿记事本也能改"这个逃生口）。

## 7. P0 落地记录（2026-11-04 已实现）

拍板：①A（硬换行＝段内 `<br>`）、②C（严格保真，编辑弹窗里留一键合并的出口，待 P1）、
④A（升级现有弹窗）、③B（选区）、⑤A（sidecar）、⑥C（预设＋自由色）、⑦B（P2 下一版）。

这一轮**只做 P0**（结构保真），P1 样式层与 P2 docx run 保真未动。

| 改动 | 位置 | 判据 |
|---|---|---|
| 连续非空行不再用空格拼平，改为保留 `\n` | `script.rs::join_lines` | 这是"挤成一团"的直接成因 |
| `Paragraph` 增 `blank_before` / `heading`，`Sentence` 增 `line_break_before` | `script.rs`（都带 `serde(default)`） | 老稿件/老前端读到新字段不会炸 |
| `\n` 只结句、**不进句子文本**；行尾空白砍、行首保留 | `script.rs::push_sentence` | 换行若进文本，`offset_in_sentence` 与 DOM 下标会差位 |
| 标题去掉 `#`；`---` 分隔线整块丢弃 | `script.rs::heading_of` | 原来 `#` 会显示在正文里 |
| docx 的 `</w:p>` 改成**空行**（段落边界），`<w:br/>` 仍是单换行 | `doc.rs::extract_from_xml`（新增 `para_tags`） | 原来两者都是单换行 ⇒ 整份 Word 一段 |
| `tidy` 不再 trim 行首、不再把段落压回去 | `doc.rs::tidy` | 缩进要靠行首空白 |
| 段前留白按 `blank_before` 算；`.para` 加 `white-space: pre-wrap` | `styles.css` | 空白/缩进要看得见 |
| 标题档位：字号 = `--fs × 1.1 × 距离衰减` | `styles.css .para.head` | 仍然只有一个字号源 |
| 句子前插 `<br>`（按 `line_break_before`） | `PrompterView.tsx` | `<br>` 不产生文本节点 ⇒ 点句下标不变 |
| 编辑弹窗往返：段内换行保留、标题补回 `#`、空行数按 `blank_before` | `PasteImport.tsx::scriptToText` | 否则"打开编辑→保存"会把结构吃掉 |
