## 3. 第一件要查的事：升层对不对（★★★ 最高风险）

> **这一步如果闪退，说明 `[view window]` 升层没生效。**
> `raw_window_handle` 在 AppKit 上给的是 **NSView\***，而 `setSharingType:` / 所有隐身选择子
> 都属于 **NSWindow**。漏做升层 ⇒ `unrecognized selector` ⇒
> **进程直接死，且没有 Rust panic、没有日志**（ObjC 异常不是 Rust 异常）。

**做法**：

1. 用 `scripts/open-app.py` 打开（或 Finder 双击 `.app`）
2. **看诊断输出** —— 打开设置，看「会前自检」或隐身那一项的结论文字
3. 按 `Cmd+Shift+3` 截全屏 → 打开截图 → **提词器窗口应该不在里面**

| 现象 | 含义 | 处置 |
|---|---|---|
| 闪退、无任何日志 | 升层失败 | 停下，这版不能测了，报给我 |
| 起来了，诊断写「已应用私有 API 排除捕获」 | 符号找到了，进入真实验证 | 继续 §4 |
| 起来了，诊断写「私有 API 亦不可用（…）」 | `dlsym` 没找到符号 | 停下，报给我，可能是 macOS 版本太新 |
| 起来了，诊断写「窗口可能尚未上屏」 | `view_window` 返回空 | 等窗口真正上屏后再点隐身 |

## 4. ★ 必测：macOS 版本决定走哪条路

**这是整份清单最关键的一步 —— 先把版本号告诉我，它决定后面所有判断标准。**

```bash
sw_vers
```

| macOS 版本 | 走哪条路 | 预期结果 |
|---|---|---|
| **14 或更低**（Sonoma 及以前） | 公开 API（`sharingType`） | 隐身**应当有效**，且是 Apple 认可的做法 |
| **15+**（Sequoia 及以后） | 私有 API（`CGSSetWindowCaptureExcludeShape`） | **未知** —— 这正是这次要验证的 |

> **背景（重要）**：Apple 在 macOS 15 改了 WindowServer 合成架构，ScreenCaptureKit
> 直接抓合成后的 framebuffer，**公开 API 全部失效**。Apple 官方论坛原话：
> **"目前没有公开 API 可以防止屏幕捕获"**。
> 我们代码里走的是社区目前唯一已知有效的私有符号，但**从未在真机验证过**。

## 7. ⚠️ 已知会失败的地方（不是你的操作错）

| 现象 | 根因 | 严重度 |
|---|---|---|
| 隐身对某些会议无效 | macOS 15+ 公开 API 作废，私有路径未验证 | 🔴 预期内 |
| 关闭隐身时可能报错「不支持撤销，需重启窗口」 | 代码**刻意**显式失败（不能用 NULL 蒙混过关） | 🟡 设计如此 |
| 私有 API 可能在未来的 macOS 更新后失效 | 未文档化 API，Apple 可随时改 | 🟡 结构性风险 |
| `.app` 可能提示"来自身份不明的开发者" | 未签名 + 用了私有 API | 🟡 **必然**，见下 |

**关于签名**：用了未文档化的私有 API ⇒ **App Store 审核必被拒**，只能官网/直接分发。
首次打开需在「系统设置 → 隐私与安全性」里点「仍要打开」，
或 `xattr -d com.apple.quarantine <路径>/Prompter.app`。

## 9. 这次验证可能推翻什么

**这不是走过场。** 三种可能的结果，各有不同后果：

| 结果 | 含义 | 后续 |
|---|---|---|
| ✅ **真隐形** | 双平台定位成立 | 出 `.app` + `.dmg`，README 的 macOS 列可以写「已验证」 |
