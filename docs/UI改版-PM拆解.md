# 提词器 UI 大改版 · PM 需求拆解

> 输入：一张参考图（播客/直播用的移动端 AI 提词器）＋ 一句需求
> 「现在的功能特别杂乱、特别多，操作性比较差。做一个大改造，简洁化，不要有太复杂的功能。」
>
> 本文是**决策记录**：先诊断，再定级，再给规格。凡是「有选项」的地方按默认走，
> 默认值都写在下面并给了理由 —— 只有一个选项的东西不叫选择，叫判断。

## 二、问题诊断

### P0 · 没有主角

提词器在一场直播/一次汇报里，**最高频的动作是「开始/暂停跟读」**。
但它现在藏在 `设置 → 语音识别 → 第 7 行`里。顶栏最大的那个东西是「▶ 演示」，
它做的是「隐身 + 置顶 + 开始跟读」三件事的编排 —— 很聪明，但也很重，
用户理解不了「演示」和「开始识别」差在哪。

> 参考图给了一记很清楚的耳光：它的底部只有一个**大红色圆按钮**。
> 其余六项全是等大的小图标。这就是「主角」应有的待遇。

### P0 · 两个「开始」打架

顶栏「▶ 演示」与设置「开始识别」是同一个意图的两个入口，
但状态不同步（点了一个，另一个还显示原样）。

### P1 · 状态用文字表达，占掉了窗口

4 个文字胶囊（投屏隐身 / ▶演示 / 穿透 / 锁定）合计约 400px。
其中 **穿透、锁定是「每场最多用一次」的动作**，却和「每场要确认三遍」的隐身
占同样的宽度。

### P1 · 设置是「能力的清单」，不是「任务的清单」

按后端模块分组（排版 / 外观 / 窗口 / 迁移 / 诊断），
而不是按用户心里的任务分组（「开讲前」「字看不清」「窗口挡住 PPT 了」）。

### P2 · 术语是内行话

`可定位字数` `垂直锚点` `毛玻璃` `控制栏浮在正文之上` `跟读灵敏度` `匹配下限`
—— 用户想要的是「字大一点」「字往中间靠」「背景糊一点」。

## 三、目标 / 非目标

**目标**
1. 界面出现**一个明确的主角**，一场直播里 90% 的操作靠它完成。
2. 顶栏控件数**砍掉一半以上**，把宽度还给稿件标题。
3. 设置按**任务**重组，术语口语化。
4. 不牺牲任何一条已论证过的安全约定（见第六节回归项）。

**非目标**
- 不动后端能力（穿透 / 隐身 / 对齐 / 曲库一律保留）。
- 不为「好看」引入新依赖、新动效框架。
- 不删功能，只**改入口位置与默认可见性**；确实删掉的列在第五节，逐条给了理由。

## 五、删除清单（逐条给理由）

| 删除项 | 理由 |
|---|---|
| 顶栏「穿透」「锁定」文字胶囊 | 一场会议最多用一次，却占 100px。**退出口没少**：穿透仍可从设置关、从托盘关、按热键关（三条路，仍满足「穿透必须配不受该通道影响的退出口」这条硬约定） |
| 顶栏「收起」「设置」图标按钮 | 移到底部控制台，靠近主角 |
| 底栏「对不上 · N」独立提示 | 它是「跟读失准」，与底栏那条黄色警告是同一类事。**并入警告通道**，由生产者给标签（本轮之前刚立下的纪律） |
| 设置「可定位字数」 | 内部概念（阿拉伯数字不参与对位），用户拿它做不了任何决定 |
| 设置「窗口尺寸」只读行 | 显示一个用户不能改、也不关心的数 |
| 设置「参考语速」的 4 个预设按钮行 | 滑块本身就是预设。4 个按钮占一整行 |
| 设置「试一句」（feed hypothesis） | 开发者联调工具。收进「更多 › 诊断」 |
| 设置「最近听到」常驻回显 | 只在识别出问题时才有意义。并入诊断 |

## 七、交互规格

### 7.1 底部大圆按钮 —— 四态（这是本轮的核心）

| 态 | 外观 | 点击后 |
|---|---|---|
| 未开始 | **绿**（描边）+ ▶ | **开始提词** = 隐身 + 置顶 + 开始跟读（原「一键演示」的编排） |
| 就位中 | 扫描动画 | （禁用）等后端确认 —— 这段最久（要启动识别引擎），没有它就是"点了没反应" |
| 进行中 | **绿**（实心）+ ⏸ | **暂停** —— 只停跟读，隐身与置顶原样保留 |
| 已暂停 | **蓝**（描边）+ ▶ | **继续** —— 把跟读拉回来 |

> ★ 常驻界面上**只有这一处**「开始」；设置 › 提词 里那个「开始 / 结束」保留着，
> 但它与大圆按钮**走同一份编排**（`lib/prompting.ts`）⇒ 两处状态永远一致。
> 改版前的问题是"两个入口 + 两套实现"（顶栏开了隐身、设置里不知道），不是"有两个入口"。
>
> ★ 为什么「未开始」是绿的、用**描边/实心**而不是换颜色来区分它与「进行中」：
> 第一版把「未开始」和「已暂停」都做成了蓝色描边 + ▶ —— 离线一量才发现两者
> `color` / `border` / `background` **逐字节完全相同**，用户根本分不出
> "还没开始"和"按停了"。修法是让绿承担"提词这条线上一切正常"
> （就绪 or 在跑，与顶栏那盏灯同义），**实心/描边**才是"在跑"与"就绪"的区别；
> 蓝仍然只归"用户自己按下的状态"（暂停）所有。

三条纪律（沿用已有论证，不改）：

1. **暂停 ≠ 收摊。** 暂停只停跟读；「收摊」（停跟读 + 撤置顶）在设置 › 提词里，
   与隐身「彻底关掉放设置」同一条约定：*可逆的、高频的留在按钮上；不可逆的、低频的收进设置。*
2. **暂停与收摊都不动隐身。** 隐身是用户自己的开关，不该被顺手撤掉。
3. **只有真的停住了才翻牌。** 停失败就停在原态 + 报警告 ——
   翻成一个说假话的绿牌子，比不翻更糟。

**颜色语义（全界面一个颜色只有一个意思）**
- 绿 = 一切正常（已生效 / 就绪）
- 琥珀 = 受限 / 没生效（**不是**「暂停」）
- 蓝 = 用户自己按下的（暂停 / 已锁定）
- 同一个色相内部的区分靠**实心 vs 描边**，不靠再引入第五个颜色

### 7.2 顶栏状态灯

一个图标 ＋ 3 字标签（`未隐身` / `隐身中` / `已暂停` / `未生效` / `不可用`），
点击 = 三态循环（未隐身 → 隐身中 → 已暂停 → 隐身中 …）。
「彻底关掉」仍在设置里 —— 循环控件里不放不可逆的那一档。

- `隐身中` → 绿 ＋ 呼吸点（呼吸 = 「状态是活的」）
- `已暂停` → 蓝
- `未生效 / 不可用` → 琥珀（**唯一**会报警的档，也是删掉长文案后仅剩的失败信号）

### 7.3 术语对照

| 旧 | 新 |
|---|---|
| 垂直锚点 | 当前句位置 |
| 毛玻璃 | 背景模糊 |
| 左右边距 | 左右留白 |
| 控制栏浮在正文之上 | 控制栏悬浮 |
| 已读内容变暗 | 已读变暗 |
| 跟读灵敏度（匹配下限 0.38） | 跟读灵敏度（副标题：往左跟得紧 / 往右跟得稳） |

## 九、回归风险与必守项

改版只动外观与入口，以下**已论证过的约定一条都不能破**：

| # | 约定 | 本轮如何守住 |
|---|---|---|
| R1 | 穿透必须配不受该通道影响的退出口 | 设置开关 ＋ 托盘菜单 ＋ 热键 `Ctrl+Alt+P`，三条都在 |
| R2 | 界面显示「实际在工作」，不是用户按下的意图 | 主角/状态灯仍读后端事实（`ct_working` / `stealth.applied`） |
| R3 | 状态由界面自己表达，不弹一段字 | 主角自己变色变形状；不新增任何说明性弹窗 |
| R4 | 「收进托盘」不能在窗口消失后才说明 | 首次收托盘前 1.7s 提示仍保留 |
| R5 | 警告的标签必须由生产者给 | 底栏警告改用 `StatusWarning{label, detail}`；「对不上」并入时带自己的标签 |
| R6 | 上报的是**一组矩形**不是包围盒 | 控制台仍标记 `data-interactive`；顶栏与控制台是两块独立矩形 |
| R7 | 「编辑当前内容」绝不写回源文件 | 未改动 |
| R8 | 收起到 40px 时面板会被裁 ⇒ 打开面板即展开 | 未改动 |
| R9 | **删掉一个信号之前，必须确认它还有别处承载** | ★ 本轮**真的破了这一条**，自查时补回，见下 |

### ★ 自查补回的一处回归（R9）

改版先把「穿透」从顶栏胶囊收进设置 › 窗口。**退出口是三条，一条没少（R1 守住了）**，
但另一件事被漏掉了：**失败信号**。

- 改版前，穿透那个胶囊会在 2.2 秒宽限期过后变成**琥珀**——
  那是删掉 138 字说明之后「开了但没生效」的**唯一**信号。
- 收进设置之后，`ctActive` / `ctPending` 一度**没有任何组件消费**（成了死状态）：
  用户按热键 `Ctrl+Alt+P` 开穿透（人还不在设置页），后端判它没生效，
  界面上**什么都不会发生** —— 正好退回「点了没反应」。
- 判据不是"功能还在不在"，而是**「不弹它会不会出事」**。会：
  用户以为穿透开了，去点桌面上的东西，被窗口吃掉那一下点击。

**补法**：信号不消失，只换位置 —— 挂进控制台第一行那个**唯一的状态槽**
（`cb-status`，它本来就是给"受限 / 没生效"准备的）。
判据用 `ctPending && !ctActive`（意图已下、后端没确认），**不是** `!ctActive`
（后者在"压根没开"时为真，会常年挂一条假警告）；宽限期沿用 2.2 秒。
优先级排在「错误 > 后端警告」之后、「跟读失准」之前 ——
前面两条是更具体的诊断，而它比"跟读失准"更贴"用户正动手那一刻"。

复现与验收都进了桩：`click=ct&ctBroken=1&settle=2600`
（`ctBroken` 是**专为这条路径**加的开关 —— 正常跑时可交互区一定报得上去，
不加这个开关，那条分支永远走不到，就会变成"写了但从没验过"）。

**教训（值得进判断基线）**：改版/简化时，被砍掉的**入口**通常有人盯着（有 R 清单守），
而被砍掉的**失败信号**没人盯 —— 它不占地方、不报错，只是从此不再出现。
⇒ 每收走一个控件，要问的不是"功能还在吗"，而是**「它原来负责说的那句话，现在谁说」**。

**明确不动的**：`stealth/` `script/` `align/` `library/` `doc/` `win::geometry` `win::click_through`
（全部只认纯数据与纯函数，能独立单测）—— 本轮**零后端逻辑改动**，只在 `win` 层之外改前端入口。

## 十一、第二轮：跟读组（按参考图对齐）

参考图是一屏手机提词器的设置：暗底、左侧标签 + ⓘ、右侧绿滑块 / 一排色点 / 绿灰开关。

### 11.1 图里五项 → 落到哪里

### 11.2 刻意**没有**照抄参考图的两处

1. **「跟读位置」的默认值**：图上是 25%，我们保持 36%。
   36% 是上一轮论证过的位置（"偏上、下面多留备读"），25% 会把备读区压得太少。
   参考图给的是**那一台设备的当前状态**，不是我们要继承的默认值。
2. **「跳读范围」的单位**：图上只写 `20`，我们按**句**解释并在副标题里说明。
   换算是 `句 × 12 字`（`CHARS_PER_SENTENCE`）。用常量而不是"当前稿件的平均句长"，
   是为了让手感**不随稿子变化** —— 否则换一篇稿子用户会发现"同样 20，这篇紧那篇松"，
   而屏幕上没有任何东西能解释这个差别。

| `read_color` | String（色板 key） | `"green"` | 同上。存 key 不存 RGB：色板是**界面**的事，改色板不该动到老配置 |

### 11.4 ★ 顺手补回的一处**隐性偏差**（不是本轮需求，但同一条纪律）

- 处置：`bootstrap` 里补上 `set_min_score` / `set_jump_range`，
  并打一条 `[bootstrap] 跟读参数：match_floor=… jump_range=… 句` ——
  打的是**引擎实际采用的值**，因为"配置改了没灌进去"的排查就是从这一行开始的。

### 11.6 浅色主题：色板必须有两套

这几个色是按**深色背景**挑的（饱和度高、明度也高）。放到浅底上，做细线
（2px 下划线、6% 底色）时几乎看不见 —— 实测把亮绿 `52 211 153` 画在白底上，
对比度低到"看不清有没有在跟读"。

处置：色板每一项给两套值（`rgb` / `rgbLight`），由 `applyLayoutVars` 按**解析后的主题**选。

★ 它**不能**靠 CSS 主题块覆盖：`--read` 是用 `style.setProperty` **内联**写在
`documentElement` 上的，内联优先级高于 `:root[data-theme="light"]` 里的规则。
⇒ 只能由 JS 选值；且 `system` 必须先 `resolveTheme` 成实际的，否则 `system` 下永远拿深色那套。

浅色档刻意与既有 `--ok` 同值（绿：深 `52 211 153` → 浅 `5 150 105`）——
"同色号压深一档"要和项目已有的档位**成套**，不能随手挑一个"看着够深"的数。

| | 深色主题 | 浅色主题 |
|---|---|---|
| `readVar` | `52 211 153` | `5 150 105` |
| 正文当前句底色 | `rgba(52,211,153,0.06)` | `rgba(5,150,105,0.06)` |
| 播放头 / 选中色点环 | `rgb(52,211,153)` | `rgb(5,150,105)` |

★ 色点也按主题取色：设置页里显示的那个颜色，必须就是**正文里真会出现的**那个颜色。
否则用户挑了一个"看着很清楚"的色，回到正文却是一条几乎看不见的浅线。

## 十二、第三轮：匀速滚动（自动滚动播放）

### 12.1 需求与它真正在问什么

原话：「让它自动滚动播放。我们现在是让它跟随语音嘛，然后我需要增加一个让它自动滚动播放的功能」

拆开是两件事，第 2 件比第 1 件重要：

1. **多一种推进方式**：不采声音，按设定速度把稿子推下去。
2. **现有那个「引擎」下拉是个黑箱**。它把「用不用麦克风」和「用哪个语音模型」混成
   一个控件 —— 于是"我想让稿子自己滚"这件事在界面上**没有位置**，用户只能去猜
   「Manual」是什么意思。所以本轮不是"加一个选项"，是**把那一维显式化**。

### 12.2 拍板（三处，均已按拍板实现）

| # | 问题 | 拍板 | 为什么不是另一个 |
|---|---|---|---|
| ① | 怎么组织「稿子往下走」 | **三选一**：语音跟随 / 匀速滚动 / 纯手动 | 不做成"自动滚动开关 + 引擎下拉"：开关与下拉会互相矛盾（关了开关，下拉还写着「云端」）。三选一里每一格都自洽 |
| ② | 匀速的速度用哪根滑杆 | **独立字段** `auto_wpm` | 复用一个滑杆会串味：参考语速 300 是"我讲多快（用来估剩余时间）"，匀速 300 是"稿子走多快"，同一根杆上两个口径，用户调完会问"我调了 300，它为什么按 280 估时间" |
| ③ | 讲的中途要调速 | **控制台给一条速度条** | 直播中途回设置页 = 把唯一在讲的那块区域让出来。调速是这一场里唯一可能反复动的东西，必须在常驻栏上 |

### 12.4 四处关键设计（每条都有代价，别顺手改掉）

1. **位置在后端线程里按时间算，不在前端 `setInterval`。**
   代价：多一条线程。
   换来：投屏时提词窗口**不在前台**，浏览器的 `setInterval` 会被节流到 1s 一拍
   （真机上表现为"一卡一卡地跳"）。位置由 `base + elapsed × wpm/60` 现算，
   **不是逐拍累加** —— 累加会随每一拍的误差漂移，十分钟后偏出去一大截。

2. **`seek` 绕过文本匹配。**
   代价：多一条事件分支。
   换来：匀速滚动的位置是**算出来的已知答案**，再送进对位器"猜"一次，
   只会在稿件有重复句时猜错（把光标甩到别处）。两条路是并列的两个来源，不是一条路上的分支。

3. **中途调速必须 `rebase`。**
   把当前位置冻住当成新的基准点，再按新速度往下走。
   不这样做，调速那一刻光标会**跳**一段（新速度乘上"已经过去的总时长"）。

4. **改「推进方式」不重启正在跑的引擎。**
   代价：这一格要下次开讲才生效（文案里已写明）。
   换来：中途换引擎一定会让画面卡一下，而用户多半是在**确认一下**它设对了没有。

### 12.5 ★ 交付前自查抓到的：一处"只说了一半"的结束信号

匀速滚动**会自己走到头**。后端在那一刻把 `running` 打成 `false`，控制台那格于是
显示「已讲完」—— 到这里是对的。但**大圆按钮读的是另一套状态**（`demoActive/demoPaused`
那套"演示编排状态"，记的是"用户按下过开始"），它不会自己退出。

于是滚完之后：**控制台说「已讲完」，大圆按钮还亮着实心绿（= 正在提词）**。
而人扫一眼屏幕，看的是那个大按钮 ⇒ 以为还在滚，实际早停了。
这正是「界面显示实际在工作，不是用户按下的意图」的反面 —— 而且是**静默**的：
不报错、不占地方、门槛全绿。

处置：新增 `demoEnded` 一维（**不用** `demoActive === false` 顶替 —— 那条路上有
"讲完了"和"讲到一半被停"两种情形，前者该说「已讲完」，后者什么都不该说；
也不用"光标在末尾"顶替 —— 用户把进度条拖到底也会到末尾，那会儿他什么都没讲）。
三条转移规则：滚到底置位 / 重新开跑清零 / 光标离开末尾清零。

★ 附带固定的一条判据：**这个事件必须带 `progress >= 0.999`**。启动瞬间后端也会先报
一次 `running=false`，只按 `!running` 判会把「就位中」当场取消，按钮闪一下退回就绪。

### 13.3 修掉「收起后没有展开选项」

根因一行就够：

```css
.app.collapsed .controlbar { height: 0; opacity: 0; pointer-events: none }
```

那颗「展开」按钮**长在被收起的那个东西里面**。点完收起，按钮跟着控制栏一起消失，
窗口上只剩顶栏 —— 而顶栏上没有展开键，唯一出路是记住 `Ctrl+Alt+M`。

这与「穿透必须配托盘」是同一条纪律：
**任何会关掉某个通道的能力，都要附一个不受该通道影响的退出口。**

做法：栏**一直留着**（它现在就是唯一的栏），那颗键在收起态变成 `⌄`。
动画分两拍、方向相反：

* 收起：先让正文滑上去淡出（`--t-collapse`）**再**把窗口压成一条。
  反过来窗口先变矮、正文被生硬裁掉，动画根本没机会播。
* 展开：先把窗口放开，正文自己淡入下滑（CSS transition 接管）。

★ `--t-collapse` 是**唯一源**：`TopBar` 用 `getComputedStyle` 读它，不写死第二份。
两处各写一份的话，谁调了 CSS、忘了调 JS，窗口就会在正文滑完之前先变矮 ——
用户看到的不是"滑走"而是"被裁掉"，**且不报任何错**。

★ `COLLAPSED_H: 40 → 48`：收起态的窗口高度必须 ≥ `--h-top (46) + 上下边框`，
否则那颗**现在承载着"唯一出路"**的展开键会被裁掉一角。

### 13.4 ★★ 真正的坑在工具上：截图比真实窗口宽 32px

前面 13.2 里那句"标题刚好放得下"差点是错的，因为它一度是被**假图**判定的。

`ui-preview.py` 用无头 Edge 跑两次：一次 `--dump-dom`（测量）、一次 `--screenshot`（出图）。
**这两种模式对 `--window-size` 的解释不一样**（2026-09-27 实测）：

| 模式 | 视口 |
|---|---|
| `--screenshot` | `W × H` |
| `--dump-dom` | `(W−32) × (H−96)` |

而项目里流传的口诀是"想渲染真实 560 就传 592"—— 那是**按测量模式**修的，
于是图那边就一直被渲染成 592 宽。**32px 的富余刚好够标题把话说完**：

```
测量（真 560）：titleW=93   titleTextW=115.7  → 标题被省略号截掉
截图（假 592）：标题一个不少地全画出来
```

这就是最坏的一类不一致：**图说没事、数说有事**。而我从图里得出的结论是
"标题没被截，那个 93 是我量错了"。为此还去量了盒子的左右边界、加了红描边，
绕了一大圈才确认两边都没错 —— 错的是它们**不在同一个视口里**。

处置：把换算收敛进 `run_browser()`，两种模式渲染出的视口都等于调用方给的
`--w × --h`；调用方从此只给**真实窗口尺寸**（原来的 `W+32 / H+96` 口诀作废）。
★ 顺带把 `titleClip` 也修了：它原先写 `scrollWidth > clientWidth + 1`，
在"就差 0.5px"的边界上会**报反**（截图明明挂着省略号，它说没截）。
现在用 `Range` 量文字的真实排版宽度、直接报 `titleShort`（差多少 px）。

★★ 还有一处**因此被推翻的判断**：见 13.2 取舍三里那句
"调速条是正常控件，凭什么让标题消失"。它是在 592 宽的假图上写的
（那时标题看着还剩 90px）。修完工具实测只有 **60px**（`titleShort=55.7`）
—— 也就是一个 "2026…"。判据不变（标题让位），只是"再一件"现在也包括调速条。

## 十四、第五轮：四条反馈里的三个真 bug 与一个工具坑

### 14.1 四条反馈（原话）

> 1. 把进度接到这一句的点击效果不太好，有时候点不上。
> 2. 右上角的点击稿件图标点击可以展开，再次点击未收起。
> 3. 这次设置好的所有设置以后打开或者打开其他稿件要记住之前的设置。
> 4. 设置里面的切换按钮都增加苹果 UI 交互式动画。

四条里 **① ② ③ 都是真 bug**，而且三条的**症状与原因都不在同一个地方** ——
它们分别是"命中区"、"事件顺序"、"两个写者"。

### 14.2 ① 点不上：命中区只盖住了字形

`seekHere` 原来挂在 `<span class="sentence">` 上。句子是 **inline** 元素，
它的盒子只包住字形 —— 行距（`line-height` 默认 1.7、字号 34 ⇒ 每行约 18px）
与行尾空白**都不属于它**。于是版面里有一大片点不动的区域。

改法：处理器挪到**块级**的 `<p>` 上（块盒高度 = 各行行盒之和，行距落在行盒内），
再用 `caretRangeFromPoint` 把坐标换成"段内第几个字"，按 `s.text` 长度累加定位到句。

三个细节缺一不可（都有它的代价）：

* **口径必须用 UTF-16 码元**（`s.text.length` 就是），不能用 `Array.from` 的码点口径
  —— 两者在 emoji 上差一位，差一位就跳错句。
* **拖选要放过**：正文是可以选中复制的。判据用**位移**（> 6px 视为拖选），
  **不是**"有没有选区" —— 双击路径本来就会选中一个词，按选区判断会把
  「快捷跳读关掉 ⇒ 双击跳」整条路堵死。
* **光标形状跟着命中区走**：`cursor: pointer` 从 `.sentence` 挪到 `.para`
  （且只在快捷跳读开着时）。留在字形上等于继续告诉用户"行距那儿点不动"。

### 14.3 ② 再点不收：mousedown 与 click 之间隔着一次重渲染

事件顺序 `mousedown → mouseup → click`，而 React 的 `onClick` 拿的是**本次渲染**的闭包：

```text
① mousedown  → 外点关闭把 historyOpen 置 false（面板关了）
② 重渲染     → 按钮的 onClick 变成"当前是关着的"
③ click      → 把 false 取反 ⇒ 又打开
```

于是"点一下开、再点一下还是开"。用户看不到第②步（它发生在两下之间）。

改法：给三个面板切换按钮标 `data-panel-toggle`，外点关闭**跳过落在它们身上的
mousedown**。用标记而不是"比对某个 ref"，是因为将来给别的面板加外点关闭时
这个坑会原样再来一遍。

### 14.4 ★★ ③ 设置不记住：一个文件两个写者

这一条最花时间，因为它**指向的地方不是原因所在**（用户只会说"设置没记住"）。

配置是**整份**写的，而有两个写者：前端（设置页改一项 ⇒ 防抖 400ms ⇒ 一整份）
和后端（窗口几何 / `last_script` / 穿透 / 置顶，各自即时写）。前端的副本是
**启动那一刻**的快照，于是：

```text
① 用户把窗口拖到 700×400   → 后端写 window = 700×400
② 用户顺手关掉「背景模糊」 → 前端把自己那份（还写着 560×274）整份写回
③ 文件里 window 退回 560×274 ⇒ 下次启动位置/大小、"上次那篇稿子"全回旧值
```

同时还有一个独立的、更直白的原因：**「窗口置顶」根本没有持久化**
（它是设置页里一个 `useState`，读完就丢）。当初的论证是"它是摆窗口时的
一次性动作" —— 真用起来才知道不成立：提词器的常态就是盖在 PPT 上。

三处一起改：

* 新增 `always_on_top` 字段（Rust + `types.ts` + **桩**三处），
  由**后端**写：`set_always_on_top` 同时改窗口属性与配置，返回实际生效值。
  「开始提词 / 收摊」和设置里的开关都走它 —— 合成一个命令，两处才不会打架。
* `save_config` 先过一道 `state::merge_backend_owned`：**后端拥有的字段一律以
  内存态为准**（几何 / `last_script` / 穿透 / 置顶），前端只决定它真正拥有的那些。
  它是纯函数，所以"哪个字段归谁"被钉进了单测（`merge_keeps_backend_owned_fields`）。
* 启动时按配置恢复置顶（与隐身/穿透同一条路：配置说开着就开）。
* 顺手补一个 400ms 的窗口：原来防抖的清理只 `clearTimeout`，用户
  "改完设置马上关窗"那一下**永远不落盘**。现在卸载时补发那一份。

### 14.5 ④ 苹果手感：先弄清"像"在哪三件事上

形状（胶囊轨道、带投影的滑块）只是**静态像**。真的手感来自：

1. 滑块带**回弹**（位移的缓动是 back-out：`cubic-bezier(0.4, 1.25, 0.5, 1)`）；
2. 按住时滑块**横向抻开**（`scaleX(1.16)`，160ms —— 比位移快一半）；
3. 轨道比滑块慢一拍起步（260ms 的底色过渡）。

★ 抻开必须用 `transform: scaleX()`，**不能改 `width`** —— 改版前用的正是 `width`，
它会触发重排，而且和位移混在同一条 `transform` 里没法分开给曲线。
★ 位移量存在 `--x` 上、由 `.on` 改，`::after` 只写一条 `translateX(var(--x))`：
这样 `:active` 那条（保留位移 + 加挤压）不会和 `.switch.on::after` 抢同一个属性
（两条权重相同，谁在后面谁赢 —— 那种写法迟早让滑块"弹回左边"）。
★ 补 `role="switch" + aria-checked`：它是**状态**控件，状态必须能被读屏念出来。
★ `prefers-reduced-motion` 下退化为直切 —— 开关是设置里唯一承载"开/关"的地方，
动画只是修饰，而它会让人前庭不适。

## 十五、第六轮：把"收起来"的落点从托盘改成任务栏

### 15.1 反馈

> 「没有办法收起到这里。」（附一张任务栏截图）

### 15.2 先把"到底是什么坏了"查清 —— 这一步改变了修法

四条证据，缺一条都会修错地方：

| 检查 | 手段 | 结果 |
| --- | --- | --- |
| 托盘对象建起来没有 | 应用日志 | ✅ `[tray] 已创建`（当天 3 次） |
| 托盘图标注册进系统没有 | 读 `HKCU\Control Panel\NotifyIconSettings` | ✅ 有 `'Prompter 提词器'`（debug/release 各一条） |
| 它显示在哪一格 | 同上，看 `IsPromoted` | ❌ `IsPromoted=0` ⇒ **被 Win11 折进 `^` 溢出区** |
| 任务栏里有没有它 | `tauri.conf.json` | ❌ `skipTaskbar: true` ⇒ 永远没有 |

⇒ 结论不是"托盘坏了"，而是**那句提示在说假话**：它写着"点托盘图标"，
而那个图标在一个用户不点 `^` 就看不见的地方。这属于本项目最忌讳的
**"承诺一件当前做不到的事"**（同族：静默失败）。

★ 方法论收获：三条本想用来验证的手段里**两条是错的**（见 15.6）。
  在写修复之前先把"怎么证"定下来，否则会拿一个假信号去证明修复有效。

### 15.3 拍板：任务栏留按钮，**只在收起时出现**

三个选项（托盘图标提到 `^` 外面 / 任务栏常驻按钮 / 只在收起时出现），
老大选了第三个：

* **平时**：`skip_taskbar = true` —— 浮在 PPT 上，不占任务栏（原设计保住）；
* **收起来**：`set_skip_taskbar(false)` + `minimize()` ⇒ 任务栏出现按钮；
* **回来之后**：把按钮收回去（`set_skip_taskbar(true)`）。

### 15.4 实现要点（每条都有代价，别顺手改掉）

**① 机制在 tao 里，不在我们的代码里**

`set_skip_taskbar` 在 Windows 上走 **COM `ITaskbarList::AddTab / DeleteTab`**，
**不是** `WS_EX_TOOLWINDOW`。这决定了：来回切是官方支持的做法（这两个接口就是
为"临时给某窗口加/撤任务栏按钮"设计的）；但**验证手段完全不同**（见 15.6）。

**② 两步握手必须是显式三态（`win/taskbar.rs`）**

动作分两半，而且两半在不同地方发生：前半在命令里（放按钮 + 最小化），
后半在窗口事件里（用户点任务栏按钮把窗口弄回来之后把按钮收回去）。
中间隔着"正在最小化"的窗口期 —— 这一期里如果来了窗口事件、被当成
"用户已经还原了"处理，就会**在最小化之前把按钮撤掉**：
症状是「点了收进任务栏，窗口缩下去了、任务栏里什么都没有」，
**与我们要修的 bug 一模一样**。所以状态是 `None / Armed / Minimized`，
`Armed` 阶段**什么都不做** —— 这一段就是为窗口期留的白。

**③ 最小化会送来一次 `0×0` 的 `WM_SIZE`**

原来的窗口事件只挡了"收起态"，没挡"最小化"。最小化时宽高报 `0×0`，
照记不误的话 `sanitize_size` 会判越界、**回落成 `560×360` 默认值** ——
用户"收起来一次"就把拖好的窗口尺寸弄丢了，全程无提示。
⇒ 新增纯函数 `should_capture_geometry(visible, minimized, collapsed)`，
把"该不该记几何"收成一处判断。

**④ 判据从"两处各写一遍"收成一个纯函数，顺带修掉一个真 bug**

`is_visible() && !is_minimized()` 这条判据原来只写在托盘菜单里，
现在有三个调用点（托盘菜单文本、`Ctrl+Alt+H`、几何保护）⇒ 抽成 `geometry::on_screen`。
**顺带修掉**：`Ctrl+Alt+H` 原来只看 `is_visible()`，对着一个已最小化的窗口会去
`hide()` —— 用户按了快捷键，**什么都没发生**。

### 15.6 ★★ 验收：怎么证明"任务栏上真的有按钮了"

这一段的风险**不在我们的代码里**，而在一个 Windows 事实。三种手段，只有第三种成立：

| 手段 | 结果 |
| --- | --- |
| 数 `MSTaskListWClass` 的按钮 | ❌ **数不到**。Win11 任务栏是 XAML 渲染，这条老 Toolbar 是 `visible=False` 的空壳，`TB_BUTTONCOUNT` 恒为 0 |
| 查 `WS_EX_TOOLWINDOW` | ❌ **假结论**。tao 用的是 COM 接口，没动那个样式位 |
| **截图前后对比** | ✅ **AddTab 后任务栏确实多出一枚按钮**（34163 像素差异，落在按钮区），DeleteTab 后回到原样（残留 2554 像素＝重绘噪声） |

工具 `scripts/check-taskbar-button.py`（默认只读 / `--selftest` 看返回码 / `--pixel` 截图对比）。
**两个坑**：① 进程必须 DPI 感知，否则 `GetWindowRect` 给虚拟化坐标、
`ImageGrab` 按物理像素截，截到的是屏幕中部一条无关内容 —— 而差异恰好是 0，
**看着特别像"按钮没出现"**；② explorer 处理 Add/DeleteTab 是异步的，
截太快会拿到上一帧（现象是"AddTab 那张没差异、DeleteTab 那张反而有差异"）。

### 15.9 ★★ 出包时踩的两个坑（都不是这次改动的 bug，但差点骗过我）

**① "没有进程在跑"是假的 —— 一次空输出不等于事实。**

第一次出包直接失败：

```
error: failed to remove file `...\target\release\prompter.exe`
Caused by: 拒绝访问。 (os error 5)
```

但在那之前我**查过两次**：Bash 的 `tasklist //FI "IMAGENAME eq prompter.exe"` 返回空，
PowerShell 工具连 `Write-Output "PING"` 都返回空 —— 两次空输出让我断定"旧实例已退出，
不需要清理"。实际 `prompter.exe`（pid 20144）正从**产物路径**运行、锁着 exe。
⇒ 教训：**判断"有没有在跑"必须用一个自己会报数的途径**，不能把工具的静默当结论。
本轮改用 `ctypes` 的 `CreateToolhelp32Snapshot` 直接读进程表，一次就把 pid、父进程、
完整镜像路径全拿到（`prompter.exe` 的 ppid 是 `explorer.exe`，路径就是产物路径）。

**② `msedgewebview2.exe` 有两支，一支是系统的。**

本轮快照里有 13 个 `msedgewebview2.exe`，分组后：

| 根进程 | 个数 | 归属 |
| --- | --- | --- |
| `prompter.exe` | 5 | 提词器的 WebView2 —— 要一起清 |
| `SearchHost.exe` | 6 | **Windows 搜索界面的渲染进程** —— 动它掉任务栏搜索 |

⇒ 一个"顺手"的 `taskkill /F /IM msedgewebview2.exe` 会把系统搜索一起关掉。
正确做法是**按 pid 树**杀，并且**先算出"受保护"集合、事后复核它们还活着**。

**沉淀成两件工具**（都是本轮新写的，已在 `scripts/`）：

| 脚本 | 干什么 |
| --- | --- |
| `kill-prompter.py [--dry-run]` | 按进程树清提词器；保护非提词器系 WebView2；善后复核 |
| `gates.py [--build]` | 一条命令跑完四道门槛（含零警告检查 + 期望数断言），可选再出包 |

`gates.py` 的存在理由：此前"四道门槛"散在记忆和文档里，每次靠手敲四条命令 +
肉眼数警告 ⇒ 加了个脚本把它们变成**会自己失败的断言**（期望数写死在脚本里，
数字变了就报错，逼人来解释）。

### 16.6 ★★★ 踩到 React error #310（整页白屏），教训要单列

也没用（不是慢，是**根本没渲染**）。现象是**红底错误边界 + 整页白屏**。

```
Uncaught Error: Minified React error #310
```

**React #310 = 渲染的 hook 数量与上次不一致。** 根因：

```tsx
if (!config) return null;        // ← 首帧 config 为空，在这里提前返回
const toggleCollapsed = useToggleCollapsed();   // ← hook 写在提前返回之后
const sendToTaskbar = useSendToTaskbar();
```

首帧 `config` 空 ⇒ 提前返回，两个 hook 一次没跑；配置到位后突然多出两个 hook
⇒ hook 数量变化。**修**：把两个 hook 提到提前返回**之前**，并在原处留注释说明。

⇒ ★★ 铁律：**hook 一律写在提前返回（early return）之前**。压缩产物的报错
完全看不出是 hook 问题，表现就是一朵白屏。

## 十七、第八轮：图标改一横 + 按 Uiverse 规范把交互动效大换血

### 17.1 两条反馈（原话）

> 「用一个横线表示就可以了，不要放一个下载的图标。很奇怪，你从哪里获取到的这种知识。」

> 「我桌面上有UI动画的规范跟案例 `Universe of UI elements made with HTML & CSS`，
>   把我们现在的交互动画按照里面的内容做一个大换血」

### 17.2 图标为什么错：图形承载了别处约定俗成的意思

第七轮我把「收进任务栏」画成**底边 + 下箭头**，理由是"往下缩到那条线里"。
反馈说得很准：**那在全世界都读成「下载」**。

★ 记这条判据：**图标对不对，不看"像不像那个动作"，看"会不会让人读成另一个动作"。**
「下箭头 / 下箭头扎进一条线 / 托盘 + 上箭头」这一族图形，在操作系统、
浏览器、办公软件里被用烂了，含义是"保存到本地"。用户改不了这个条件反射，
我们也不该对抗它。

⇒ 改成**一条横线**（`M3.5 12h17`）。动作本来就是"窗口消失、任务栏上留下一条"，
画那一条最朴素、且不会被读成任何别的东西。
★ 同时把注释改写：原来那段"为什么不用托盘"的论证留着（它仍然对），
但**新增**了"为什么箭头也是错的"——否则下一个人会觉得箭头更直观、又改回去。

### 17.3 「大换血」的参照物：Uiverse 到底给了什么

先找到资料：桌面上那个快捷方式是一个 **PWA**（app-id `mndeomphblamideifdgokhpfbii` 一类），
指向 **https://uiverse.io/elements** —— "4489 UI elements: CSS & Tailwind"。
它的开源库是 **`uiverse-io/galaxy`（GitHub，MIT）**，含 3000+ 元素的真实源码。

从它的公开指引（`uiverse.io/blog/the-future-of-motion-ui-...`）与库里的真实代码里，
抽出**能落地到本项目**的部分。注意：**照搬元素是错的**，社区元素大多是展示品
（渐变、发光、3D），与项目既定的 Linear/FlightRadar24 式克制审美直接冲突。
能搬的是**动力学**，不是**皮肤**：

| Uiverse 的做法 | 本项目的落地 | 为什么 |
| --- | --- | --- |
| 微交互 150–250ms | 四档 token，上限守死 250ms | 提词器要更严：动画还在播＝在和稿子抢视线 |
| `cubic-bezier(0.175,0.885,0.32,1.275)` 式回弹 | `--ease-back: cubic-bezier(0.34,1.4,0.5,1)` | 只用在"东西出现/长出来"，且位移量必须小 |
| 只动 `transform` / `opacity` | 沿用（本项目本来就守） | 不触发 layout/paint，稳 60fps |
| 时长与缓动做成 token | 从"三档时长 + 一条缓动"扩成**四档 + 三条曲线** | Material 3 同口径 |
| `prefers-reduced-motion` | 通配符全覆盖（原来只有 `.switch` 一处） | 前庭无障碍，漏一个元素就是一种伤害 |
| hover/active/focus 三态齐全 | 补 `:focus-visible` 焦点环（全项目原来只有 1 处） | 项目有整套快捷键，键盘用户需要知道焦点在哪 |
| 按压有"抓住了"的反馈 | `.btn/.hero-btn/.tb-step:active` 加 `scale` | 见 17.5 |

### 17.4 动效 token（`styles.css` 顶部 `:root`）

```
--t-press:  90ms   按压/抬起（手还在按钮上）⇒ 必须比手快
--t-fast:  140ms   悬停、换色这类小面积变化
--t-base:  190ms   面板展开、状态切换
--t-enter: 240ms   浮层进场（要交代层级，允许略长）
```

★ 四档不是拍脑袋，是**从"谁在动"反推的**。写法上刻意保持了"名字说用途、
不写数值区间"—— 写 `--t-150` 这种名字，一旦调成 160 就变成谎言。

缓动三条，各管一件事：

```
--ease       cubic-bezier(0.32, 0.72, 0, 1)   通用进出 / 大位移（沿用原值）
--ease-back  cubic-bezier(0.34, 1.4, 0.5, 1)  带过冲，只给"出现/长出来"
--ease-in    cubic-bezier(0.4, 0, 1, 1)       退场专用（东西要走时加速离开）
```

**刻意不复用 token 的两处**（都在注释里写清了理由，免得被"统一化"顺手改掉）：

| 位置 | 值 | 为什么必须特殊 |
| --- | --- | --- |
| 收音环 | `0.08s linear` | 它跟的是麦克风电平（每帧都可能变），不是某次交互 |
| 进度条 | `0.12s linear` | 跟识别进度，用 ease 会让连续推进一顿一顿 |
| 段落推进 | `0.32s ease` | 跟**语速**；必须比按钮反馈慢，否则用户还没念完下一句就淡进来了 |
| 开关轨道 | `260ms cubic-bezier(0.4,0,0.2,1)` | 是"状态的颜色渐变"不是"一次点击"；对称曲线做颜色插值最中性 |

★ 归纳成一句可复用的判据：
**"跟连续信号走的过渡一律 linear 且极短；跟语速走的要慢于按钮反馈；
跟一次交互走的才用 token。"**

### 17.5 按压反馈：加位移之外还要加一点点缩放

原来所有按压都只有 `translateY(1px)`。参照 Uiverse 的元素后改成：

| 元素 | 改成 | 为什么 |
| --- | --- | --- |
| `.icon-btn` | 只有位移，**不缩放** | 一排 32px 按钮挨着，缩放会让整排各自胀缩、读成"在抖" |
| `.hero-btn` | `translateY(1px) scale(0.96)` | 它是**孤零零一个圆**，没有邻居会被带着抖；46px 的圆里 1px 位移几乎看不见 |
| `.btn` | `translateY(1px) scale(0.98)` | 矩形小按钮，视觉重量比圆轻，所以幅度比 hero 小 |
| `.tb-step` | `translateY(1px) scale(0.94)` | 它最小（24px 热区），需要最大的相对位移才读得出"按到了" |

★ 尺度不是随手定的：**缩放幅度与元素尺寸成反比** —— 越小的控件要越大的相对变化。

### 17.6 ★★ 两条全局动效策略（写在文件末尾，靠层叠压住所有个例）

**① 提词中：只留有意义的动效**（`.app.prompting`）

判据：**这个动效有没有在传达状态**。
- 有 ⇒ 留：大圆按钮按下反馈、进度条、收音环、跟读高亮、扫光。
- 没有 ⇒ 停：悬停抬升、阴影变化这类纯装饰。

★ 为什么不干脆全停：提词中用户仍会去点"暂停"，仍需要看到"我按到了" ——
把按钮反馈也停掉，等于在最需要确认的时候把确认撤走。

★ 为什么装饰性的**必须**停：屏幕此刻正在被**当作稿子读**。
余光里任何非必要的运动都会被眼睛抓住，把人从句子上拽走。
这不是审美偏好，是这块屏幕唯一的职责。

**② 系统要求"少动画"：通配符全覆盖**

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

★ 原来只点名了 `.switch` —— 等于"只有开关尊重了这个设置"。
少动画是**无障碍需求**（前庭功能障碍者会因动效眩晕），漏一个就是一种伤害。
★ 用 `0.01ms` 而不是 `0s`：`0s` 会让部分浏览器**跳过 `transitionend`**，
而本项目有代码在等这个事件（收起动画的第二拍）。
★ 开关的 `:active` 里那条 `scaleX(1.16)` 是**另一条声明**、不受时长影响，
所以单独保留了一条覆盖 —— 这个细节写在原处注释里了。

### 17.7 ★★★ 验收：动效也要有断言（而且断言自己抓出了一个坑）

`transition` 写错**不会报错** —— 拼错一个 `var(--t-xxx)`、少个分号吃掉下一行、
token 定义在被覆盖的位置，浏览器全部静默忽略，界面看起来"只是没那么顺"。

⇒ 在桩里加了一组 `motion*=` 断言，**期望值从唯一源现算**（和 `--expect-bars` 同一套做法）：

| 断言 | 实测 |
| --- | --- |
| `motionTokens` | `ok`（六个 token 都能解析出非空值） |
| `motionPressOrder` | `ok`（`--t-press` < `--t-fast`） |
| `motionRaw` | `press=90,fast=140,base=190,enter=240` |
| `motionUnderLimit` | `ok`（全部 ≤ 250ms） |
| `motionPromptingRule` | `yes` |
| `motionReducedMotion` | `yes` |

**★★ 断言第一次跑就报了 `bad:90>=0.14` —— 而 CSS 是对的。**
根因：`getComputedStyle` 会把 `--t-fast: 140ms` **规范化成 `.14s`**，
而同在 `:root` 里的 `--t-press: 90ms` 保持 `90ms`。
于是 `parseFloat` 成了「90 与 0.14 比较」。
⇒ 凡"拿计算值做数值比较"的地方，**必须先归一单位**。
这条已写进断言旁的注释（别把 `parseFloat` 当成"读 CSS 数值"的通用解法）。

**提词中策略的对比验证**（关键：不能只验"类在不在"）：

| 断言 | 正常态 | 提词中 |
| --- | --- | --- |
| `promptingClass` | `no` | **`yes`** |
| `promptingCutsTransform` | `no` | **`yes`** |

★ 第二项问的不是"规则写了吗"，而是**读一个受它管辖的属性的计算值**：
拿一颗 `.icon-btn` 问它的 `transition-property` 里还有没有 `transform`。
只验"类存在"不够 —— 同特异性规则完全可以在后面把它盖掉，那时类在、效果不在，断言照样绿。

★ 造"提词中"这个状态时踩了一个坑：一开始改的是 `asr_status` **命令**的桩返回值，
但前端拿 `running` 走的是 `events.onAsrStatus` **事件**通道，
启动时根本不调那个命令 ⇒ 改了没人读。
改成顺着真实监听路径发 `prompter://asr-status` 才命中。
（新增查询串开关 `prompting=1`。）

## 十八、第九轮：macOS 移植

### 18.1 这一轮的起点：一段**从来没被编译过**的代码

`src-tauri/src/stealth/macos.rs` 有 274 行，全文是 `objc_msgSend` 的签名强转、
`sel_registerName` 的选择子字符串、`dlsym` 的私有符号查找、`sysctlbyname` 的
缓冲区长度 —— 是整个项目**最不可能靠肉眼看出错**的一段。

而它被 `#[cfg(target_os = "macos")]` 圈着，开发机是 Windows
⇒ **`cargo test` 从来不看它一眼**。

也就是说：在此之前，"macOS 端能不能编过"这个问题，只有到真 Mac 上
第一次 `cargo build` 才会被回答 —— 而那一刻还同时有 SDK 版本、链接、
Tauri 打包一堆报错挤在一起，**根本分不清是哪一个**。

⇒ 本轮第一件事不是加功能，是**让这段代码在开发机上被编译到**
（`scripts/check-macos-backend.py`）。它一跑就绿，说明前八轮留下的这段
macOS 实现**是真的能编过的** —— 这是本轮之前谁都不知道的事实。

### 18.2 ★★ 手法：`#![cfg]` inner attribute 才能"编译但排除"

要"把 mac 后端编译一遍"不能直接 `use crate::stealth::macos` —— 它在
Windows 上**根本不存在**（`mod macos;` 自己就被 cfg 了）。试最直觉的写法：

```rust
#[cfg(prompter_check_macos)]
mod macos_check {                       // ✗ 不行
    #[cfg(target_os = "macos")]
    include!("macos.rs");
}
```

`include!` 展开的是**未解析的 token**，那些 `#[link(name = "objc")]`、
`libc::sysctlbyname` 会被当作**当前平台**（Windows）的 item 去 name-resolve
⇒ 报一堆"`libc` 不是依赖"的**假错**。

正解是让整个模块**先被判死再解析**：

```rust
#[cfg(prompter_check_macos)]
pub mod macos_check {
    #![cfg(target_os = "macos")]        // ✓ 这一条 inner attr 管整个模块
    #[allow(unused_imports)]
    use super::__check::macos;
    include!("macos.rs");
    pub fn _touch() {}
}
```

`#![cfg(..)]` 是模块级 inner attribute，**先于一切**判死整个模块
（含里面所有的路径解析）⇒ 在 Windows 上是"空但合法"。

三个必须配套的细节，少一个就出问题：

1. **`use super::__check::macos;`** —— `include!` 出来的代码里有一句
   `use super::{CaptureGuard, ...}`，它相对 `macos_check` 解析 ⇒ 于是要
   `super::CaptureGuard`。但 `include!` 前那半段的模块路径（`use super::{...}`
   指向的是**原始 `macos.rs` 那个 `super`**，即 `stealth` 自己）也要能解析，
   所以补一个占位壳 `mod __check { pub mod macos {} }`，**只在非 mac 上存在**。
   不加它，Windows 开 cfg 时会报一条"找不到 `macos`"的假错。
2. **`--cfg` 必须在 `Cargo.toml` 的 `[lints.rust]` 里声明** ——
   否则每次跑检查都多一条 `unexpected_cfgs` 警告，而门槛是"零警告"
   ⇒ **一个只该报真错的检查，会先自己把门槛弄红**。
3. **`_touch()`** —— 保证模块里至少有一个名字被用到，免得 `unused` 那族
   lint 在开了 cfg 但没引用时抱怨。

### 18.3 ★★★ 最需要判断力的一处：「收进任务栏」在 macOS 上没有落点

Windows 上这个动作有明确出口：最小化 + `set_skip_taskbar(false)` 让任务栏
长出一枚按钮。**macOS 没有"任务栏按钮"这个东西**：

* Dock 图标只在 `activationPolicy = .regular` 时出现，而本应用是 `.accessory`
  语义（`skipTaskbar: true`）；
* `NSApplicationActivationPolicy` **只在冷启动时确定**，启动后变更
  Dock **不会立刻重排** ⇒ 那正是 Windows 上 `ITaskbarList::AddTab` 那条坑，
  只是更糟：Windows 上顺序对了就一定能补上，macOS 上**根本补不上**。

⇒ 照搬的结果是**窗口缩下去、没有任何入口回来** —— 即本项目最不能接受的
**静默失败**（根 `MEMORY`：「宁可显式失败，不可静默失败」）。

**决定：macOS 上不做这个动作，改用「收起」。** 理由不是"做不到就算了"，
而是**收起达成本来那个目的**：用户按这颗键的意图是"让它现在别挡着我"。
收起之后窗口还在屏幕上（一条 46px 细栏），顶栏整个还在（展开/关闭都点得到），
**不依赖任何系统 API、不依赖热键、不依赖托盘**。

它比 Windows 那条路**弱**（还占着 46px），但**可见、可逆、一定能回来**。
两害相权，选可达性。

### 18.4 ★★★ 由此冒出的判据冲突：两颗按钮干同一件事

设置里那一行原先是「收起 / 收进任务栏」**两颗按钮并排**。
在 macOS 上如果保留「收进任务栏」，而它按下等于收起 ⇒
**两颗按钮干同一件事** —— 正是根 `MEMORY` 里明令禁止的
（「同一件事只准一支按钮」）。

⇒ 处置是把**按钮数随平台变**，而不是把两颗做成"有区别"：

| 平台 | 设置里那行 | 顶栏图标数 |
| --- | --- | --- |
| Windows | 「收起 / 收进任务栏」+ **两颗**按钮 | 5 |
| macOS | 「收起窗口」+ **一颗**按钮（文案里不提"任务栏"） | 4 |

★ 关键实现选择：平台判定与**文案**都由后端的 `win::platform` **给出**
（`collapse_label` / `collapse_hint` / `has_taskbar`），前端只渲染。
理由：同一个判断在后端已经存在一份（`minimize_to_taskbar` 靠它分流），
前端再按 `os === "macos"` 自己写一份文案分支，两处就会分头漂移 ——
表现是"按钮写着收进任务栏、按下去却是收起"，或者反过来。

### 18.5 「顶栏图标数是定数 5」这条判据要改口径

第七/八轮留下的硬约束是「**顶栏图标数必须保持 5**，加任何东西的代价都从
标题身上出」。macOS 上少一颗之后，那条判据的**字面**就不成立了。

⇒ 改成：**5 是上限，不是必须凑满的数**。而少掉一颗省下的宽度**归标题** ——
这不是回归，是修好了：移植前 560px 下 `titleShort=-0.6`（余量仅 0.6px，
标题**本来就已经被省略号截了**）。

两条平台实测：

| 断言 | Windows | macOS |
| --- | --- | --- |
| `topIcons` | `5` | `4` |
| `titleShort` | `-0.6` | **`-16.6`**（余量宽了 16px） |
| `titleClip` | `no` | `no` |
| `topH` / `titleW` / `progW` | `46` / `116` / `61` | `46` / `132` / `77` |

★★ 这条修正必须写进断言，否则后人看到数字不对会**补一颗图标把位置填满** ——
那正好把标题又压回去。`scripts/check-platform-layout.py` 里钉住了这一点。

★★ 顺带一个**自己的错**：我第一版断言写成 `titleShort >= 0` 才算没被截，
一跑就红。查桩的定义才发现 `titleShort = 文字宽 − 盒子宽`
⇒ **正数才是放不下**。我把它读反了，差点去"修"一个本来就对的数字。
⇒ 正确做法是用桩直接给的 `titleClip`（yes/no），不要自己对着符号下结论。

### 18.6 热键文案：11 处硬编码，两个平台各错一半

`Ctrl+Alt+X` 这串字在界面上出现了 **11 处**（顶栏 title、设置里两处、
`sendToTaskbar` 的提示、Transport 的警告……）。

macOS 上它有两重错：

1. **按键对不上** —— macOS 后端注册的其实是 `Command+Option+H`，
   因为 `Ctrl+方向键` 被 Mission Control 占着（照搬会跟系统抢键，
   表现是"热键时灵时不灵"且失败毫无规律）。界面还写 `Ctrl+Alt+H`
   ⇒ 用户照着按没反应，**而他不可能猜到该按什么**。
2. **改键后说谎** —— 热键是用户能改的。写死字符串，改完键之后所有提示
   全在说假话。

⇒ 收口成 `types.ts` 的 `hotkeyLabel(spec)`：从 `config.hotkeys.*` 现取、
统一把 `KeyH` 洗成 `H`、`ArrowUp` 洗成 `↑`。**只留一个来源**。

### 18.7 打包：macOS 缺一整套 PNG 图标

`src-tauri/icons/` 里**只有 `icon.ico`**。Tauri 在 macOS 打包时要求一组 PNG
（它自己合成 `.icns`），缺了就是打包期报错 —— 而本项目的规矩是
**永不产安装包**（`tauri:build` = `tauri build --no-bundle`）
⇒ 这个错在开发机上**从来不会自己冒出来**，只有真到 Mac 上出包那一刻才炸。

⇒ `scripts/make-icons.py` 从 `icon.ico` 生成 14 个 PNG（尺寸表与 Tauri 官方
`tauri icon` 模板一致）。用脚本而不是手拖：手拖的那份**没人知道它是从哪来的**，
下次换品牌图标就对不上。

★ 生成时取的是 `.ico` 里**最大那张**（256×256），不是第一张 ——
拿 16×16 放大到 512 会糊成一团，而且**在缩略图上看不出来**，
Dock 上一眼就是渣。脚本里对"源图 < 256px"会打警告。

`tauri.conf.json` 同步：`icon` 数组补 PNG、加 `bundle.macOS.minimumSystemVersion: "11.0"`。

#### 18.8.1 第二轮扩展：从"顶栏"扩到"设置里那一行"（收尾时补）

第一版 `check-platform-layout.py` **只验了顶栏**，而"收进任务栏"在设置里
还有**第二个入口** —— 那边的分岔同样危险，却完全没被盯着。补上的三项：

| 断言 | macOS | Windows |
| --- | --- | --- |
| 标签 | `收起窗口` | `收起/收进任务栏` |

它们全属于**写错了界面照样渲染**的那一类 —— 标签写错、按钮多一颗，
渲染出来都是"正常的界面"。这正是断言该管的地方。

★ 定位方式按**语义**（`.grp-t` 里含「收起」）而不是按位置索引 ——
按位置写死的断言会在下次改版时**静默指错行**。

★ 顺手记一个坑：桩的 `nowrap()` 会把文本里的空格压掉，所以期望值写的是

第一版照抄 JSX 字面量，一跑就红 —— 门槛误报比漏报更消耗信任，所以这一条
改成了"以实际量到的稳定值写死"并写进注释。

★ 变异验证（**门槛能不能失败，比它能不能通过更重要**）：
把桩里 macOS 的 `has_taskbar` 改成 `true`（模拟"藏图标那段被改坏"），

### 18.11 收尾：把「注释说做了、代码没做」这件事收掉

18.10 里那条最高风险项，本质是**开发现场的一处自相矛盾**：

* `commands.rs::native_handle` 的文档注释写「macOS —— `NSView*`，**后端内部再取它的
  `window`**（见 `stealth::macos`）」；
* 而 `stealth/macos.rs::apply()` 里是 `unsafe { set_sharing_type(handle, sharing) }`
  —— **没有那一步**。

★ 这类矛盾比单纯写错更危险：它让下一个读代码的人**以为已经处理了**，于是不会去查。
所以处置原则是**先收敛到一处，再把判断写清楚**，而不是两边各改一半。

**实际改动（`stealth/macos.rs`）：**

1. 新增 `view_window(view) -> NSWindow*`，用 `objc_msgSend` 发 `window` 选择子。
   注释里写明**为什么这不是保险措施**：
   > `setSharingType:` 是 `NSWindow` 的方法。对 view 发这个选择子会抛
   > `unrecognized selector` —— 在 `objc_msgSend` 的 C ABI 下这笔异常**直接终止进程**
   > （不是 Rust panic，没有 unwind、没有捕获点），表现为「打开隐身就闪退」。

   ⇒ 这解释了**为什么必须**在这里做、而不是"顺手加一层"。
2. `apply()` 最前面统一升层；拿到 nil 时返回 `NoHandle("窗口可能尚未上屏")`
   —— 可预期状态走**显式失败**，不是硬崩。
3. **撤销路径改为显式失败**：私有 API 的 `shape=NULL` 语义是「完全排除」，
   关闭时若沿用 NULL 会变成**关不掉**。没有公开文档说明恢复该传什么形状，
   真机又试不出来 ⇒ 直接 `Err("私有 API 路径不支持撤销，需重启窗口")`，
   UI 如实显示"未能关闭隐身"。这是「宁可显式失败，不可静默失败」的又一处落点。
4. `commands.rs` 的注释改为**与代码一致**，并写明「升层不在这一层做，
   由 `stealth::macos` 内部统一处理」，给出理由（上层句柄语义一致 + 不会有人漏做）。
5. 文件头「预留实现」改为「**已在开发机完成离线编译校验，尚未在真机运行**」，
   并把「已验到什么程度」拆成三行（能编译✅ / 逻辑有单测✅ / 实际行为❌）。

**新增 2 条单测**（`stealth/macos.rs::tests`）：

| 测试 | 拦的是什么 |
| --- | --- |
| `version_splits_at_15` | 版本分流在 15 处切开（14 走公开、15 走私有） |
| `closing_stealth_must_not_silently_succeed` | ★ 若有人"顺手"把 `hidden=false` 也传 NULL，就会变成「关不掉但 UI 说关掉了」——这条断言拦住那次改动 |

两条都**不依赖 FFI**（`closing_...` 传 NULL，在探测私有符号之前就返回 Err），
所以在 Windows 上也跑得起来。★ 这也是选依赖的硬判据那一条的又一次应用：
**能不能单测，决定了逻辑该放在哪一层。**
* `pop-out` 退场关键帧仍未生效（沿用第八轮的遗留）。
* macOS 上"收进任务栏退化成收起"是**保守选择**，不是最优解：
  更彻底的做法（应用级 `activationPolicy` 切换 + Dock 菜单）需要
  runtime FFI 操作 `NSApplication`，且必须真机验证 Dock 重排 —— 本轮不做。

## 十九、第十轮：干掉原生 `title` + 怎么给 Mac 装

### 19.1 起点：用户的两句话

> 「鼠标移到所有按钮的时候都会弹出文字提示，三个字：不需要。
> **特别特别 low，而且交互体验会特别差**。第二：怎么给 mac 装」

第一句是**投诉**（要改），第二句是**提问**（要答）。拆成两件事做。

### 19.2 为什么原生 tooltip 必须死（三个理由，按重要性）

1. **视觉上根本不归我们管**。系统 tooltip 不跟随主题、不用我们的字体、
   不受圆角/阴影/间距约束 —— 在一个精调过的深色玻璃窗上，
   它是**唯一一块没被设计过的东西**。
2. **窗口只有 560×360**。系统 tooltip 不为这么小的窗口做避让，
   而超出窗口边界的像素就是画不出来（窗口本身就是画布，没有"窗口外"）。
3. 悬停约 1 秒才出，而且原生 `title` **没法换行排版**。

⇒ 全部换成已有的 `Hint.tsx` 自绘气泡（portal 到 body + `position:fixed` +
现算位置 + 视口夹取）。它本来就写好了，只是之前只有设置页那 6 个分组标题在用。

### 19.3 分组标题的 3~5 行原理说明 → **整个移除**

`AskUserQuestion` 确认的选择。依据比"用户嫌烦"更基本：

> **分组标题不是可交互元素**。它没有点击行为，却是个悬停热区 ——
> 用户每次去点它下面那一行，都要先路过一个弹窗。

说明文字**没有丢**：

* 需要它的已写进各行的 `sub` 或 `tip`（那些地方本来就在讲同一件事）；
* 剩下的属于"给开发看的"（为什么这样分组），留在代码注释里。

### 19.4 ★★★ 本轮真正的坑：钩子规则写了注释、照样踩

加 `useHint` 时往 **4 个**组件里写，**4 个**都写在了提前返回之后：

| 文件 | 提前返回 | 症状 |
| --- | --- | --- |
| `FindBar.tsx` | `if (!findOpen) return null;` | ★ 首帧就踩（`findOpen` 初始为 `false`） |
| `ScriptHistory.tsx` | `if (!historyOpen) return null;` | 同型 |
| `PasteImport.tsx` | `if (!pasteOpen) return null;` | 同型 |
| `SettingsDrawer.tsx` | `if (!config) return null;` | ★ 该文件里**上一轮就写过**一条注释，标题正是「这两个 hook 必须在所有提前返回之前调用（React 规则 #310）」 |

后果：**Minified React error #310 ⇒ 整页白屏**。
压缩产物里 `#310` 就是个数字，报错指不到自己的任何一行。

**定位手法**（别在 stderr 上耗）：构造一个带探针的预览页，注入
`window.onerror` / `unhandledrejection` 把 message/file/line 塞进 `<title>`，
再用 `--dump-dom` 读回来。一把就拿到：

```
TITLE: ERR:Uncaught Error: Minified React error #310; ... @index-BU9sPacv.js:40
```

⇒ **结论**：这条规则靠"读注释记住"**不成立**。新增 `check-hook-order.py`（每次跑）。
★ 判据关键是**花括号深度**：只认组件体那一层的 `return`。
第一版把 `useEffect(() => { if (!x) return; })` 里的守卫也算进去，
报出 20 处假阳性 —— **永远红着的门槛会被直接忽略**。

### 19.5 ★★★ 第二个坑：把功能改没了，而所有门槛都绿着

`useHint` 第一版只返回 `anchor` ref，指望调用方自己写 `ref={hint.anchor}`。
**30 多个调用点没有一个写** ⇒ `anchor.current` 恒为 null ⇒ 位置算不出来
⇒ 气泡永远以 `visibility:hidden` 渲染在 `(0,0)`：

```
界面上      ：鼠标移上去什么都不发生（和没做一模一样）
title 禁令  ：照样通过 ✅（确实没有 title 了）
tsc / build ：全过 ✅（TS 不检查"你忘了传 ref"）
```

⇒ 修法不是"提醒大家记得传 ref"，而是**让 ref 不可能忘**：并进 `{...hint.trigger}`。
★ 类型坑：`RefObject<HTMLElement|null>` 摊不上 JSX 的 `ref`（要具体元素类型，TS2322）
⇒ 用**回调 ref**（入参协变，一个写法对所有元素类型成立）。

### 19.6 ★★ 第三个坑：`check-tooltips.py` 第一版是"瞎的"

第一版逐行扫 `<([a-z]\w*)\b[^<>]*?\btitle=`，**漏掉整整一类**：

```jsx
<input                          ← 标签名在这行
  ref={inputRef}
  className="fb-input"
  title="关闭"                  ← 逐行扫描看不见（本行没有 `<`）
/>
```

而 JSX 里**绝大多数**标签都是这么写的 ⇒ 实际命中率取决于"作者有没有恰好
把 title 写在开标签那一行"，**跟被守的东西毫无关系**。
它第一次跑就"通过"了 —— **因为它也瞎**。往 `FindBar` 塞一个多行 `title=` 才暴露。

⇒ 改成"先拼成整串、再按**开标签单元**扫"（`<tag …>` 遇 `>` 收尾，`re.S` 跨行）。
★★ **规矩**：新门槛必须做一次**变异测试** —— 塞一个已知违规、确认报红、再还原。
本轮三条新检查（`check-tooltips` / `check-hook-order` / `bubbleEl`）都验过能失败。

### 19.7 ★★ 第四个坑：清零 `title` 把测试桩的"抓手"一起清掉了

`ui-preview/tauri-stub.js` 的 `byTitle(cls, text)` **一直是靠 `title` 找按钮的**
（「设置」「Ctrl+K」…）。title 清零后，那些点击步骤**全部静默变成 no-op**：
`el?.click()` 找不到元素就什么都不做，`diag` 里只留一个 `tap1=none`。

★ 它藏在**桩**里、不在产物里 ⇒ **任何产物侧的门槛都拦不住**。

⇒ 给触发元素摊一个 `data-hint`（说明首行）当**能测但不给用户看**的稳定身份。
`data-*` 不参与渲染、不产生任何系统 tooltip，与 title 禁令不冲突。
`byTitle()` 改为优先读 `data-hint`，保留 `title` 兜底。

### 19.8 ★ `check-platform-layout.py` 的一个假病因

它的 `probe()` 原先写 `"--out", os.devnull`（"我不要那张图"）。
Edge 的 `--screenshot` **按扩展名判格式**，`nul` 没扩展名 ⇒ 直接拒：

```
Unsupported screenshot image file type:
```

⇒ 不出图 ⇒ 脚本末段 `if not out.exists(): SCREENSHOT_FAILED` ⇒ `probe()` 抛
**"拿不到测量结果 —— 预览没跑起来（先 npm run build 试试）"**。

★★ **真正的病因（出图路径不合法）和它给的提示（去 build）完全对不上**，
会让人反复重 build 一个本来没问题前端。⇒ 改成写一个真 `.png` 临时文件、用完即删。

### 19.10 怎么给 Mac 装（用户本轮的第二问）

本节是**操作说明**，不是"已经验过的结论"。★ 先把话说在前面：

> **macOS 上的一切行为都没在真机跑过。** 第九轮交付的是
> "编译得过 + 判定正确 + 文案不错"，**不是**"在 Mac 上能用"。
> 未验证清单按风险排序见 `README.md`「未验证」段与本文档 18.10。

#### 19.10.1 在 Mac 上出 `.app`

```bash
# 1) 依赖：Rust 工具链 + Node
#    Xcode Command Line Tools 是必需的（链接 ObjC 框架）
xcode-select --install

# 2) 装前端依赖
npm install

# 3) 出 .app —— ★ 注意**不能**沿用 Windows 那条 --no-bundle
npm run tauri:build -- --bundles app
#    产物：src-tauri/target/release/bundle/macos/Prompter.app
```

★★ **为什么必须显式 `--bundles app`**：`package.json` 里那条 `tauri:build`
写的是 `tauri build --no-bundle` —— 那是 **Windows 的规矩**（本项目"永不产安装包"，
只出一份绿色 exe 配 `scripts/make-shortcut.py` 建快捷方式）。
在 macOS 上"可交付"的单位就是 `.app` **目录**（双击就跑），
`--no-bundle` 会只留一个裸可执行文件、没有 `Info.plist`、没有图标、
**双击没反应**。⇒ 平台不同，交付物的**形态**就不同，命令必须跟着改。

#### 19.10.2 上机前先跑这三步（都不需要 GUI）

```bash
python3 scripts/check-macos-backend.py    # 把 mac 专属后端强制编译一遍
cargo test --manifest-path src-tauri/Cargo.toml --lib
python3 scripts/gates.py                  # 不动出包那一步
```

★ 这三步在 Windows 上**已经跑过**（见 19.9），但真机上的 Rust 版本、
SDK 版本都不一样 ⇒ **再跑一遍**才算数。

#### 19.10.3 第一次开起来的顺序（按风险，别跳）

1. **★ 先查投屏隐身** —— 这是**唯一可能推翻"双平台"定位**的未知项。
   开一个腾讯会议/飞书会议，共享屏幕，看提词窗口在不在共享画面里。
   macOS ≤14 走公开 API `sharingType`，15+ 只剩私有 API
   （`CGSSetWindowCaptureExcludeShape`），**可能随系统升级失效**。
2. 穿透（鼠标能不能点穿它）—— 注意 40ms 轮询在 Mac 上的**耗电**。
3. 热键 `Command+Option+方向键` 与系统/Mission Control **是否冲突**。
4. 应用以 `.accessory` 起来时 **Dock 有没有图标**、退出路径够不够。
5. 透明窗口 + 圆角在 Mac 上的**裁切与穿透表现**。
6. 「收进任务栏」在 mac 上**已退化成「收起」**（见 18.3）—— 确认按下就是收起，
   且设置里那一行**只有一颗按钮**。

★ 已知的**设计性限制**（不是 bug，别当故障修）：
私有 API 撤销路径**只能开不能关** ⇒ 关隐身会**显式失败**，
UI 如实显示"未能关闭隐身"（理由见 18.11 与 `判断基线.md` 第七条）。

#### 19.10.4 图标

`src-tauri/icons/` 已有 `scripts/make-icons.py` 生成的 14 个 PNG（含

## 二十、第十一轮：删掉全部的提示

### 20.1 起点：一句推翻上一轮的话

第十轮把原生 `title` 全换成了自绘气泡（`useHint` + `Hint.tsx`），
自认为"视觉问题解决了"。用户看完截图回了一句：

> 「@image#1 **不行，还是删掉全部的提示吧。**」

截图里那个气泡正**盖住正文三行**。

`AskUserQuestion` 澄清"删到什么程度"，用户选 **「两类全删（最干净）」**：
悬停气泡（24 处）**+** 常驻小字 `.grp-s`（34 处）**都删**。

### 20.2 ★★★ 根因不在"气泡好不好看"

第十轮的复盘写成"原生 tooltip 太丑 ⇒ 换自绘"。**那个复盘是错的。**
用户不接受自绘气泡，说明问题不在皮肤。三个理由（按重要性）：

1. **它遮住稿子。** 在提词器上盖住正文是**最大的一宗罪** ——
   而触发它只需要鼠标**路过**，不需要任何意图。
2. **它不受控。** 提词时鼠标往往就停在窗口上，气泡反复弹出又收回。
3. **里面装的不是用户当时需要的东西。** 会去看气泡的人**已经在看那个按钮**了；
   他要的是"按下去会怎样"，而气泡里写的是"这个功能为什么这样设计"——
   那是**给开发看的**。

⇒ 结论：**界面上所有说明文字一律不留。**

### 20.3 判据：'状态'与'警告'不是提示，是运行事实

34 处常驻小字**不是一刀切删的**，逐条判过。留下的判据只有一句：

> **不显示它，用户会不会做错事？**

会 ⇒ 就地常驻（`.grp-s`）；不会（只是解释原理/取舍）⇒ 删。

**保留的 16 处**（每处在代码里都有 `// ★ **保留**：…` 注明理由）：

| 类别 | 例子 |
| --- | --- |
| 运行状态 | 「当前」、`麦克风探针`「正在测」、`识别服务`「实际在工作」 |
| 警告 | `全屏提词`「共享屏幕时别用」 |
| 当前口径 | `快捷跳读`「单击 / 双击」 |
| 代价 | `磨砂`「吃性能」、`固定顶栏`「盖住第一行」 |
| 另一半语义 | `平滑滚动`、`念过的段落降明度` |
| 联动关系 | `窗口置顶`「开始提词会自动打开」 |
| 物理后果 | `镜像`「文字反过来」 |
| 选择后果 | `ASR 引擎`「音频外不外发」 |
| 算出来的数 | `滚动速度`/`参考语速`「300 字/分」 |

★★ 这条判据写进了 `check-tooltips.py` 的报错文案与 `SettingsDrawer.tsx`
的 `Row` 注释里 —— 否则下一个人会以为"删提示"就是"把 `sub` 也删干净"。

### 20.4 ★★ 两处「删提示 = 删信息」

| 位置 | 结论 |
| --- | --- |
| `jumpHint`（`PrompterView` 的跳读说明） | **没丢**：`quick_jump` 下方那行 `.grp-s` 本来就在说同一件事 |
| `report.fallback_hint`（隐身失败的回落路径） | **真丢了**：原先只出现在气泡与 warning 的 `detail` 里，两处都没了 ⇒ **无替代出口** |

第二处是本轮**唯一**"删提示 = 删功能"的地方。已在 `TopBar.tsx` 注释里写明
"为何接受 + 留作未决"——**不假装它还在**。

### 20.5 ★★★ 本轮最大的坑：桩的"按文字找"第三次静默失效

| 代 | 桩怎么找按钮 | 什么时候失效 |
| --- | --- | --- |
| 一 | 按原生 `title` 文字（`byTitle(".icon-btn","设置")`） | 第十轮 `title` 清零 |
| 二 | 按 `data-hint` 文字 | **第十一轮提示删净** |
| 三 | **按结构**：`iconAt(n)` / `iconFromEnd(n)` | — |

第二代失效的症状：`byTitle()` 返回 `undefined`、`el?.click()` **静默 no-op**，
`diag` 里只留一个 `tap1=none`。★ 它藏在**桩**里、不在产物里 ⇒
**任何产物侧的门槛都拦不住**。

⇒ 第三代改成按结构找，并**每一步都报名字**（`iconName(el)` 给 class/aria-label）——
让"序号漂了"能被看出来，而不是静默指错。

★ 判据分层（这一轮想清楚的）：
* **按钮** → 锚**位置**（文案比图标数量更容易变）；
* **设置里的一行** → 锚 `.grp-t` 文字（那是**控件的名字**，不随别处增删而变）。

### 20.6 ★ 同族第二个坑：`waitFor` 等的选择器也消失了

桩的入口是 `waitFor(".hint-ico", …)` —— 等提示图标出现才开始驾驶。
提示删净后这个选择器**永远等不到** ⇒ 300×25ms ≈ 7.5s 后写
`PREVIEW_FAIL:.hint-ico` ⇒ 桩一句都没执行 ⇒ 产物侧门槛报
**"预览没跑起来（先 npm run build 试试）"**。

★ 这与 19.8 记的 `--out nul` 坑是**同一族**：真正的病因与它给的提示完全对不上，
会让人反复重 build 一个本来没问题的前端。

⇒ 等的东西换成了 `.topbar .icon-btn`（结构的、这轮不会消失的）。
同时删掉了 `click=hint:N` 分支（它同样按 `.hint-ico` 找，已永远选不中）。

### 20.7 门槛换代 + 新增第四道

`check-tooltips.py` 从"禁 title、要求走气泡"改成**"禁一切提示"**：
按**名字**查（`title=` + `\buseHint\b` / `\bHint\b` / `tip-bubble` / `hint-ico`），
`\b` 锚整词以免误伤 `scriptExtsHint` / `fallback_hint` / `collapse_hint`
这些**后端字段名**。三个变异（跨行 `title` / `useHint` 复活 / `.tip-bubble` 复活）
全部报红。

★★★ **新增 `check-hover-silent.py`**（第四道，每次跑）。为什么静态查名字不够：

* 有人换个名字重写一套悬停提示（`Tooltip.tsx` / `popover` / 自己 append div），
  查名字**拦不住**；
* **截图更拦不住** —— 截图里本来就没有悬停态，有提示时同样长这样。

⇒ 所以真的把事件发出去：按真实顺序
（`pointerover`→`mouseover`→`mouseenter`→`mousemove`）扫过**每一个**可交互元素，
再走一遍 `focus()`，然后数残留。实测：

```
[主界面]   扫过 80 个控件 → 气泡 0 个 / 原生 title 0 个
[设置抽屉] 扫过 80 个控件 → 气泡 0 个 / 原生 title 0 个
```

★ `hoverSwept` 不是装饰 —— 它是**防伪指标**：若哪天变成 0（选择器写错），
那两个 0 就毫无意义。故门槛要求 `hoverSwept >= 20`。
两个变异（塞 `title=` / 塞 `.tip-bubble`）都验过能报红。

### 20.8 ★★ 新门槛自己的坑：它读 `dist/`，不是源码

做 `.tip-bubble` 变异时真踩了一次，形态值得记：

```
往 App.tsx 塞 .tip-bubble → 但位置让 JSX 语法错了
⇒ npm run build 报 TS1382 失败 ⇒ dist/ 还是旧的（没有那个 div）
⇒ check-hover-silent.py 照跑、照报绿
```

**一次语法错误，可以让这道门槛悄悄验一个不存在的界面。**

⇒ 处置：`gates.py` 里它排在 `npm run build` **之后**，正常流程里 build
一失败就轮不到它。但**单独手工跑**（做变异测试时）必须自己先确认 build
真的成功了。这条写进了脚本文件头。

## 二十二、第十二轮之二：删掉全部功能介绍小字，说明收进「更多」

> 承接二十二节之前的第十二轮（磨砂三档）。本节记的是同一轮里的第二件事：
> **设置面板的信息层级重排**。

### 22.1 需求原文

用户截了一张设置面板的图，指着「背景磨砂」下面那行灰色小字：

> 「功能介绍小字太多了，全部都删除，一个不要留。
> 在更多里面加一个详细的各个功能介绍就可以。」

### 22.2 做了什么

| | 改前 | 改后 |
| --- | --- | --- |
| 设置面板行内小字 | **29 处** | **0 处** |
| 说明放哪 | 散在 29 行的下面 | 「更多」→「功能介绍」区，**37 条** |
| 抽屉一屏能看到 | 跟读组刚露头 | 跟读组 + 稿件组 + 外观组开头 |

### 22.3 关键决定：拆 prop，而不是逐个传 `undefined`

`Row` / `SliderRow` 上的 `sub` prop **整个删除**，29 处调用点跟着删。

理由是本项目的老判据：「能靠读注释记住的规则，在刚写完一大段代码时就是不成立」。
如果只把 29 处改成 `sub={undefined}`，下一个人加小字只需要删掉 `undefined` ——
没有任何阻力。拆掉 prop 之后，**`tsc` 才是那个守卫**。

★ 本轮实测到了它的价值：做变异测试时用脚本偷偷塞了一处 `sub={undefined}` 进去，
  `npm run build` 当场报 `TS2322: 'sub' does not exist`。当场发现、当场删掉。

### 22.4 每一处删掉的小字，现在谁来说

这是本轮**最花时间**的部分 —— 判据是「信号只换位置不消失」，
所以必须逐条定下替代出口，不能删完就算：

| 原来小字说的 | 现在谁来说 |
| --- | --- |
| 提词中：隐身 · 置顶 · 跟读 | 底部大圆按钮（图标＋底色）＋顶栏状态槽 |
| 未开始 · 还没有稿件 | 「开始」按钮无稿时**禁用** |

### 22.5 ★ 顺带查出一件先于本轮就存在的问题：`wpm_ref` 已经是死设置

删「参考语速」那行小字时顺手查了它的消费者，结果是：

* 前端：**只有那行小字**用它（算"剩下 X 字约 Y 分钟"）；
* 后端：只存不读（`state.rs` 里有字段，没有消费者）；
* 顶栏的剩余时间**第十一轮**就摘掉了 —— 注释写着"挪进了进度条的悬停说明"，
  而**进度条上并没有那个悬停说明**。那一版它就断了。

⇒ 本轮之后，「参考语速」这根滑杆**拖了没有任何可见后果**。

**处置**（按「显式失败不静默失败」）：**不擅自删**（删它属于改产品范围，
要老大拍板），而是在功能介绍里**如实写明**它现在拖动看不到直接效果，
并在代码注释里写清「哪天要把剩余时间重新显示出来，第一个要接的就是这里」。

> 这是本轮唯一一个**没有干净解决**的问题，需要老大定：
> ① 接回去（把剩余时间重新显示在顶栏）② 删掉这根滑杆 ③ 先留着。

### 22.6 门槛：把一条**失效**的断言换掉

`check-platform-layout.py` 里有一条「macOS 的收起提示里不许出现『任务栏』」，
它读的是那一行的 sub。小字删完后 `collapseRowSub` 恒为 `none`，
**那条断言变成永真** —— 它再也不会失败，却给人"平台用语有人守着"的错觉。

> **失效的门槛比没有门槛更危险。**

换成的断言：**抽屉里 `.grp-l .grp-s` 的处数必须为 0**（两个平台都验）。

★ 判别式为什么是 `.grp-l .grp-s` 而不是 `.grp-s`：
  块级说明（自检结论、模型缺失警告、"最近听到"、诊断结果）**仍然是** `.grp-s`，
  它们是运行事实、不是功能介绍小字，用 `.grp-s` 会一起数进来导致误报。

★ 变异测试：让桩往第一行 `.grp-l` 里注入一个 `.grp-s` ⇒ 两平台各报
  「还有 1 处行内小字」并退出码 1。还原后归零通过。**这道门槛有判别力。**

### 22.7 桩同步（改了 UI 必须改桩）

新增三个参数，都按**结构**找元素、不按位置：

* `moreclick=1` —— 展开「更多」组。
  ★ 坑：`Group` 可折叠时会先渲染一枚箭头 `›`，`textContent` 是「›更多」而不是
    「更多」。写成全等匹配会得到 `moreHead=none`，而且**它不报错**，
    只是 quietly 什么都没点，截图看起来跟没加这个参数一样。必须用 `includes`。
* `guideclick=1` —— 展开「功能介绍」。
  ★ 坑一：不能按「功能介绍」四个字找 —— 折叠态下那行的标签是
    「查看各项功能是做什么的」，**根本不含**那四个字（在 `.grp-sub-h` 上）。
    改用结构：`.grp-box .grp-row.tap .grp-caret`（可点 ＋ 带箭头，整页唯一）。
  ★ 坑二：`realTap` 的 click 是 **setTimeout 延后**发的，紧跟着量必然量到 0。
    必须再排一个 `setTimeout` 去量 —— 那不是"点了没反应"，是"还没重渲染"。
* `guidescroll=<px>` —— 滚到抽屉指定位置（37 条一次截不完）。

### 22.8 排版踩的两个坑（出图才发现，静态检查一个都拦不住）

1. **`★` 漏进用户界面**：功能介绍里有五处沿用了代码注释的 `★` 标记。
   开发者符号不该出现在产品文案里，已全部改成正常句子。
2. **术语与说明粘成一个词**：「当前开始或结束这一场提词」。
   ★ 两条路都试过、**都无效**：
   - CSS `column-gap`：gap 算的是 flex **项**之间的距离，而说明文字是
     **一项**（`flex: 1 1 0`）、内部逐字换行 ⇒ 术语仍贴着它的首字。
   - JSX 里写 `{" "}`：React 把相邻 span 之间的纯空白**折叠掉** ⇒ 出图无变化。

   ⇒ 只剩 `.guide-k::after`（伪元素挂在术语**自己**的盒子上，一定被渲染）。

   ★ 教训：这类问题**只有出图才看得见**，`tsc` 与静态门槛全绿。
   所以"改完 UI 一定要出图看"不是流程上的客套，是唯一有效的验收。
