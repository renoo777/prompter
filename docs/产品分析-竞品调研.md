# Prompter 产品分析 + 竞品调研

> 调研日期：2026-10-05
> 结论先行：**这个产品真正的稀缺性不在"提词器"，在"Windows 上被实测证明的投屏 OS 级隐形 + 离线中文语音跟随 + 强稿件管理"这三件事同时成立。**赛道比预想的挤（至少 6 个直接或间接竞品，其中 3 个 2026 年新出），但**没有一个把"隐形"这件事拿出客观证据**——这是本产品最锋利、也最难被复制的资产。
> 最大的结构性风险不是竞品，是 **macOS 15+ 上 Apple 已把公开隐形 API 作废**（详见 §4），而本产品 macOS 至今未上真机。

---

## 1. 结论先行：三句话

1. **定位成立，且是一个被验证过的真需求。**"投屏时稿子不外泄"是竞品里最贵的付费点（$150/mo 的 Final Round AI、¥48 的 HideCue 都建立在这上面），不是伪需求。
2. **但"隐形"本身正在迅速贬值。**ShareSpeak、HideCue、GhostPrompter、极简提词器都在 2026 年前后进入，全都在卖同一个 OS 级排除。**唯一还守得住的是"证据"和"中文本地链路"**。
3. **macOS 是这一整份分析里唯一的生死项。**Windows 已经实测通过（0.00% 像素差），macOS 走的是唯一已知有效但未验证的私有 API 路径。**上真机之前，"双平台"只是设计意图，不是产品事实。**

## 2. 产品自身分析

### 2.1 定位与核心价值

| 层 | 事实 | 判据 |
|---|---|---|
| **一句话** | 开飞书/腾讯会议投屏 PPT 时，稿件窗口对共享画面完全隐形，且跟着说话自动滚动 | README 首屏 |
| **真正解决什么** | 不是"读稿"，是**"读稿这件事不暴露"** | 竞品无一例外都把"invisible"放在第一位宣传位 |
| **替代方案** | ①纸质稿 ②PPT 备注页（自己都看得见，观众也看得见）③关摄像头躲稿 ④双人配合 | 全部有致命缺陷 |
| **真实使用场景** | 飞书/腾讯会议/钉钉汇报、直播口播、录课、面试准备 | 竞品场景清单高度重合 ⇒ 需求真实且同质 |

### 2.2 能力盘点：哪些是真护城河

按"竞品能不能一周内抄掉"分三档：

| 档位 | 能力 | 为什么在这档 |
|---|---|---|
| **🟢 独占/难抄** | Windows 投屏隐形**已实测**（0.00% 像素差） | 抄代码容易，抄"证据"难。见下方 §3.1 |
| **🟢** | **离线本地中文语音跟随** | 竞品的语音跟随全靠云（PromptSmart 用 Azure/Deepgram，Interview Copilot 用 Groq + Claude）。离线中文 = 无网络/无费用/无隐私外泄 |
| **🟢** | **docx 正文 + pptx 备注页**手写扫描器 | 竞品多是"导入 txt/md"或依赖云解析。"取 pptx 备注页"这个细节目前没见到第二家做对 |
| **🟡 中等** | 稿件管理（历史库 / 稿内查找 / 拖入 / 粘贴另存） | HideCue 有"无限笔记"、GhostPrompter 有"脚本管理"，但粒度粗 |
| **🟡** | 穿透 + 收起 + 托盘退出口 | 竞品有 click-through（GhostPrompter/HideCue 都有） |
| **⚪ 可替代** | 排版工具箱、亮暗主题、会前自检、匀速滚动 | 都是通用能力，任何一个提词器都有 |

**一句话判据：**"能提词 + 能隐形"是入场券（人人都有），"**隐形可被证明 + 语音离线中文 + 稿件开箱即用**"才是差异。

### 2.3 短板（按严重度）

| # | 短板 | 严重度 | 说明 |
|---|---|---|---|
| 1 | **macOS 未上真机** | 🔴 最高 | 唯一可能推翻"双平台"定位的项。详见 §4 |
| 2 | **不产安装包** | 🟠 高 | `--no-bundle` 意味着**没有卸载项、没有开始菜单、没有自动更新**。竞品 HideCue 在**微软应用商店**上架（支持语言含简中），ShareSpeak 强调"**不依赖 Microsoft Store**"打企业端。**分发渠道是产品能力的一部分**，现在是零 |
| 3 | **第二设备同步未实现** | 🟠 中高 | 竞品普遍给"1 个 license 覆盖 2~3 台设备"。团队/夫妻双机场景我们只能手动导入导出 |
| 4 | **无自动化更新/版本检查** | 🟡 中 | 改完代码要用户自己重新构建 |
| 5 | `wpm_ref`（参考语速）死设置 | 🟡 低 | 滑杆还在、后端只存不读，前端唯一的消费者（剩余时间）在第十一轮已摘掉。**一个拖了没后果的滑杆 = 一次静默的信任损耗** |
| 6 | 功能介绍 37 条无验收门槛 | 🟡 低 | `check-platform-layout.py` 只验"行内小字 == 0"，不验内容与实现是否一致 |
| 7 | 状态截图全为改版前旧图 | 🟡 低 | `check-state-shots.py` / `make-state-sheet.py` **给 ✅ 但什么都没验**——失效门槛比没门槛更危险 |

### 3.2 三条关键发现

#### ① 竞品的"隐形"全是**宣称**，没有一个拿出证据

我逐个核过：ShareSpeak 说 "invisible at the OS level"、HideCue 说"对观众完全隐形"、GhostPrompter 说 "Invisible in screen share"——**没有一家公布过验证方法**。而且 ShareSpeak 那张对比表是它自己写的（页面上明确写了 "ShareSpeak is our own app, so read this as a disclosure, not a neutral review"），把它列为可信来源是错的。

而本产品有 `verify-stealth.py`：用"隐藏窗口锚点 + 切换前后抓屏对比"给出 **0.00% 像素差**（不隐形时同区域 92.9% 变化），并反解出 α=0.942 与配置 0.94 一致。

> **这是全篇最值钱的一句：产品分析的价值不在"我们有多少功能"，在"我们能证明什么"。**
> 竞品在卖承诺，我们在卖测量结果。这一条应该变成产品的一部分，而不是 README 里的一段技术自述。

#### ② 价格带已经形成：买断 $15–60 / ¥48，不是一个订阅市场

隐形提词器赛道全部是**一次性买断**（ShareSpeak $14.99、HideCue ¥48、GhostPrompter $49），**没有一个收订阅**。而普通提词器赛道（PromptSmart $9.99/mo、Teleprompter.com $7.5–19.99/mo、VODIUM $15/mo）全是订阅。

> **判据：用户只为"隐形"付一次钱，不会为"隐形"按月付。** 订阅能收得上钱的地方，用户买的是云端能力（AI 写作、字幕、多平台同步）。
> 这直接决定本产品如果商业化，**不该做订阅**。

#### ③ 需求真实，但**"隐形"已经不是差异化了**

极简提词器功能极少（0 评分 0 用户），HideCue 刚发布 0 评分——但它们的存在证明了一件事：**中文用户明确在找这个东西**。2026 年 6 月前后至少 4 个同类产品集中出现。

同时要看到另一面：Interview Copilot 这条线正在把"隐形悬浮窗"和"AI 实时生成答案"绑在一起，客单价高一个数量级（$49–150/**月**）。**它们已经抢走了"愿意为此付大钱"的那部分用户**，而这条路带着明显的"面试作弊"舆论包袱（Amazon 明令禁止）。

## 4. 风险研判：macOS 隐形的真相（本报告最需决策的一节）

### 4.1 发生了什么

Apple 在 macOS 15 (Sequoia) 改了 WindowServer 合成架构：所有窗口先合成成单一 framebuffer，ScreenCaptureKit 直接抓那个 framebuffer。**结果：所有旧的窗口保护标志全部失效。**

| macOS 版本 | `NSWindow.sharingType = .none` | 状态 |
|---|---|---|
| ≤ 14 Sonoma | ✅ 有效 | 公开 API，可过 App Store |
| ≥ 15 Sequoia | ❌ **被 ScreenCaptureKit 忽略** | Apple 官方："目前没有公开 API 可防止屏幕捕获" |

**证据源**（多源交叉，非单一说法）：
- Tauri issue #14200（2025-09-20 提出，状态 `upstream`）——引用 Apple 开发者论坛的官方回复
- Electron issue #48258（同一问题在 Electron 侧的镜像）
- 第三方技术分析（sudonull）明确说明：Zoom/Teams/QuickTime/系统截图/新版 OBS 用 SCKit → **窗口可见**；而 Chrome `getDisplayMedia`/Google Meet/旧版 OBS 用 CoreGraphics → **窗口隐藏**

最后这条是本节最要命的：**同一个 app 在不同会议软件里隐形结果可能相反。** 这意味着"隐形"在 macOS 上不是开关，是**逐个客户端碰运气**。

### 4.2 好消息：我们代码里已经是那条唯一已知有效的路径

我核了 `src-tauri/src/stealth/macos.rs`：代码注释里写明 macOS ≥ 15 走私有 API `CGSSetWindowCaptureExcludeShape`，用 `dlsym` 动态查找、找不到就优雅降级。

我拿 Control.app（trycontrol.app）那篇技术博客对照——**他们公开的 macOS 15+ 方案，用的正是同一个 `CGSSetWindowCaptureExcludeShape`**。也就是说：**我们在没有真机的情况下，选中了目前社区唯一已知有效的那个符号。** 这不是运气，是"私有 API 只能开不能关 ⇒ 显式失败"这条判断基线带来的结果。

代价也清楚（Control.app 自己写在明处）：
- ❌ **App Store 审核必被拒**（未文档化 API）⇒ 只能官网分发
- ❌ **OS 更新后可能失效**，需要跟版本
- ❌ 撤销路径需要构造恢复形状，我们当前**显式失败**（要重启窗口）

### 4.3 三个选项

| | ① 双平台继续押注 | ② 主打 Windows，macOS 降为"尽力而为" | ③ 只做 Windows，砍掉 macOS |
|---|---|---|---|
| 工作量 | macOS 真机验证 + 跟 OS 版本 | 文档与 UI 如实降级表述 | 删 `stealth/macos.rs`、`win::platform` 分支、托盘原生实现 |
| 对定位的影响 | 完整，但要真机背书 | **诚实且可控**，竞品里没几家敢这么写 | 砍掉一半市场 |
| 风险 | macOS 15+ 私有 API 随时可能失效 | 无 | 无 |
| 建议 | 目标态 | **当前实际状态应该照实改** | 不建议 |

> **我的建议：现在就该把 README 里 macOS 那一列的措辞从"同左"改成"尽力而为，macOS 15+ 无公开 API 可用"**，并把"上真机"作为一条独立决策项，而不是混在"下一步"里。
> 现在 README 第 93–113 行大量写"✅ 同左"，而实际是"⚠️ 未验证"——**这违反本项目自己的诚实清单原则**。对外的产品文档里"同左"两个字是会被拆穿的。

## 5. 机会建议（按 ROI 排序）

| 优先级 | 建议 | 理由 | 成本 |

- ❌ 在 macOS 真机验证之前扩功能 —— 那个未知项随时会推翻定位
