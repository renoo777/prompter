  ★ 2026-10-04（第十二轮·磨砂玻璃）107→112 / 91→96，两处都 **+5**
  （`win::effects` 平台映射 3 条 + `state` 老配置迁移 2 条）。
  ★★ 顺带一条：期望数**不许凭印象改**。这一轮先写成 +3（只数了 effects 那三条），
  门槛当场报"数字变了"——**这正是它存在的理由**。
- 前端 `tsc --noEmit` 零错误 + `vite build` 通过；`--features local-asr` 与 `--no-default-features` 两种构建**零警告**
  （被裁代码用 `#[cfg_attr(not(feature = "local-asr"), allow(dead_code))]`）。
- ★ 定义了却没人用的 `pub const` 也触发 dead_code → 顺手改成断言自身不变式的测试
  （`PLAIN_EXTS` → `SCRIPT_EXTS == RICH_EXTS ∪ 纯文本、不许交叠不许漏`），比删掉有价值。
- ★★ 构建必须走 Tauri CLI（`npm run tauri:build`）。原始 `cargo build --release` **不带 `custom-protocol`**
  ⇒ 不嵌 `dist/`、仍读 `devUrl` 的 `localhost:5273` ⇒ **白屏**。
- ★★★ **出安装包要另走一条路，且不能写 `npm run tauri:build -- --bundles X`**（2026-09-28 实测）：
  `package.json` 那条脚本里的 `--no-bundle` 会**把后加的 `--bundles` 压掉**，
  而 Tauri **不报冲突** —— 症状是"命令成功、只出裸 exe、`bundle/` 目录根本没建"。
  ⇒ 出包一律用 **`npx tauri build --bundles <nsis|app|dmg>`**（绕过 npm script）。
  ★ 别为了出包去改 `package.json`：`--no-bundle` 是 Windows 日常开发的规矩
  （"永不产安装包、产物留在仓库里"），改了日常构建就会多打好几个用不上的包。
  **两条路各走各的。** 完整说明见 `docs/分发到另一台电脑.md`。
- ★★ **这个项目产出的 `prompter.exe` 不可单独分发**：Tauri 应用依赖系统的
  **WebView2 运行时**（`C:\Program Files (x86)\Microsoft\EdgeWebView\`）。Win11 / 打过补丁的
  Win10 基本自带，所以"拷 exe"在**新机器上大概率能跑**——但这是碰运气，
  对方机器没有时的表现是**"双击没反应、没有任何错误提示"**（Tauri 起不来不弹窗）。
  ⇒ 分发一律出安装包。NSIS 默认 `webviewInstallMode = downloadBootstrapper`（silent），
  即装的时候联网补 WebView2（已装的机器跳过）；完全离线要改 `offlineInstaller`（包涨到约 100MB）。
- 真机脚本用**系统 Python 3.12**（`C:\Users\26611\AppData\Local\Programs\Python\Python312\python.exe`，有 PIL+numpy）。
- ★★ 构建前一键清场：`python scripts/kill-prompter.py`（先 `--dry-run` 看会杀谁）。
  旧实例还在跑时 cargo 收尾会报 `error: failed to remove file ...prompter.exe / 拒绝访问。 (os error 5)`。
  - ★★ **别用一次"查进程"的空输出就断定没在跑**（2026-09-27 实测）：同一时刻 Bash 的
    `tasklist //FI ...` 与 PowerShell 工具**都返回空**，而 prompter.exe 正从产物路径运行、锁着 exe
    ⇒ 我据此以为"无需清理"，第一次出包直接撞 `os error 5`。判据用 `kill-prompter.py --dry-run`。
  - ★★ **`msedgewebview2.exe` 绝不能一锅端**：机器上同时有父为 **prompter.exe** 的（我们的，要清）
    和父为 **SearchHost.exe** 的（**Windows 搜索界面的渲染进程**，杀了掉任务栏搜索）。
    ⇒ 只按 **pid 树**杀；脚本会先算出"受保护"集合、事后复核它们还活着。
- ★ 四道门槛现在由 `python scripts/gates.py [--build]` 一条命令跑完（含零警告检查与期望数断言）。
  期望数写死在脚本里是**故意的** —— 数字变了而没人改它，就该有人解释为什么。
- ★★ **静态前端门槛五道，每次都要跑**（第十轮加两道、第十一轮加一道、第十二轮加一道、第十四轮加一道，`STATIC_CHECKS`）：

  - `python scripts/check-doc-refs.py` —— README / `docs/*.md` 里引用的**图片与文档链接

    ★ 加它的理由：**路径写错没有任何东西会响** —— 编译、`tsc`、出包、其它门槛
    **全都不读 Markdown**，本地也没人会一个个点开看，直到有人打开 GitHub 看见一排碎图和死链。

    ★ 判据里有一条是必须的：**先剥掉围栏代码块和行内代码**再找引用 —— 文档里正经会贴

    ⇒ **一个假阳性比没有门槛更坏**（真断链出现时没人再信它）。
    ★★ **它原本只查图片、叫 `check-doc-images.py`；同一天里"悬空引用"手工修了 6 处

    ① `docs/能力与验证状态.md` 里的 `src-tauri/src/stealth/macos.rs` ——

    "拿不到测量结果 —— 预览没跑起来（先 npm run build 试试）"。

## 架构约定（不可破）

- **分层**：`stealth` / `script` / `align` / `library` / `doc` + `win::geometry` / `win::click_through`
  **完全不认识 Tauri**，只有纯数据与纯函数，可独立单测（`src-tauri/src/lib.rs:1-22`）。
  例：穿透把「该不该切换」抽成纯函数 `next(zone, cursor, state)`，窗口 API 只负责执行。
  ★ 这条线决定「副屏拔掉窗口会不会跑出屏幕」「光标在控制区边缘穿透会不会抖」**能不能被自动化验证**。
- ★★ **「能不能单测」是选依赖的硬判据**：`.docx`/`.pptx` 抽正文选手写 XML 扫描器而非 `quick-xml` ——
  纯函数（吃 XML 吐文本）能把「多 run 拼同一行」「`<w:br/>` 算换行」「`&#65;`→`A`」全写成断言；
  引库则「库在这个边界怎么表现」变成**没法单测**的外部行为。→ **能用 20 行纯函数钉住的，别换成外部库的承诺。**
  ★ 前提写进注释：Office 生成的 XML 里正文的 `<` 一定转义成 `&lt;`，所以能按 `<` 切 —— 这条一破扫描器就错。
- **两处都要用的常量，一律后端当唯一源、前端只消费**（`doc::SCRIPT_EXTS` → `bootstrap.script_exts`）。
  反例：前端 dialog filter 曾硬编码 `["txt","md","markdown"]`，后端支持 `.docx` 后立刻出现
  「拖进来能载入、从「打开稿件」里选不到」。
- **前端不直接 `invoke("xxx")`**，全走 `lib/api.ts`（命令名散在组件里，后端改名要全局搜着改，拼错只在运行时炸）。
- `AppConfig` 带 `#[serde(default)]` ⇒ 新增字段自动兼容；但**删/改名字段会让老用户静默丢行为** → 要写迁移。
  ★★ **嵌套结构（如 `HotkeyConfig`）也必须加 `#[serde(default)]`**：没有 default 时往里**加一个字段**
  会让老用户反序列化**整份失败、静默清空**。凡「将来一定会加字段」的结构，default 一开始就要有。
- ★★ **一个文件只能有一个"拥有者"（每个字段）**：`config.json` 是**整份**写的，而有两个写者 ——
  前端（设置页改一项 ⇒ 防抖 400ms ⇒ 一整份）与后端（窗口几何 / `last_script` / 穿透 / 置顶，
  各自即时写）。前端手上那份是**启动那一刻**的快照，于是"拖完窗口大小、再改个别的设置"
  会把几何退回旧值；"换完稿件、再改个设置"会把 `last_script` 退回旧值。
  **症状只有一个说法：用户说"我设的东西没记住"** —— 而它指向配置，于是会被当成"保存坏了"。
  ⇒ 后端拥有的字段必须在 `save_config` 里从**内存态**盖回去（`state::merge_backend_owned`，
  纯函数，字段清单钉在单测里）。**新增一个后端会自己写的字段，就要同时加进那个清单。**
  ★ 同族（同一条纪律的另一面）：`window.locked` 归前端 —— 它也由后端命令写，但**前端也有**，
    两边值一致，所以没必要抢。判据是"**谁的信息更全**"，不是"谁先写的"。
- ★ **窗口的运行时属性若用户会在设置里关掉它，就必须落配置**：置顶曾被判为"摆窗口时的
  一次性动作、不落配置"（设置页一个 `useState`）—— 真用起来站不住：提词器的常态就是盖在 PPT 上，
  每次开机都要重点一次。⇒ 判据不是"它属于哪个功能"，而是"**不记住会不会让人每次都重复一遍**"。
  ★ 落地口径：**窗口属性与配置必须由同一条命令写**（`set_always_on_top`），
    因为改它的有"开始提词/收摊"和设置开关两处 —— 两边各写一份必然出现
    "界面说置顶、窗口没置顶"。
- ★★ **hook 一律写在提前返回（early return）之前**。`SettingsDrawer` 里
  `if (!config) return null;` 之后调了两个新 hook ⇒ 首帧 `config` 空、提前返回、
  hook 一次没跑；配置到位后突然多出两个 ⇒ hook 数量变化 ⇒ **React error #310**。
  压缩产物的报错**完全看不出是 hook 问题**，现象只剩**整页白屏**（红底错误边界）。
  ★ 定位手法（别在 stderr 上耗）：自己写探针页注入 `window.onerror` /
  `unhandledrejection`，把 message/file/line 塞进 `<title>` 再读回来。
- ★★ **同一件事只准一支按钮**：顶栏要"加东西"时，余量往往不在宽度里，而在
  **有没有两支按钮干同一件事**。（第七轮误加过一颗"调参"，与"设置"齿轮同功能，
  白压掉标题 23px。）
- ★★ **两个入口要共用同一段实现，不是两段相似的代码**：顶栏那颗与设置里那颗走同一个
  hook（`lib/sendToTaskbar.ts` / `lib/collapse.ts`）。抽 hook 顺带修掉旧毛病 ——
  设置里那颗原先直接调 `api.setCollapsed`，**跳过了第一拍动画**，手感与顶栏不一致。
- ★★ **按位置写死的断言会在下次改版时静默失效**：收起态验收原写
  `btns[btns.length - 2]`（"倒数第二颗是收起"），换成新按钮后直接指错。
  ⇒ 断言按**语义**写（找 `title` 含某关键词的那颗）。
  ★ 2026-09-27 更新：`title` 已被全项目清零（见下条），语义锚点改用
    **`data-hint`**（`useHint().trigger` 摊上去的说明首行）。`byTitle()` 已同步改读它。
- ★★★ **界面上任何需要文字解释的地方，一律走自绘气泡，不准出现原生 `title`**（第十轮）。
  原生 tooltip 的三个问题：① 视觉不归我们管（系统字体/配色，在一个精调过的深色玻璃窗上
  是**唯一没被设计过的东西**）；② 不为 560×360 小窗避让（超出边界的像素根本画不出来）；
  ③ 悬停约 1 秒才出、还不能换行。用户原话：「**特别特别 low，而且交互体验会特别差**」。
  ★ 守它的门槛是 `check-tooltips.py`，**每次**跑。**必须用脚本守的理由**：
  这个问题**截图看不见**（不悬停就不出现）⇒ 人手 review 一定漏。
  ★★ 判据细节：`<Group title="提词">` 这类**组件 prop** 不算违规（不落 DOM）；
  按"标签名是否小写开头"区分 DOM 属性与组件 prop。
- ★★★ **`useHint` 的 `ref` 必须由 hook 自己摊出去，不能指望调用方记得传**（第十轮，血证）。
  第一版只返回 `anchor`（让调用方写 `ref={hint.anchor}`），结果**30 多个调用点没有一个写**
  ⇒ `anchor.current` 恒为 null ⇒ 位置算不出来 ⇒ 气泡永远 `visibility:hidden` 挂在 (0,0)：
  **鼠标移上去什么都不发生（= 功能没做）**，而 `tsc`、`vite build`、`check-tooltips`
  **全都绿着**。这就是"把功能改没了，而所有门槛都通过"的典型形态。
  ⇒ 修法不是"提醒大家记得传 ref"，而是**让 ref 不可能忘**（并进 `{...hint.trigger}`）。
  ★ 类型坑：`RefObject<HTMLElement|null>` 摊不上 JSX 的 `ref`（要具体元素类型，TS2322）
  ⇒ 用**回调 ref**（入参协变，一个写法对所有元素类型成立）。
  ★ 同一条纪律的另一半也进了门槛：**摊了 `trigger` 却忘了渲染 `bubbleEl`**，
  同样是"编译过、截图看不出、功能没了"，`check-tooltips.py` 一并查。
- ★★★ **"要靠读注释记住"的规则一律不成立 —— 该机器判的必须机器判**（第十轮总结）。
  本轮往 **4 个**组件里加 `useHint`，**4 个**都写在了提前返回之后（React error #310）；
  其中一份文件（`SettingsDrawer.tsx`）里**就在上一轮写过一条注释**，
  标题正是「这两个 hook 必须在所有提前返回之前调用」，还记着症状。照样踩。
  ⇒ 加 `check-hook-order.py`（每次跑），按**花括号深度**只认组件体那一层的 `return`
  —— 不能把 `useEffect(() => { if (!x) return; })` 里的守卫也算进去
  （第一版算了，报出 20 处假阳性；**永远红着的门槛会被直接忽略**）。
- ★★ **一道门槛"通过"了什么也证明不了，先证明它"能失败"**（第十轮，两次都验了）。
  `check-tooltips.py` 第一版逐行正则，**漏掉整整一类**：JSX 里绝大多数标签都是
  「标签名一行、属性各一行」，而逐行扫描看不见跨行的 `title=`。
  它第一次跑就"通过"了 —— **因为它也瞎**。往 `FindBar` 塞一个多行 `title=` 才暴露。
  ⇒ 规矩：**新门槛必须做一次变异测试**（塞一个已知违规，确认报红，再还原）。
  本轮的 `check-tooltips` / `check-hook-order` / `bubbleEl` 三条都验过能失败。

## 产品取向（有论证的，别当审美偏好推翻）

- **深色是论证过的**：窗口长期浮在 PPT 之上、视线高频切换，浅色让瞳孔反复收缩、高饱和块在余光里抢注意力
  （`src/styles.css:1-9`）。默认深色，浅色只是可选项。
- ★★ **宁可显式失败，不可静默失败**。反面教材在本项目里就有：「拖放」承诺了（空态文案写着"拖进来"）
  但实际零处理、静默丢弃。**新增交互必须回答"失败了用户看不看得见"**。
- `focus:false` + `skipTaskbar:true` + `alwaysOnTop` = **不抢用户操作**，立身之本，新能力都不得破坏。
- ★★ **穿透必须配托盘 —— 这是不可撤销性要求**：穿透态下收不到任何鼠标消息、右键菜单也出不来，
  若只能改配置文件才能退出，这功能就是**把窗口锁死**。
  → **任何"会关掉某个输入通道"的能力，都必须附一个不受该通道影响的退出口。**
- ★★ **退出口还必须"找得到"，否则等于没有**。窗口 `skipTaskbar:true` 时，
  **原生最小化 = 把窗口送进一个既不在屏幕上、也没有任务栏入口的地方**；
  退路只剩托盘图标（Win11 默认折进 `^` 溢出区）与全局热键（用户不知道）。
  `tray.rs` 开头"三件事叠在一起会让窗口彻底找不回来"那段注释，因此**一字不差地应验了** ——
  触发它的却是最普通的那个「最小化」按钮（真实反馈：「我点击右上角的缩小就找不到这个软件了」）。
  → 处置：① 按钮语义改成**收进托盘**（`hide()`），图标也换成"箭头入托盘"。
  **一条横线说的话是"缩到任务栏"，而这是个错误预期**；形状本身就是那句说明。
  ② **本次运行首次**执行时，先在窗口正中给 1.7s 提示，说清"它去哪了、怎么叫回来"——
  窗口可以消失，但**这件事必须在消失之前交代**（消失之后说给谁听？）。
- ★ **收起态（只剩一条控制栏）整窗都是控制区，永不切穿透**，否则用户收起来后连"展开"都点不到。
- ★ **越界值回落默认，不夹到边界**（夹到下限得到"能开但没法用"的窗口）。
  位置同理：判"还在不在屏里"用**重叠面积 ≥ 80px** 而非"左上角在屏内"；**副屏在主屏左侧的负坐标合法，原样保留**。
- ★★ **「查」与「跳」必须是两个动作**：查找只做"滚过去 + 标出来"，**绝不移动朗读光标**；要真念有独立的
  「从这处开始读」。理由：找位置这个动作本身会把位置弄丢。→ **"浏览/定位"类交互不得有副作用地改掉"当前进度"。**
- ★ **搜索的计数与高亮必须共用同一个匹配函数**（`lib/find.ts::findHits`）；各算一遍必然在"大小写怎么算/
  空查询怎么办"上分叉，表现是"数着 12 处只标出 11 处"。附带守卫：用 `indexOf` 而非正则（搜 `(` `[` `.`
  不该要先学转义）；`toLowerCase()` **不保证长度不变**（'İ'→2 字符），长度不一致就退回区分大小写。
- ★★ **"编辑当前内容"绝不写回源文件**：改稿走 `set_script_text` 另存副本，原文件一字不动（界面上明写）。
  → **凡"用户上传过的东西"，改它的默认语义是另存，不是覆盖。**
- ★ **两个不同的事绝不能叫同一个名字**：设置 › 窗口 里的「锁定」= 位置锁定（防误拖）；
  同组里的「控制栏浮在正文之上」= `bar_pinned`（占不占正文的地方）。
  叫成同一个词，用户永远不知道自己锁的是哪个。
  ★（改版前「锁定」在顶栏，是一条会**被顺手误按**的常驻控件；现在两者同组，正好并列着区分。）
- ★★ **设置页「说明可以藏，警告不能藏」**：解释性文案可收进感叹号 hover 气泡；**破坏性/不可逆的后果必须
  不用 hover 就能看见**（保留：导入会覆盖当前稿件 / 原文件不动 / 会盖住 PPT）。
  → 判据：**"能不能藏"的标准是"不点它会不会出事"，不是"它长不长"。**
- ★ **"跟随系统"不能只信 store**：`data-theme` 由 JS 直接改 DOM，系统主题变化时 React 不重渲染
  ⇒ 依赖 `config.theme` 的图标会停在旧值。要显示"当前实际生效的观感"，组件得自己订阅 `matchMedia`。
- ★ 新按钮往**还有空位的那一条栏**放，不是往"看起来最像工具栏的那一条"放。
  ★ 更根本的一条：**控件该不该留在常驻栏上，判据是"一场直播里按几次"**，不是"它属于哪个功能"。
  本轮据此把「穿透 / 锁定 / 全屏 / 主题」全部收进设置 —— 它们都是"设好就不动"的，留在栏上只占地方。
- ★★ **只有一条栏，贴在窗口最上方**（2026-09-26 两条并一条；`--h-cb: 0px` ⇒ 底部没有栏）：
  `bar_pinned:true` 时它 `position: absolute` 浮在正文之上，正文**从栏的下方开始**；
  `bar_pinned:false`（`.app.bar-inline`）回到普通流，占独立一行。
  ★★ 这条栏的宽度是**全项目最紧的一环**（560px 一行里塞十余件事）。动它之前先看
  [`技术决策与架构.md`](技术决策与架构.md) 的「一条栏贴在窗口最上方」：能给「标题 + 进度条」分的是
  `行宽 − 定宽项 − 间距 − 内边距`（实测约 175px），而 `flex-grow`/比例/`min-width`
  **都改不动这个总数** —— 想让标题多显示几个字，只能把定宽的东西改小。
  ★★ **往栏上加一颗图标，只能从标题身上扣**（第七轮实测：560px 下基线
  `topIcons=5` / `titleW=116` / `titleShort=-0.6` —— 余量是**零**）。
  所以「加一颗按钮」的正确姿势通常是**「换」**：删一颗不常用的、换上新那颗，
  总数保持 5。★ 且回答"加这颗要不要紧"必须拿**逐字节数值**比（`titleW`、`titleShort`），
  不能靠看图 —— 图里 `2026 上半年经营汇报` 看着完好，数里可能已经被压碎。
- ★★ **删掉一个控件之前，先确认它原来的"失败信号"还有别处承载**（本轮真踩，见 `UI改版-PM拆解.md` R9）：
  把「穿透」从顶栏收进设置时，**退出口**三条都还在（R1 守住了），
  但 `ctActive`/`ctPending` 变成**没人消费的死状态** ⇒ "开了但没生效"在界面上完全静默
  ⇒ 正好退回"点了没反应"。它不报错、不占地方、**全部门槛都绿**。
  → 每收走一个控件，要问的不是"功能还在吗"，而是**「它原来负责说的那句话，现在谁说」**。
  信号的处置与退出口一样：**不消失，只换位置**（现挂在控制台那个唯一的状态槽上）。
  ★ 判断条件也要挑对：用 `ctPending && !ctActive`（意图已下、后端没确认），
  **不是** `!ctActive` —— 后者在"压根没开"时为真，会常年挂一条假警告。
- ★★ **控制栏图标一律内联 SVG，不用 Unicode 字形**（`components/Icons.tsx`）。字形（`⌕ ✎ ☰ ⚙ ─ ✕ ⛶ ☾ ☀ ▴ ▾`）
  放大后宽度/基线各平台不一致、缺字体变豆腐块 → **任何"放大控件规模"的改动必须同时把字形换成 SVG**。
- ★★ **"收起来"必须落在一个用户走得到的地方**（2026-09-27 第六轮）：
  原文案是「已收进系统托盘 · **点托盘图标**」—— 而 Win11 把新托盘图标默认折进 `^`
  溢出区（实测 `IsPromoted=0`），**程序还无法自己提升它**。于是那句提示在
  **指着一个他看不见的东西**，用户的原话就是「没有办法收起到这里」。
  → 三点：① 落点要选**用户本来就会去找的位置**（任务栏按钮优于托盘图标，
  因为前者是所有 Windows 软件的共同肌肉记忆）；② 提示里写的落点必须**当下可达**
  （写之前先确认它真的在那儿）；③ 形状/文案/键名都要跟着落点一起改，
  **别留旧名字**（`IconTray`、`click=tray`、`06-tray.png` 全部同步改掉）——

  「收进任务栏」先画成"底边 + 下箭头"（理由是"往下缩到那条线里"），
  反馈一句到位：**那在全世界都读成「下载」**。下箭头 / 托盘加箭头这一族图形
  在系统、浏览器、办公软件里被用烂，含义是"保存到本地"，用户改不了这个条件反射。
  ⇒ 改成一条横线。**宁可朴素，不可被误读**；且改完要在注释里写明
  "为什么箭头也是错的"，否则下一个人会觉得箭头更直观、又改回去。
- ★★ **README（产品页）该放什么：只放"读者是使用者"的东西。**
  **只问一句：它的读者是「想用这个产品的人」，还是「我们自己」？**
  判定表与每份维护者文档的"什么时候读"见 [`README.md`](README.md)（docs 索引）。
  ★ 这条不是审美偏好，是**实际踩过**：2026-10-09 把 README 收成产品页那一轮，

  《上传GitHub操作指引》这种东西也挂在了产品首页上。用户原话：

  ⇒ **产品页里的链接不是目录，是"读者读完这一页之后真挚会有的下一个问题"**

## ★★ 提示专题（第十一轮：界面上**不留任何悬停提示**）

> 完整记录见 `docs/UI改版-PM拆解.md` 第二十节。

### ★★★ 一、根因不是"气泡好不好看"

三代演变，每一代都以为解决了问题：

| 代 | 做法 | 用户的反应 |
| --- | --- | --- |
| 一 | 原生 `title` | 「**特别特别 low，而且交互体验会特别差**」 |
| 二 | 自绘气泡（跟随主题、能换行、会避让） | 「**不行，还是删掉全部的提示吧**」 |
| 三 | **全删** | — |

★★ 第二代的复盘写成"原生 tooltip 太丑 ⇒ 换自绘"，**那个复盘是错的**。
用户不接受自绘气泡，说明问题不在皮肤。真正的根因三条：

1. **它遮住稿子** —— 提词器上盖住正文是**最大的一宗罪**，而触发它只需鼠标**路过**。
2. **它不受控** —— 提词时鼠标往往就停在窗口上，气泡反复弹出又收回。
3. **里面装的不是用户当时需要的东西** —— 会去看气泡的人**已经在看那个按钮**了，
   他要的是"按下去会怎样"；气泡写的是"这功能为什么这么设计"——那是**给开发看的**。

⇒ **界面上所有说明文字一律不留。**

### ★★★ 二、'状态'与'警告'不是提示，是**运行事实**

删的时候**不能一刀切**。判据只有一句：

> **不显示它，用户会不会做错事？**

会 ⇒ **就地常驻**（`.grp-s` 小字）；不会（只解释原理/取舍）⇒ 删。

第十一轮 34 处常驻小字里**留了 16 处**，覆盖这几类（各自在代码里带
`// ★ **保留**：…` 注明理由）：运行状态、警告、当前口径（单击还是双击）、
代价（吃性能 / 盖住第一行）、另一半语义、联动关系（开始提词会自动开置顶）、
物理后果（镜像 ⇒ 文字反过来）、选择后果（ASR 引擎 ⇒ 音频外不外发）、
算出来的数（参考语速 300 字/分）。

★ 旧规则（第九轮）说"说明可以藏进 hover、警告不能藏"—— **"藏"的载体没了，
但"警告不能藏"这半条依然成立**，只是现在连"说明"也不给悬停出口。

#### ★★★★ 2026-09-28 覆盖：常驻小字**也**删，理由从"不遮挡"换成"每行都贵"

用户第十二轮的截图指着一行灰色小字：「功能介绍小字太多了，全部都删除，
一个不要留。在更多里面加一个详细的各个功能介绍就可以。」

⇒ **上面那条「会 ⇒ 就地常驻」的例外被取消**。第十一轮留下的 16 处，
本轮连同另外 13 处一起删掉，共 **29 处**归零。

## ★★ macOS 移植（第九轮起：五条硬判据）

> 完整记录见 `docs/UI改版-PM拆解.md` 第十八节。这里是可复用的那几条。

### ★★★ 一、被 `#[cfg(target_os = ...)]` 圈住的代码，开发机上**永远不被编译**

`stealth/macos.rs` 274 行，全文是 `objc_msgSend` 强转 + `dlsym` 私有符号 +
`sysctlbyname` 缓冲区 —— **项目里最不可能靠肉眼看出错的一段**，而它在 Windows 上
连 `cargo test` 都不看它一眼。⇒ "能不能编过"被推迟到真机第一次构建，
而那一刻同时有 SDK/链接/打包一堆报错挤在一起。

**处置**：`scripts/check-macos-backend.py` 用 `RUSTFLAGS=--cfg prompter_check_macos`
强制编译。★ 机制是 **`mod { #![cfg(target_os="macos")] include!(...) }`** ——
必须用 **inner attribute** 才能"编译到但排除解析"；用外挂 `#[cfg]` 会把它整个剔掉、
用裸 `include!` 会因为 `#[link(name="objc")]` / `libc::` 报一堆**假错**。
★ `--cfg` 还得在 `Cargo.toml` 的 `[lints.rust]` 里声明，否则检查自己会多出一条
`unexpected_cfgs` 警告，把"零警告"门槛弄红。

### ★★★ 二、移植一个能力之前，先问「目标平台上有没有**落点**」

Windows「收进任务栏」的落点是**任务栏按钮**（`ITaskbarList::AddTab`）。
macOS **没有这个东西**：Dock 图标只认冷启动时的 `activationPolicy`，
启动后改它 Dock 不重排 ⇒ **窗口缩下去、没有任何入口回来**（静默失败）。

**判据**：平台移植时，"API 有没有对应物"是第二个问题；第一个问题是
**"这个动作的落点在那边的语义里存不存在"**。落点不存在的，要重新设计动作，
而不是找个相似 API 硬套。

### ★★★ 三、落点不同 ⇒ 入口的**数量**不同，不只是文案不同

macOS 上「收进任务栏」按下等于「收起」⇒ 设置里留着两颗按钮就是
**两颗按钮干同一件事**（本项目明令禁止）。⇒ 按钮数**随平台变**
（Windows 两颗 / macOS 一颗）。

★ 关键实现选择：**平台判定与文案都由后端给**（`win::platform` 的
`collapse_label` / `collapse_hint` / `has_taskbar`），前端只渲染。
理由：同一个判断在后端已经有一份（`minimize_to_taskbar` 靠它分流），
前端再写一份文案分支就会漂成"按钮说一套、按下做另一套"。

### ★★ 四、「顶栏图标数 = 5」要改成「**最多** 5」

第七/八轮把它定成定数（因为标题宽度是定数）。macOS 上少一颗之后，
字面不成立了 ⇒ **上限 5，不是必须凑满**；少掉的宽度**归标题**。
★ 移植前 560px 下 `titleShort=-0.6`（标题**本来就已被省略号截了**）
⇒ macOS `-16.6` 是**修好了**，不是回归。
★★ 必须写进断言，否则后人看到数字不对会**补一颗图标把位置填满** —— 正好压回去。

**★★ `titleShort` 的符号别搞反**：它是 `文字宽 − 盒子宽`
⇒ **正数才是放不下**。（我第一版断言就写反了，差点去"修"一个对的数字。）
⇒ 用桩直接给的 `titleClip`（yes/no），别自己对符号下结论。

### ★★ 五、界面上的热键，一律从 `config.hotkeys` 现取

`Ctrl+Alt+X` 在界面上有 **11 处**硬编码。它有两重错：
① macOS 后端注册的是 `Command+Option+X`（`Ctrl+方向键` 被 Mission Control 占着，
照搬会跟系统抢键）⇒ 界面还在说 `Ctrl+Alt` 等于**指一个按不出来的键**；
② 热键是用户能改的 ⇒ 改完键之后所有提示全在说假话。
⇒ 收口成 `types.ts::hotkeyLabel()`，**只留一个来源**。

### ★★★ 六、给对象发方法前先问「这个方法**属于哪个类**」

`raw_window_handle` 的 `AppKit` 变体给的是 **`NSView*`**，而项目要用的
`setSharingType:` / `windowNumber` **都是 `NSWindow` 的方法**。
对 view 发这些选择子 ⇒ `unrecognized selector` ⇒ 在 `objc_msgSend` 的
**C ABI 下直接终止进程**（不是 panic，没有 unwind、没有捕获点）
⇒ 用户看到的症状是「一开隐身就闪退」，而**日志里什么都没有**。

**判据**：runtime FFI（`objc_msgSend` + `sel_registerName`）没有编译期检查 ——
**选择子的归属类只能靠人记住**。⇒ 拿到一个"窗口句柄"时，必须问清
「在这个平台上它是哪个类的实例」，并让**真正发选择子的那一层**负责升到位
（本项目放在 `stealth::macos::view_window`，不是放在 `native_handle`）。

★ **顺带一条组织判据**：注释说「某处会做 X」而代码其实没做 ⇒ 比单纯写错更危险，
因为下一个人**会相信它**。发现这种矛盾要**收敛到一处**（改代码或改注释，
不是两边各改一半），并把「为什么必须这么做」写进注释 —— 否则会被改回去。

### ★★ 七、私有 API 只能开不能关时，要**显式失败**

`CGSSetWindowCaptureExcludeShape` 的 `shape=NULL` 语义是「完全排除」。
关闭隐身时若沿用 NULL，结果是**关不掉**。没有公开文档说明恢复该传什么形状，
真机又试不出来 ⇒ 直接返回 `Err("私有 API 路径不支持撤销")`，
UI 如实显示"未能关闭隐身" —— 而不是静默地以为已经关掉了。
★ 配一条单测把这条契约焊死（`closing_stealth_must_not_silently_succeed`），
拦的就是将来"顺手让它也能传 NULL"的那次改动。

## 动效（第八轮起：按 Uiverse 惯例定 token）

- ★★ **时长与缓动是 token，不是散落的数字**（`styles.css` 顶部）：
  `--t-press:90` / `--t-fast:140` / `--t-base:190` / `--t-enter:240`（ms），
  缓动 `--ease`（通用/大位移）、`--ease-back`（带过冲，只给"出现/长出来"）、
  `--ease-in`（退场）。
  ★ 档位**从"谁在动"反推**，名字说用途不写数值区间（写 `--t-150`，调成 160 就成了谎言）。
  ★ **微交互上限守死 250ms**（Uiverse/常见平台的惯例是 150–250ms），
  提词器还要更严：**动画还在播＝在和稿子抢视线**。
- ★★ **跟连续信号走的过渡一律 `linear` 且极短，不复用 token**：
  收音环 `0.08s linear`（跟麦克风电平）、进度条 `0.12s linear`（跟识别进度）、
  段落推进 `0.32s ease`（跟**语速**，必须慢于按钮反馈，否则用户还没念完下一句）。
  → 判据一句话：**跟连续信号走 ⇒ linear；跟语速走 ⇒ 慢于按钮反馈；
  跟一次交互走 ⇒ 才用 token。**
- ★★ **过冲缓动（`--ease-back`）只给"东西出现/长出来"，且位移量必须小**：
  6px 的入场位移过冲约 2px = "轻轻落下"；40px 上就是"甩"、会晕。
  大位移（抽屉 352px 滑出）一律回 `--ease`。
- ★★ **按压反馈加不加 `scale`，看它有没有邻居**：
  `.icon-btn` 只位移**不缩放**（一排挨着的按钮各自胀缩会读成"在抖"）；
  `.hero-btn` / `.btn` / `.tb-step` 加 `scale`（孤立控件，46px 圆里 1px 位移看不见）。
  幅度**与元素尺寸成反比**（越小的控件要越大的相对变化：0.98 / 0.96 / 0.94）。
- ★★ **两条全局动效策略写在 `styles.css` 末尾**（靠层叠压住所有个例，放前面会被盖回来）：
  1. `.app.prompting`（由 `asrStatus.running` 驱动）：**停装饰性动效、留状态性动效**。
     判据 = 这个动效有没有在传达状态。★ 不全停的理由：提词中用户仍会点暂停，
     需要看到"我按到了"；★ 必须停的理由：**屏幕正在被当作稿子读**。
  2. `@media (prefers-reduced-motion: reduce)` 用**通配符全覆盖**
     （原来只点名 `.switch` ⇒ "只有开关尊重了这个设置"）。
     ★ 用 `0.01ms` 不是 `0s`：`0s` 会让部分浏览器**跳过 `transitionend`**，
     而收起动画的第二拍在等这个事件。
- ★★ **`transition` 写错不会报错**（拼错 token、少个分号、被后面覆盖 ⇒ 浏览器静默忽略）。
  ⇒ 动效也要有断言，且**期望值从唯一源现算**（桩里的 `motion*=`，同 `--expect-bars`）。
  ★★ 断言要验**"命中"而不是"写了"**：只查"类在不在"不够 ——
  同特异性规则可以在后面盖掉它，那时类在、效果不在，断言照样绿。
  正解是读一个**受它管辖的属性的计算值**（如 `.icon-btn` 的 `transition-property`
  里还有没有 `transform`）。
- ★★ **拿 `getComputedStyle` 的值做数值比较前，必须先归一单位**：
  实测同一个 `:root` 里 `--t-press: 90ms` 读回是 `90ms`，
  而 `--t-fast: 140ms` 被**规范化成 `.14s`** ⇒ `parseFloat` 成了「90 与 0.14 比较」，
  断言报错但 CSS 全对。（别把 `parseFloat` 当成"读 CSS 数值"的通用解法。）
- ★ **造一个状态要用它真实的到达路径**：想让预览进入"提词中"，
  改 `asr_status` **命令**的桩返回是没用的 ——
  前端拿 `running` 走的是 `events.onAsrStatus` **事件**通道，启动时不调那个命令。
  顺着真实监听路径发事件才算"验到了"（查询串开关 `prompting=1`）。

### 状态要由界面本身表达，而不是弹一段字

- ★★ **能用界面状态表达的，就不要用文字复述**。删掉的都是**确认类**（"已切换主题 / 已锁定 / 已全屏 /
  已载入 XX 字"）—— 界面上本来就有对应变化（图标翻了、按钮文字变了、稿子换了）。
  **判断"这处长文案能不能删"的标准是"不弹它会不会出事"，不是"它长不长"。**
- ★★ **警告类不能删，只能换位置**。典型：「历史已清空，但你的原始文件一个都没删」——
  界面状态说不出来。处置是把它从"操作后强塞的弹窗"移到**就地可查**的位置
  （历史浮层底部本来就有一行常驻说明，那是**点之前**就看得见的，比事后一句更早）。
- ★★ **"关掉"和"暂停"是两件事，而"暂停"必须可逆、有记忆**。隐身后端只有 `hidden|visible` 两态，
  所以三态要靠前端 `stealthIntent` 推：`visible` + 原本意图是 `on` ⇒ **暂停**（不是关掉）。
  漏掉这层推断的后果很具体：演示中途按一下热键，界面上就只剩「重新开启」，再也找不到「继续」。
  → **凡"会关掉某个能力"的控件，都要先问：用户会不会需要"暂时关一下、等下接着用"。**
- ★★ **"彻底关掉"不进循环控件**。隐身的 pill 只在「未开启 → 隐身中 → 已暂停」之间循环，
  "不用它了"属于设置项。做进 pill 会让人在演示中途手一抖撤掉保护。
  → **不可逆的那一档，与可逆的几档分开放。**
- ★★ **"暂停"的粒度是"这个能力里可逆的那一部分"**。演示模式 = 隐身 + 置顶 + 跟读，
  它的暂停**只停跟读**，隐身与置顶原样保留 —— 那才是"脱稿讲一段、回头接上"要的。
  上一版「点一下 = 收摊」，用户只想暂停却把整个演示关掉了（pill 退回「▶ 演示」，只能从头重开）。
  实现上后端只有"跟读在不在跑"一维，所以「已暂停」同样要靠前端 `demoPaused` 推出来 ——
  **与隐身的 `stealthIntent` 是同一个问题、同一个解法：后端只有事实，意图由前端记住。**
- ★★ **"跟读没起来就不翻牌子"**：暂停/继续两个分支都**只在真的成功之后**才改状态。
  翻早了 = 界面上蓝着「已暂停」而跟读其实还在推光标 —— **一个说假话的状态比不翻更坏**
  （同 `StatusWarning` 那条：会把人引到错的地方去查）。
- ★★ **提词器不是歌词播放器 —— 照抄歌词范式时，有四条必须反着来**：
  1. **"未唱"只降一档，不降到最淡**：歌词可以把未唱压得很淡（下一句马上亮），
     而提词器里"还没念的那半句"是讲者**下一秒要看的字**，压过头等于把稿子擦掉。
  2. **层次做在段落上，不做在句子上**：句子是 inline 元素，改字号会改行高
     ⇒ 每次换句整段重排、画面跟着抖；段落是块级，只有跨段落时才动一次（且有 `transition` 兜着）。
  3. **字号用 `font-size`，不用 `transform: scale()`**：scale 不重排（零抖动）很诱人，
     但它把文字**位图放大** —— 小倍率下中文字边缘先糊。提词器第一要务是"下几个字看得清"。
  4. **"当前字"要留一个播放头**：歌词不必说"唱到哪个字"，提词器必须（下一句可能要等三秒）。
  → 一句话：**歌词优化的是"正在唱的那一行"，提词器必须同时照顾"马上就要念的那几行"。**
  层次取自歌词的四条范式（网易云全屏歌词 / QQ音乐歌词组件 / XCMusic DOM 渲染器）：
  当前行字号最大最亮 → 相邻行按距离逐级变淡 → 逐字从左到右揭示 → 平滑滚动把当前行送到锚点。
  本项目**已有一半**：按句 smooth 滚动 + `anchor` 锚点、`cursor.offset_in_sentence` 逐字进度。
- ★★ **一个颜色只能有一个意思**（同一块界面上）。本项目：绿=已生效/进行中、琥珀=受限/没生效、
  蓝(`accent`)=用户自己按住的状态（暂停 / 已锁定）。**「暂停」用琥珀是错的** ——
  它是正常操作，用警告色会让人去查一个不存在的故障。
  ★ 2026-09-26 补：**同一条纪律也要求"一个意思只能有一个颜色"** ——
  正文里"语音念到哪"（`--read`，默认绿）与"用户点了哪"（`--accent`，蓝）
  此前共用 accent，于是屏幕上"我念到哪"和"我刚点了哪"是同一个颜色。
  现在明读指示单独走 `--read`（当前句底色 / 左侧竖条 / 播放头下划线三处同色）。
  ⇒ 一个颜色只承载一个意思，**一个意思也只用一种颜色**。
- ★★ **内联写在根元素上的 CSS 变量，主题块覆盖不了它**。本轮加 `--read`（跟读颜色）时踩到：
  色板是按深色背景挑的高明度色，放到浅底上做 2px 下划线几乎看不见 ——
  本想"在 `:root[data-theme="light"]` 里再写一遍"就行不通，因为
  `applyLayoutVars` 是用 `style.setProperty` **内联**写到 `documentElement` 上的，
  内联优先级高于任何主题选择器。
  ⇒ 只能由 JS **按解析后的主题**选值（`readColorRgb(key, theme)`），
    且 `system` 必须先用 `resolveTheme` 解成实际的，否则 `system` 下永远拿深色那套。
  ⇒ 验收要**两套都量**：深色 `readVar=52 211 153`、浅色 `readVar=5 150 105`
    （浅色那档刻意与既有 `--ok` 同值 —— 同色号压深一档这件事要和项目已有的档位成套，
    不能随手挑一个"看起来够深"的数）。
- ★★ **"开启中"这类中间态要有动画，而且不能停不下来**。判据是"它有没有在动"，
  所以验证必须读**伪元素**的动画名（扫光挂在 `::after` 上，读元素本身永远 `none`）。
  反面：`stealthBusy` 在异常路径上不清 ⇒ pill 永远转圈 —— **一个"看起来还在忙、其实早就完了"的状态，
  比直接报错还糟**。
- ★★ **界面显示的是"实际在工作"，不是"用户按下的意图"**。穿透为此专门加了
  `ct_working() = ct_enabled() && zones_ok()`；**不能拿 `ct_now()` 驱动状态灯** ——
  它的意思是"此刻光标在不在稿件区"，鼠标一动就翻，灯会闪，而且分不清"没生效"和"光标恰好在栏上"。
- ★★ **删掉长文案之前，必须先确认失败信号还有别处承载**。穿透原先靠一段 138 字的提示兜住"点了没生效"，
  删掉之后**唯一**的信号是"宽限期(2.2s)过后变琥珀"。如果那条不亮，就等于回到"点了没反应"。
  ★★ **同一条纪律也适用于"把控件收走"**（不只是删文案）：本轮把穿透收进设置时，
  那条琥珀信号**跟着控件一起消失了**（详见「产品取向」里 R9 那条）。
- ★★ **控制台那类"常驻状态行"的标签必须由生产者给**（`StatusWarning { label, detail }`）。
  写死过一次「麦克风异常 · 点击自检」，而这条通道有**六个以上**的生产者 ——
  写死就会说假话（隐身没开却显示"麦克风异常"），**比不提示更坏：它把人引到错的地方去查**。
  ★ 该位置是**一个槽、多个生产者按优先级依次占用**（错误 > 后端警告 > 穿透没生效 > 跟读失准 > 剩余时间），
  不是把它们并排挤成一小堆 —— 同"一个颜色只能有一个意思"：**那一行也只能有一个意思**。

- ★★ **可点区域的盒子必须真的等于"看起来能点的区域"**。正文那句"把进度接到这一句"原来挂在
  `<span class="sentence">` 上，而句子是 **inline 元素**：它的盒子只包住**字形**，
  行距（`line-height` 1.7、字号 34 ⇒ 每行约 18px，约占版面三分之一）与行尾空白
  都**不属于它**。用户的话是"有时候点不上"。
  ⇒ 判据：**点击处理器要挂在能包住整个可点区域的那个盒子上**（这里是块级的 `<p>` ——
    块盒高度 = 各行行盒之和，行距落在行盒内），再用**坐标**反查语义
    （`caretRangeFromPoint` + 文本节点累加），**不要靠 `e.target`**。
  ★ 同族：可交互区上报必须按**几何**判可见性（`display/visibility/opacity` + 与视口求交），
    不能只判 `offsetParent`。两处的错法不同，判据是同一条：**"看起来在这里"不等于"盒子上在这里"**。
  ★ 坐标反查的口径要对齐：`s.text.length` 是 **UTF-16 码元**，`Array.from` 是**码点** ——
    两者在 emoji 上差一位，差一位就跳错句。
- ★★ **拖选必须与点击分开，而且判据是"位移"不是"有没有选区"**。正文可以选中复制；
  没有这条，用户"选一段来复制"会顺手把朗读进度跳到他划过的那个字上。
  ⇒ 用按下→抬起的位移（> 6px 放过）。**不能**用"选区非空"当判据 ——
    双击路径本来就会选中一个词，按选区判断会把「快捷跳读关掉 ⇒ 双击跳」整条路堵死。
  ★ 光标形状要跟着命中区走（`cursor` 挂在 `.para` 上，且只在单击生效时才挂）：
    留在字形上等于继续告诉用户"行距那儿点不动"。
- ★ **"关掉"不是"禁用"，所以关掉之后总得有个新说法**。快捷跳读关掉＝改成双击，
  这条约定最容易在改版里静默丢掉，而用户不会觉得"改版了"，只会觉得"误触被取消了"。
  ⇒ 凡是"关掉＝换一种操作方式"的开关，**两种模式都必须各有一条断言**（单击 0 次 / 双击 1 次）。
- ★ **苹果式开关的手感在三件事上，不在形状上**：位移带**回弹**（back-out，如
  `cubic-bezier(0.4, 1.25, 0.5, 1)`）、按住时滑块**横向抻开**（比位移快一半）、
  轨道比滑块**慢一拍**起步。形状（胶囊轨道 + 带投影滑块）只是静态像。
  ★ 抻开必须用 `transform: scaleX()`，**不能改 `width`** —— 后者触发重排，
    而且和位移混在同一条 `transform` 里没法分开给曲线（改版前用的正是 `width`）。
  ★ 位移量存在自定义属性上（`--x`）、由状态改，伪元素只写一条 `translateX(var(--x))`：
    这样 `:active` 那条（保留位移 + 加挤压）不会和 `.on` 那条抢同一个属性 ——
    两条选择器**权重相同**，谁在后面谁赢，那种写法迟早让滑块"弹回左边"。
  ★ 补 `role="switch" + aria-checked`：它是**状态**控件，状态必须能被读屏念出来。
  ★ `prefers-reduced-motion` 下退化为直切 —— 开关是设置里唯一承载"开/关"的地方，动画只是修饰。

## 穿透（click_through）专题

- ★★ **上报「一组矩形」，不是包围盒**：早先控制栏有**两块**（顶部那条栏 + 底部那个控制台），
  合并成包围盒恰好覆盖整窗 ⇒ "在控制区外"永远不成立 ⇒ 穿透一次都不触发。
  **真机量出来的，不是推演。**
  ★ 两条并一条之后这个特例本身不会重现（栏的包围盒就是栏），但**纪律没失效**：
  只要上报的元素超过一块、且分散在窗口两侧（顶栏 + 设置抽屉 + 历史浮层就是这个形状），
  包围盒会再次盖满整窗。所以代码里是"一组矩形"，不是"一个框"。
- ★★ **可交互区收集必须按几何判可见性**，不能只判 `offsetParent !== null` / `getClientRects().length > 0`：
  设置抽屉关着时靠 `transform: translateX(101%)` 挪出窗口，`offsetParent` 仍非空、
  `getBoundingClientRect()` 仍给 352×358 → 被当成可交互区上报，把窗口右侧一条误判成"可点"。
  → 正解：查 `display/visibility/opacity` + **矩形与视口求交** + **把矩形裁进视口**（`App.tsx::visibleRectInViewport`）。
  ★ 其余浮层（`FindBar`/`ScriptHistory`/`PasteImport`）关闭时都 `return null`，只有 `SettingsDrawer` 常驻挂载。
- ★★ **上报失败绝不能静默**（曾写 `.catch(() => {})`）：后端兜底是"没收可交互区就永不切换"，
  于是现象只剩「开关点了没反应」，界面上毫无线索指向"上报链路断了"。现在首次失败弹一条 `WARNING`。
- ★ 后端有路标日志 `[click-through] 可交互区已更新 → …`，**只在形状变化时落一行**（400ms 轮询不刷屏）。
  分岔用：`没这行 ⇒ 断在前端` / `有这行但形状不对 ⇒ 断在 DOM 标了哪些 data-interactive`。
- `sanitize_zones` 判「整份不可信」而非"跳过坏的那几块"：混进一个 `NaN` 会让 `contains` 全 false
  ⇒ 整窗被判"区外" ⇒ 立刻变穿透点不动。空上报 / 超 `MAX_ZONES=32` / 零负尺寸同样整份拒。
- ★★ **真机验证只看两件事，不看截图**（默认 `stealth_on_start:true` ⇒ 抓屏里根本看不到窗口，设计如此）：
  ① 主窗自己的 ex-style 是否含 `WS_EX_TRANSPARENT`；② `WindowFromPoint` → **`GetAncestor(hit, GA_ROOT)`** 后是不是 prompter。
  ★ 坑：WebView2 渲染子窗口属于 `msedgewebview2.exe`（**不同 pid**）且自带 `WS_EX_TRANSPARENT`，
  直接拿返回值的 pid/风格比较会把"窗口好好地在那儿"整片误判成"穿透了"。
  ★ 读窗口 rect 要等 `--settle`（启动头几秒还停在系统默认级联位置，之后才被 `apply_saved_geometry` 挪走），
  否则探的是空气、得到"整列都穿透"的假象。
  ★★ **`[bootstrap]` 是比剖面更重要的断言**：它是前端挂载后调的第一个命令；没有它 = 窗口在、可点、里面空白，
  此时测穿透毫无意义（开关是前端调的）。宁可**直接失败**也不要出数字。
  ★★ **但"没 bootstrap"不等于代码坏** —— 同一个二进制实测有「能起/不能起」两种结果（见「环境坑」的
  WebView2 启动期 flaky 那条）。所以脚本**先重试**，别把 flaky 当结论。
  ★ 可交互区边界：`APPROACH_PAD = 24` 是**屏幕物理像素**，不是 CSS 像素 ——
  本机缩放 1.75 时接近环只有 ~13.7 CSS px。
  ★★ **验收期望值必须从唯一源现算，不能写死区间**（本轮踩过）：
  当时控制台在窗口**底部** ⇒ 期望区间**跟窗口高度绑在一起**，而窗口高度是用户拖出来的
  （本机配置里存的是 274，不是默认的 360）。写死 `"0-88"`、或按 360 高窗口算出来的区间，
  **必然失败**，而失败原因跟"穿透坏了"无关 —— 这种假警报会把人引去查一个不存在的故障。
  ⇒ 用 `--expect-bars`：顶栏/控制台高读 `styles.css` 的 `--h-top`/`--h-cb`，
  接近环读 `click_through.rs` 的 `APPROACH_PAD`；**改版面时不用改脚本，也就不会漏改**。
  实测（560×274，缩放 1.75）：期望 `0-60`，实测 `0-60` ✅（`--h-cb=0` ⇒ 底部无栏）
  ★★ **栏有几条也必须是现读的**：脚本写死"上下两条"的话，底栏一取消它就会凭空
  算出一条底部期望带，把"底部能穿透"（现在这才是正确行为）报成失败 ——
  又一个跟穿透无关的假警报。
  ★ **判据的形状**：剖面的边界只能分辨到一个扫描步长以内 ⇒ 采样点落在期望区间
  **两端 ± tol 之内**应判「不关心」，而不是"期望可点"。写成后者时，1px 的期望误差会被
  tol 放大成 8px 的假警报（首次实跑就报了 64/68 两处"不一致"，纯属容差自己造出来的）。
  ★ **期望区间内出现"穿透"采样点**时先别下结论：真机扫描有噪声（有人动鼠标 / 窗口被挪）。
  脚本单独把它报出来并返回 2，**同一条命令再跑一次**：复现就是真的，不重现就是噪声。
  （本轮实跑抓到过一段 `248-260` 的空洞，重跑即消失。）
  工具：`scripts/verify-click-through.py`（`--step/--hold/--settle/--tol/--tries/--shot/--expect-bars`）。
- ★ 后端路标日志 `[click-through] 可交互区已更新 → N 块 @ x,y W×H | …` 是穿透失效的**第一现场**：
  `没有这行` ⇒ 断在前端（上报没发出/被吞）；`有这行但形状不对` ⇒ 断在 DOM 标了哪些 `data-interactive`。
  只在形状变化时落一行，所以 400ms 一次的上报不会刷屏。

## 环境坑（本项目实测）

- ★★ **"功能没做"要先证伪"用户跑的是不是旧产物"**：曾真踩 —— 用户说「固定的也没有做啊」，实际是他跑着
  改动之前的 exe。决定性证据在数据目录（`%APPDATA%\cn.bobby.prompter\config.json` 只有旧 9 个字段）。
  → 已固化成 `scripts\diagnose-running-build.py`。★ **改代码 ≠ 用户看到变化，交付时必须明说"要重启应用"。**
- ★★ **`LNK1104: 无法打开 …\release\prompter.exe` 没法靠改文件名绕过**：`release\prompter.exe` 与
  `release\deps\prompter.exe` 是**同一文件的硬链接**（`st_nlink==2`、`st_ino` 相同），`os.rename` 掉前者后
  链接器立刻在 `deps\prompter.exe` 上继续报 LNK1104，白忙还留个 22MB 残留。
  **唯一正解：结束旧实例**（`taskkill -F -PID <pid>`，单斜杠）。判据：`os.stat(p).st_nlink > 1` ⇒ 改名不解决问题。
- ★★ **"窗口在、前端空白"有两个**互不相干**的成因，别混成一条**：
  **(a) 页面压根没执行**（连 `[bootstrap]` 都没有）—— 启动期 flaky，同一二进制实测有「能起/不能起」两种结果，
  本轮最后验证里连续两次失败、换全新 profile 的第三次才起来。与我们的代码无关。
  **(b) 页面执行了、但停在中途** —— 实测与配置里 `click_through` 的初值相关：
  该值为 `false` 时日志有 `可交互区已更新`，为 `true` 时 bootstrap 之后什么都没有（连 `开关 → 开` 都没有）。
  `click_through` 在前端只被读一处（`App.tsx` 的 `if (b.config.click_through)`）。**根因尚未查完，只确定了断点。**
  ★ 查这类问题的工具：后端 `frontend_beat` 打点命令 + `scripts/trace-frontend-boot.py`（做 A/B）。
  release 产物**没有 devtools**，前端"停在哪一步"从外面完全看不见 —— 只看 `[bootstrap]` 是分不出 (a)/(b) 的。
  ★ 早先把 0 字节 `.tmp` + `Default/LOCK` 当成"脏 profile"的证据 —— **那是误判**：
  健康 profile 里也有这些（`LOCK` 本来就是 0 字节）。挪走 profile 之所以"管用"，
  是因为它等价于"换一个全新 profile 重试一次"。
  ⇒ **正解是先重试**（`verify-click-through.py` 自动重试 3 次，最后一次换全新 profile）。
  连续 `taskkill /F` 硬杀会提高失败概率（浏览器进程没走完退出流程）。
  ★ 隔离测试实例的另一条路已实测**走不通**：`WEBVIEW2_USER_DATA_FOLDER` 被 wry 显式设的 data dir
  覆盖（临时目录被创建了，页面照样不执行，等 30s 也不行）→ 见 `scripts/probe-webview-udd.py`。
  ★ `taskkill /F /IM` **只杀主进程**，`msedgewebview2.exe` 孤儿会继续占住 user-data-dir → 必须杀
  **父进程已不在**的孤儿（`verify-click-through.py::kill_orphan_webviews`）。
  ★ 判据：`os.stat(p).st_nlink > 1` ⇒ 改文件名不解决 `LNK1104`。
- ★★ **"这个实例能不能测"要两条日志都到齐**：`[bootstrap]` **且** `可交互区已更新`。
  只看前者会把成因 (b) 放进来 —— 那时后端按"整窗可交互"兜底，剖面量出来是 `0-356` 全可点，
  **和"穿透完全没实现"一模一样**（本轮据此误判过一次）。
- ★★ **被外部打断时 `finally` 不保证执行**：Windows 上 `SIGTERM` 即 `TerminateProcess`，**不可捕获**
  （先加信号处理，实测无效）。真踩：一次 run 被打断，`config.json` 停在 `click_through=true`
  ——一个"窗口点不动"的状态。正解：**改动前把原文件另存成 `config.json.verify-backup`**，
  下次运行开头自愈（`heal_leftover_config()`；自测 `scripts/test-heal-config.py`）。
  → 推论：**凡是"改了别人的东西再改回来"的脚本，都不能只靠 `finally`**。
- ★★ **要看 UI 长什么样用 `scripts/ui-preview.py`，别去截老大的真窗口**：headless Edge 渲染 `dist/` +
  注入 `scripts/ui-preview/tauri-stub.js`（假 Tauri IPC），**不需要真窗口、不碰隐身窗口、不和老大抢屏幕**。
  常用：`--out shots/x.png --measure`（`--query` 预置状态、`--hold` 延迟 load、`--snapshot` 抓交互后静态态、`--w/--h/--bg`）。
  ★ 不用真窗口截图的原因：默认隐身 ⇒ 抓屏里看不到窗口（设计如此），且 alwaysOnTop 会挡住老大手头的事。

  **截图 = `W × H`，`--dump-dom`（测量）= `W−32 × H−96`**。那套口诀是按测量模式修的
  ⇒ **截图比真实窗口宽 32px**，而 32px 刚好够标题把话说完 ⇒ 出现"图说没事、数说有事"：
  截图里标题完好，真实窗口里早被省略号截掉（真踩，还据此得出过"那个测量值是我量错了"）。

  正文区图，而单看每一张都像"界面正常"。实测栏的下边框落在 y=46，与 `--h-top: 46px` 一致（缩放 1:1）。

  （切的是两条栏、期望值对着旧 DOM）⇒ **跑它拿到 ✅ 不算新界面验过**。
  新界面的状态验收看 `ui-preview.py --measure` 的
  `titleShort=` / `barParts=` / `slotText=` / `collapsed=` / `heroColor=` 这几个键。
- ★★ **桩脚本一抛异常只会静默变成一张空图**：`--measure` 回一个光秃秃的 `Prompter`（title 没被写），
  截图看着"有内容"。本轮踩过：预置块写在了 `config` 之后，而 `config` 里引用了它
  ⇒ TDZ `ReferenceError` ⇒ 整段桩失效，却**不报错**。
  ⇒ 改完桩先 `node --check`；`--measure` 回 `Prompter` 就是"桩挂了"，不是"功能没实现"。
- ★★ **桩里的 `config` 是手写的 ⇒ 后端 `AppConfig` 每加一个字段，这里就得跟一个**。
  漏了不报错，症状是：**滑块显示 `undefined`、开关一律显示"关"、色点全部不选中**。
  单看截图很像"这个新功能没做"，其实只是桩没跟上（2026-09-26 加「跟读」组时真踩）。
  ⇒ 新增配置字段的收尾清单是**三处**：Rust `AppConfig` + `impl Default`、前端 `types.ts`、桩。
  ⇒ 桩里的默认值要与 `impl Default` **一对一对齐**，这样桩量出来的默认态就等于真机首启的样子。
  ★ 同族：桩需要**回一个夹取后的值**时（`set_jump_range`），那个边界是同一个数的第三处出现
  （Rust 常量 / 设置页滑杆 min-max / 桩）—— 前两处必须，第三处是桩的代价，改常量时记得看。
- ★★ **观察"只存在几十毫秒的中间态"，必须能把时间按住**：
  `slow=1` 让命令悬住不返回（定住"开启中"）；`settle=<ms>` 把**测量**往后推
  （穿透的「未生效」要等 2.2s 宽限期，默认那 1.3s 窗口根本看不到）；
  `--hold` 是**截图**的时间窗口 —— 用 `--hold 7000` 去截"开启中"是错的，
  它早在 2.2s 就变成琥珀了。**三个时间参数各管一段，别混用。**
- ★★ **"改了别人东西再改回来"的脚本会**自持**泄露**：`verify-click-through.py` 把读到的值当"原值"再还原，
  于是一旦漏过一次 `true`，之后每次运行都忠实地把 `true` 还原成 `true`，永远回不去，
  而且**每次都打印"已还原"**（看起来完全正常）。本轮真踩。
  ⇒ 读到 `true` 又**没有副本可自愈**时，必须**出声**（脚本现在会警告）。
  → 推论：**"自愈式还原"要能区分"我改的"和"本来就长这样"，否则它会替你把错误固化下来。**
- ★ **headless 下桩的 `warn=` 能真推事件**：`plugin:event|listen` 记下 `args.handler`，
  就能把一条**真事件**送进前端的同一个回调（`emitTauri()`）。
  没有这条，所有"靠后端事件驱动的界面"在离线预览里永远看不到，只能靠读代码相信它。
- ★ **headless 出图会被"页面底色"包一圈**：窗口圆角外的区域是 headless 的默认底色（本机实测是**红色**，
  而且 `--bg/--default-background-color` **改不动它**）。要给人看的产品图，得按视口偏移裁掉外圈 ——
  `im.crop((16, 48, 16+560, 48+360))`，正好等于窗口本身。
  判据：**别拿带外圈的图当"界面长这样"的证据**，那圈颜色跟我们的 CSS 无关。
- **应用日志时间戳是 UTC**（本机 GMT+8，差 8 小时）—— 看 `Prompter.log` 时别把 14:00 当下午两点。
- ★★ **从助手的 shell 里启动 GUI 应用，它活不过那条命令**（本轮真踩）：即使 `Popen` 带了
  `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`，命令一结束应用就被宿主的 **job object** 回收 ——
  指纹是**日志停在启动成功那一刻、一句退出记录都没有**（= `TerminateProcess`，不是自己退出的），
  现象是"刚说打开了，转眼就没了"，而且很容易被误当成"应用自己崩了"。
  加 `CREATE_BREAKAWAY_FROM_JOB` 也不行：宿主 job 没开 breakaway，`Popen` 直接 `WinError 5`。
  ⇒ 正解是**让别的服务替我们拉进程** —— `Invoke-CimMethod -ClassName Win32_Process -MethodName Create`
  （带 `CommandLine` + `CurrentDirectory`，返回 `ProcessId`）。WMI 服务不在宿主的 job 里。
  ★ 附带好处：这样拉起来的进程不继承宿主注入的 `PYTHONPATH`/`NODE_OPTIONS`，更接近老大自己双击的效果。
  ★ `wmic` 虽已从本机移除，但 **CIM cmdlet（`Invoke-CimMethod`）可用**。
  封装在 `scripts/open-app.py`；判据是「启动后另开一条命令还能看到它」。
- ★★ **"打开了"≠"界面跑起来了"**：判据是 **`[bootstrap]` 与 `可交互区已更新` 两条日志都到**
  （见 `scripts/open-app.py`）。只等前者会把"页面执行了但停在半路"当成成功 ——
  那种实例的剖面是整窗可点，**和"穿透没实现"一模一样**。
- **Bash 里 `python -c "…"` 写文件时正文含反引号会被 bash 当命令替换执行**（静默毁文件：不报错、字节数正常、
  内容少几段）→ 含反引号/`$`/`\` 的文本一律用 Write 工具或先落 `.py` 再执行。
  ★ heredoc（`cat >> f << 'EOF'`）写大段含反引号的中文是**安全**的。
- **`taskkill //F //PID` 不行**（MSYS 把 `//F` 当路径转换），要单斜杠。
- **`wmic` 已从本机 Win11 移除** → 按命令行筛进程改用 Python 枚举顶层窗口 + `GetWindowThreadProcessId` 反查 pid。
- **`Popen` 拉起的背景窗口不指定 `stdout=DEVNULL` 会把上层 `| tail` 卡死**（孙进程握着管道写端）。
- 删大量临时文件用 `subprocess.run(["cmd","/c","del","/f","/q", *files])` 绕开 safe-delete **按轮累计 50 次**上限；
  ★ `cmd` 只认反斜杠路径，传正斜杠会 **rc=0 但什么都不删**（静默失败）。
- 验证/测量**结论要基于量化**（均值/分位），别信缩略图观感 —— 有张图肉眼看着"深色界面"，实测 50% 像素纯白。
- ★★ **桩的 `click=` 是按前缀分派的 ⇒ 名字就是接口**。本轮新增 `click=seekoff` 时它撞上了
  `click.startsWith("seek")` 那条通用探针：一次点击被跑成两次，`gotoN` 多 1 ——
  而多出来的那一次**伪装成"双击跳了两下"**，作者照着 `gotoN=4` 找了一个不存在的 bug。
  ⇒ 新增模式名先 grep 已有分派的前缀；分派尽量用**白名单**而不是前缀。
- ★★ **桩里"连着发三个事件"复现不出事件顺序类 bug**。`mousedown → mouseup → click` 若在**同一个
  宏任务**里连发，React 不会插进来重渲染，闭包还是旧的 ⇒ "mousedown 把状态置 false、click 又取反"
  这类 bug **复现不出来**（正反对照双双通过，等于没验）。
  ⇒ 桩要模拟真实的 task 边界：`mousedown` 与 `mouseup/click` 之间**隔一个宏任务**
    （见桩里的 `realTap`）。判据：**改完之后反向对照能真的复现旧行为**。
- ★★ **断言必须有正反两向，而且要防"监听是死的"式假通过**。本轮三条一起看才有结论：
  `click=doc2`（修好了 ⇒ `historyOpen=no`）、
  `click=doc2out`（点真·面板外 ⇒ 也 `no`，证明 mousedown 那条路**是活的**）、
  `click=doc2nogt`（把标记摘掉再点 ⇒ **必须** `yes`，复现旧行为）。
  只看 `doc2=no` 分不清"修好了"和"监听根本没挂上"。
- ★ **无头环境验不到 `:active`**（合成的鼠标事件不会让元素进入这个状态）。
  能验的只有"这条规则确实编译进了产物"；**真手感（按住抻开）只能真机按一下**。
  ⇒ 别把 `swActiveRule=yes` 当成"手感验过了"。
- ★ **交付图必须可复现**。`shots/final/` 那批原来是手敲命令拍的，参数没留下 ——
  换个人、过一周就没人知道某张图当时用的视口是多少（本项目已有一次教训：
  `shots/s-*.png` 就是这么变成"验了等于没验"的）。
  ⇒ 参数写进脚本（`scripts/shots-final.py`），一条命令重拍全部。
