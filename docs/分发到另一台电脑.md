# 拿到另一台电脑上用（Windows / macOS）

> 这份文档只回答一件事：**怎么把提词器装到另一台电脑上**。
> 项目背景、功能说明看 `README.md`；判断依据看 `docs/判断基线.md`。

## 零、先看清一件事实：这个项目**没有现成的发给别人的东西**

`package.json` 里那条构建命令是 `tauri build --no-bundle`（**刻意不带打包**），
所以仓库里现在躺着的只有：

```
src-tauri\target\release\prompter.exe     ← Windows 可执行文件，22 MB
```

**它不能直接拷给别人用**，原因见下面第一节。要发给别人，得**先出一次包**。

---

## 一、Windows → Windows

### 1.1 为什么不能"就拷那个 exe"

`prompter.exe` 是 **Tauri** 应用：界面不是画出来的，是**套在一个叫 WebView2 的
浏览器内核里**跑（微软 Edge 的引擎）。所以它除了自己的代码，还要两样东西：

| 依赖 | 在哪 | 拷 exe 带得走吗 |
| --- | --- | --- |
| `prompter_lib.dll`、VC++ 运行库 | exe 同目录 / 系统 | Tauri 已静态链接，**不用管** |
| **WebView2 运行时** | 装在系统里（`C:\Program Files (x86)\Microsoft\EdgeWebView\`） | ❌ **带不走**，另一台没有就白屏/闪退 |

Win11 和 Win10（2021 年后打完补丁的）**基本都自带** WebView2，所以"拷 exe"
在**新电脑上大概率能跑** —— 但这是个**碰运气**的做法：对方要是台老 Win10、
或者系统被精简过，你拿到的反馈就是"双击没反应"，而**没有任何错误提示**
（Tauri 起不来时不弹窗）。**发出去的东西不该靠运气。**

### 1.2 推荐做法：出 NSIS 安装包（一个 .exe）

```bash
npx tauri build --bundles nsis
```

产物（实测 **6.1 MB**）：

```
src-tauri\target\release\bundle\nsis\Prompter_0.1.0_x64-setup.exe
```

发这一个文件过去，对方**双击 → 下一步 → 桌面出图标**，完事。

★ **这个安装包本项目已实测过一遍**（2026-09-28，本机验证，不是推测）：

```
静默装到临时目录  → rc=0
  装出来的东西    → prompter.exe (23.3 MB) + uninstall.exe (79 KB)
启动装好的副本    → ✅ 界面跑起来了（[bootstrap] 有日志、可交互区已上报）
静默卸载          → rc=0，目录、开始菜单、AppData 全部无残留
```

⇒ **装得上、起得来、卸得干净**。★ 它装的是**独立一份**，不碰仓库里
那个 `target\release\prompter.exe`（日常开发用的仍是后者）。

★★★ **不要写 `npm run tauri:build -- --bundles nsis`** —— 实测**它什么都不产**，
而且**不报错**：

```
$ npm run tauri:build -- --bundles nsis
> tauri build --no-bundle --bundles nsis        ← 两个参数都在
     Built application at: ...\prompter.exe      ← 只出裸 exe
                                                  ← bundle/ 目录根本没建
```

`package.json` 里那条脚本写死了 `--no-bundle`，而**它把后加的 `--bundles`
压掉了**（`--no-bundle` 的语义就是"不打任何包"）。两个参数同时在场时，
Tauri **不报冲突**、安静地按 `--no-bundle` 执行。

⇒ **出安装包必须绕过那条脚本、直接调 CLI**（`npx tauri build --bundles nsis`）。
★ 这也意味着**别去改 `package.json`**：那条 `--no-bundle` 是 Windows 日常
开发的规矩（"永不产安装包、产物留在仓库里"），改了它日常构建就会多花几分钟
打一堆用不上的包。**两条路各走各的。**

★ **WebView2 怎么解决**：Tauri 默认的 `webviewInstallMode` 是
`downloadBootstrapper` —— 安装包会**在装的时候联网去下 WebView2**，
已装过的机器会跳过。所以：

* 对方**能联网** ⇒ 什么都不用管；
* 对方**不能联网** ⇒ 换下面 1.3 的绿色包，或者改配置把 WebView2 嵌进安装包
  （`tauri.conf.json` 的 `bundle.windows.webviewInstallMode` 设成
  `offlineInstaller`，代价是安装包涨到约 **100 MB**）。

★ 本项目的 `tauri.conf.json` 里 `bundle.targets` 已经是 `["nsis"]`，
`installMode` 是 `currentUser`（**装到当前用户，不弹管理员授权**）——
这两个都是为"发给别人"准备好的，不用改。

### 1.3 备选：免安装绿色包（对方完全不能联网时）

解压双击就能用、不装任何东西、不碰注册表。代价是**体积大**（要把 WebView2
运行时一起塞进去，约 **120~180 MB**）。

做法是给 `bundle.targets` 临时加一个 `nsis` 的离线模式，或者更干脆 ——
**把安装包那次出成 `offlineInstaller`**（1.2 里那条），再把装好的整个目录
打成 zip。★ 注意这条路径**本项目没实跑过**，属于"要用时才去验"的备选。

## 二、Windows → macOS（**另一套东西，exe 完全用不了**）

**`.exe` 在 Mac 上打不开，这不是配置问题，是平台不同。** Mac 要的是 `.app`。
而且 **`.app` 必须在 Mac 上构建** —— 没法在这台 Windows 上生成。

代码侧**已经准备好了**（第九轮做的）：macOS 的后端代码、
平台判定、文案分岔全都写完并且能编译通过。**但行为和界面从没在真 Mac 上跑过。**

### 2.1 在 Mac 上怎么做（对方自己操作，或你把这段发给他）

**前置**（只需一次）：

```bash
xcode-select --install     # Xcode 命令行工具，链接 ObjC 框架必需
```

**拿到代码**：把 `prompter/` 这个目录传过去（★ **只传源码**，
`src-tauri/target/` 有 **21 GB**、`node_modules/` 有 79 MB，**都别传**；
去掉这俩源码只有 **约 11 MB**）。

**构建**：

```bash
cd prompter
npm install
npx tauri build --bundles app        # ★ 不要走 npm run tauri:build，见下
```

产物：

```
src-tauri/target/release/bundle/macos/Prompter.app
```

★★★ **`--bundles app` 必须显式给，而且必须绕过 `npm run`**：

* `package.json` 那条 `tauri:build` 写死了 `tauri build --no-bundle`
  —— 那是 **Windows 的规矩**（本项目"永不产安装包"），它会**把 `--bundles`
  压掉**、且**不报错**（Windows 上实测：只出裸 exe，`bundle/` 目录根本不建）。
* `tauri.conf.json` 的 `bundle.targets` 是 `["nsis"]`（Windows 专属打包器）
  ⇒ **不显式给 `--bundles` 可能找不到匹配 macOS 的 target 而报错**。

两条加起来：**在 Mac 上必须是 `npx tauri build --bundles app`**。

★ 要同时出 `.dmg`（Mac 上的安装镜像）就用 `--bundles app,dmg`。

★ 图标：`src-tauri/icons/` 里那 14 个 PNG 是 `scripts/make-icons.py` 生成的。
**`.icns` 由 Tauri 打包时自己合成**，不用手工准备 —— 但**必须跑过
`make-icons.py`**，否则打包期会报缺图标。

### 2.2 ★★★ 第一次打开会被 macOS 拦住（正常现象）

`Prompter.app` 没做 Apple 签名/公证，macOS 会拦：

> **「Prompter」无法打开，因为 Apple 无法检查其是否包含恶意软件。**

这不是出错，是 Gatekeeper 对**未签名应用**的标准行为。两种放行方式：

* **右键点 app → 选「打开」→ 弹窗里再点「打开」**（只需一次，之后双击就正常）；
* 或 `系统设置 → 隐私与安全性` → 底部会有「仍要打开」。

★ 如果提示更狠（「已损坏，无法打开」），那是下载/传输过程带了隔离属性：

```bash
xattr -dr com.apple.quarantine /路径/Prompter.app
```

★ **别**教用户去关 Gatekeeper、也别 `sudo spctl --master-disable` —— 那是
把整台机器的防护关掉，为一个小工具不值得。（要做正式分发只有一条路：
交 99 美元/年的 Apple 开发者账号 + 公证，本项目现阶段不做。）

### 2.3 ★★★ 到了 Mac 上，这些功能**可能不工作**（诚实清单）

代码编得过、判定也对，**但没有一条在真 Mac 上验过**。按"会不会推翻可用性"
排序：

| 项 | 风险 | 说明 |
| --- | --- | --- |
| **投屏隐身是否真让窗口从共享里消失** | 🔴 最高 | macOS 15+ 得用私有 API，**这是唯一可能推翻"双平台"定位的未知项**。前 10 分钟就该试这个 |
| 应用起来时 Dock 有没有图标 / 退不退得出去 | 🟡 | 以 `.accessory` 语义启动，Dock 行为未验 |
| 热键 `⌘+⌥+方向键` 是否与 Mission Control 冲突 | 🟡 | 冲突的话要换键位 |
| 透明窗口的点击穿透 + 圆角裁切 | 🟡 | Windows 上正常，Mac 的合成器不一样 |
| 穿透的 40ms 轮询会不会影响续航 | 🟡 | 笔记本上要留意 |
| **「收进任务栏」这颗按钮** | ✅ 已处理 | macOS **没有"任务栏"这个东西**，所以那颗按钮在 Mac 上**整个不渲染**（顶栏 4 颗而非 5 颗）。设置里那行文案也自动变成「收起窗口」 |

★ 另外**麦克风**：这台的麦阵列在系统层面被掐掉了（设备 `ACTIVE`、未静音、
音量 82.5%，但只送数字静音），所以"真人说话 → 出字"这一段**从没在真实
声音上跑过**。换一台麦克风正常的机器本来就能顺带补上 —— Mac 上正好试。

## 三、发给别人之前的检查清单

```
□ 出包（别拷裸 exe）
    Windows → npx tauri build --bundles nsis      → bundle/nsis/*-setup.exe（约 6 MB）
    macOS   → npx tauri build --bundles app       → bundle/macos/Prompter.app
    ★★ 两条都**不要**写 `npm run tauri:build -- --bundles ...`（不产包且不报错）
□ 自己先在本机装/开一次，确认能起来（别把没验过的包发出去）
    ★ 装法：`...setup.exe /S /D=某个临时目录`（静默、指定目录），
      再用 `python scripts/open-app.py --exe <装好的prompter.exe>` 看界面起没起，
      验完 `uninstall.exe /S` 卸掉。
      —— Windows 那条路径本项目已按这个流程走通一遍（见 1.2）。
□ 告诉对方：这是未签名软件，首次打开要右键「打开」（Mac）
□ 告诉对方：第一次要用「导入稿件」选一个 txt/md 文件
□ （Mac）明说哪些功能"还没验过"，别让他以为是你没做好
```

★ **别把 `src-tauri/target/` 传过去**（21 GB）。传源码时只要
`src/`、`src-tauri/`（不含 `target/`）、`scripts/`、`package.json`、
`package-lock.json`、`vite.config.*`、`tsconfig*.json`、`index.html`、
`src-tauri/icons/`。

## 四、一句话总结

* **Windows → Windows**：`npx tauri build --bundles nsis`，
  发那个 **6.1 MB** 的 `Prompter_0.1.0_x64-setup.exe`。**就这么简单。**
* **Windows → macOS**：`exe` 完全用不了，把**源码**（不是 exe）传过去，
  在 Mac 上 `npx tauri build --bundles app`，第一次右键打开。
  **但先把自己的预期压住** —— 隐身/穿透这些核心能力在 Mac 上
  **一次都没真跑过**，第一次运行就是第一次验证。
* ★★ 两条路都**不要**写成 `npm run tauri:build -- --bundles ...`：
  那条脚本里的 `--no-bundle` 会把它压掉，**不产包、不报错**。
