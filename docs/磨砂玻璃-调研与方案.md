## 2. 调研（全部标注来源；「官方确认」与「未查到」分开）

### 2.1 技术路径：Tauri v2 内置 `windowEffects`（官方确认）

Tauri v2 在窗口配置里内置了 `windowEffects` 字段，**不用引第三方 crate**：

```jsonc
"windows": [{
  "transparent": true,                 // 官方 schema 原话：Requires the window to be transparent
  "windowEffects": {
    "effects": ["acrylic"],            // 数组：取当前系统支持的第一个
    "state": "followsWindowActiveState", // macOS only
    "radius": 12,                      // macOS only；decorations:false 时必需
    "color": [9, 9, 11, 180]           // Win10 v1903+ 只对 blur/acrylic 有效；macOS 只影响 Liquid Glass
  }
}]
```

运行时也可用 `window.setEffects()` 动态切换（设置页开关的落点）。

**Effect 支持矩阵**（官方 schema + window-vibrancy README 双重确认）：

| 效果 | 平台 | 磨的是窗口后面吗 | 官方标注的坑 |
|---|---|---|---|
| `mica`（云母） | Windows 11 | ❌ **采桌面壁纸**，不看窗口后面 | — |
| `acrylic`（亚克力） | Windows 10/11 | ✅ 磨窗口后面 | **Win10 v1903+ / Win11 22000 拖拽、resize 性能差** |
| `blur` | Win7/10/11(22H1) | ✅ | Win11 22621+ 拖拽性能差 |
| `tabbed` | Win11 | 类 Mica | — |
| NSVisualEffectMaterial（`hudWindow` 等） | macOS 10.10+ | ✅ behindWindow blending | — |
| **Liquid Glass** | **macOS 26+** | ✅ | radius/tint/opaque/`interactive`(macOS 27+) |

来源：
- Tauri 官方 config schema（`windowEffects` / `WindowEffectState`）：https://github.com/tauri-apps/tauri/commit/b68afe5fe43b7ef1f5f7f8ffafc4f2b45b5701d1
- Tauri 官方 JS API `Effects` 接口（`effects/state/radius/color/interactive`，及"macOS 可同时指定一个 Liquid Glass style + 一个 Visual Effect material 作 macOS 15 及以下 fallback"）：https://v2.tauri.org.cn/zh-cn/reference/javascript/api/namespacewindow/
- window-vibrancy README（函数支持矩阵 + Tauri 集成三前提：body transparent / `transparent:true` / `macOSPrivateApi`）：https://github.com/tauri-apps/window-vibrancy/
- window-vibrancy **0.8.1（2026-10-01 发布）** 新增 `apply_liquid_glass` + `LiquidGlassOptions`：https://crates.io/crates/window-vibrancy/0.8.1

### 2.2 Windows 侧的两个硬约束（社区实录 + 官方 issue）

| 约束 | 内容 | 对我们的意义 | 来源 |

### 2.3 苹果设计规范（HIG + WWDC 2025/2026）

| 原则 | 内容 | 对提词器的映射 | 来源 |
|---|---|---|---|
| **分层** | Glass 属于**控件/导航层**（toolbar、sidebar、浮动面板），**不属于内容层**；内容保持清晰 | 天然吻合：**那条栏是导航层**，稿子区是内容层 | https://www.brilworks.com/blog/apple-human-interface-guidelines |
| **HUD panel 先例** | macOS 的 HUD 风格面板＝**暗色半透明**，就是为浮窗设计的 | 提词器**整个就是 HUD**——整窗磨砂在苹果体系里是合法形态（HIG「Dark Mode HUD-style panel」） | https://github.com/carlosfloriani/hig-mapeado/blob/main/transversal/macos.md |
| Regular vs Clear | Regular 自适应、文本场景用；Clear 恒透明，**只给媒体场景**，建议 35% 暗化层 | 稿子要读 ⇒ 任何方案都必须保证**文本层是高对比的** | https://developer.apple.com/videos/play/wwdc2025/219/ |
| 不叠玻璃 | 父子同时上效果＝视觉噪声 + 浪费 GPU | 整窗材质之后，**栏自己的 CSS 玻璃要退掉**（否则两层磨） | 同上 |
| Tint 克制 | 只标记主要操作 | 大圆按钮的绿保留，其余不染色 | 同上 |
| 无障碍 | Reduce Transparency / Increase Contrast / Reduce Motion 全要验；同一玻璃在不同背景上读起来完全不同 | 已有 `no-glass` 开关，正好对接 | 同上 |
| **活靶子** | WWDC 2026（v27）已根据反馈**降低默认透明度**、重做 sidebar 圆角、加了 clearer↔tinted **用户滑杆** | 追 Liquid Glass 像素级复刻 = 追移动目标；**取神不取形** | 同上 |

## 3. 目标 / 非目标 / 指标

**目标**

1. 窗口外壳呈现苹果式磨砂质感：透得出身后内容、糊得掉细节、有材质的光感（不是一片纯色半透）。
2. **稿子可读性不降** —— 磨砂是氛围，稿子是命。
3. 隐身、穿透、性能**三项立身之本零回归**。

**非目标**

- 不做 Liquid Glass 的像素级复刻（折射光、透镜边缘、交互动效）—— 苹果自己 v27 还在改，追它是无底洞。**取神（材质分层、圆角、克制 tint）不取形。**
- 不改信息架构、不动控件布局 —— 这一轮只换材质。
- Linux 不做（官方明确不支持，效果由 compositor 决定）。

**可断言指标**（验收时逐条打勾）

1. 开启磨砂后，窗口放在**白底 PPT** 上：稿子文字对比度 ≥ 现状（拿同一张图前后量，用 `scripts/measure-alpha.py` 的思路量文字区 alpha/对比）。
2. 开启磨砂后，窗口放在**花背景**（桌面壁纸/视频）上：背景细节**不可读**（糊掉），但能感知颜色与明暗变化（透）。
3. 隐身实测（`verify-stealth.py` 流程 + 真实会议抓屏对比）**与现状一致**。
4. 穿透实测（`verify-click-through.py`）**与现状一致**。
5. 连续滚动 60s：无明显掉帧（肉眼 + `no-glass` 开关随时可退）。
6. 门槛全绿（含 `check-hover-silent.py`），新增断言全部做过变异测试。

## 5. 方案设计

### 5.1 核心架构分叉：Windows 的失焦问题怎么处置

Acrylic 失焦变实色，而**提词时提词器永远失焦**（焦点在 PPT/翻页软件上）。三条路：

| 路线 | 做法 | 得 | 失 |
|---|---|---|---|
| **A. 当特性（推荐）** | 接受系统行为：失焦=实底+CSS 玻璃，聚焦=磨砂 | **提词时稿子对比度最高**（正是要的）；摆弄窗口时磨砂最美（正是给人看的）；**与 macOS 系统行为一致**（苹果失焦也不用 materials）——这不是 bug 是两大系统的共同设计 | 想要"一直磨砂"的人得不到 |
| B. workaround 保持磨砂 | 监听焦点，失焦时自己维持 Acrylic active 态 | 磨砂恒定 | 逆系统设计、提词时对比度反而下降、多一段焦点监听代码 |
| C. 不用 Acrylic | Windows 维持现状 CSS 玻璃，只 macOS 上材质 | 零风险 | **Windows 上"磨 PPT"这个核心诉求没解决**，等于只做了半个需求 |

**我推荐 A**：把"失焦变实"讲成「提词中自动进入高对比模式」——它是系统设计、零代码、还对主场景有利。设置页那句常驻小字正好说这件事（按第十一轮判据：这是"当前口径"，该常驻）。

### 5.2 设置页落地（合并式布局）

现有「背景模糊」开关（`config.glass`）**升级为一个档位行**：

```
背景磨砂    [关 | 柔光 | 系统磨砂]     ← seg-btn 三档，合并进现有行，不开新面板
            系统磨砂＝透出身后内容但糊掉 · 提词时（失焦）自动变实底
```

- `关` = 现状实色（`win-alpha` 1.0 那套）
- `柔光` = 现状 CSS 玻璃（现在的 glass=true 行为）
- `系统磨砂` = windowEffects（Win: acrylic / macOS: liquidGlass+hudWindow）

`config` 新字段 `glass_mode: "off" | "css" | "system"`（`#[serde(default)]`，老配置自动落 `"css"` 保持现状——**遵守不可破第 3 条：Rust AppConfig + Default + types.ts + 桩四处同步**）。

### 5.3 工程顺序（先验证风险最大的）

1. **Spike（半天）**：本机 `windowEffects:["acrylic"]` 硬编码上窗 → 立刻验三件事：隐身回归、穿透回归、滚动掉帧。**任何一项砸了，方案退回 5.1-C 并如实记录。**
2. P0 落地（档位行 + CSS 玻璃退位 + 桩断言）。
3. 门槛 + 变异测试 + 出包。
4. P1 留给 Mac 真机轮（与现有未验证清单合并成一次）。

## 6. 风险与**我的反对意见**

### 风险表

| 风险 | 等级 | 处置 |
|---|---|---|
| stealth 被材质砸掉 | 🔴 高 | spike 第一件事；砸了退回方案 C |
| Acrylic 拖拽/变尺寸卡顿（收起/展开动画） | 🟡 中 | spike 实测；卡则 Acrylic 只在窗口静止时挂、动画前卸下 |
| Win11 旧 build / Win10 上 Acrylic 行为不一致 | 🟡 中 | 档位行第三档文案标注「Windows 10/11」；异常时用户可退「柔光」 |
| 两层磨（系统材质 + CSS 玻璃叠加） | 🟡 中 | P0-3 强制退位，桩断言 |
| 透明度滑杆与材质的语义打架（两个"透"） | 🟡 中 | 系统磨砂档下 opacity 滑杆**隐藏**（一个意思一个控件） |
| macOS 一切行为未真机验证 | 🟡 中 | 并入现有真机清单，不单独承诺 |

### 我的反对意见（PM 必须敢写的那一条）

> **这个需求的真实价值可能不在 Windows，而在 macOS。**
>
> 拆开看：Windows 上 Acrylic 是唯一"能磨 PPT"的路，但它失焦失效、拖拽卡、版本行为参差——
> 而**提词器的典型场景恰恰是失焦**。也就是说 Windows 用户拿到的最稳定形态，
> 其实和现状（实底 + CSS 玻璃）差别不大，磨砂只在"摆弄窗口的那几秒"出现。
> 真正"一直磨着 PPT"的美好画面，**只有 macOS vibrancy/Liquid Glass 能给**。
>
> ⇒ 所以我反对把这一轮做成"双平台大改版"。正确姿势是：
> **Windows 只做 spike 验证 + 一个档位开关（小步），真正的体验交付押在 Mac 真机轮。**
> 如果 spike 发现 Windows 侧任何一项立身之本回归，就干脆 Windows 不上材质，
> 不要为了一个观感功能去动隐身的地基。

## 十一、实现状态（2026-10-04）

### 11.1 Spike 结论（先做的那半天）

| 验什么 | 结果 |
|---|---|
| Acrylic 能否上窗 | ✅ `windowEffects` 一行配置就够，不需要引 crate |
| 穿透回归 | ✅ `verify-click-through.py` 通过（可点区间 0–60 CSS px 照旧，`click_through` 回落 false） |
| 隐身回归 | ⚠️ **无冲突迹象，但本机无法给出正面证据**：`stealth_on_start=true` ⇒ 窗口一直在保护态（`affinity=0x11`），`verify-stealth.py` 那个「切一次隐身看画面变没变」的断言在这里**不可观测**。真实会议抓屏对比仍留在未验证清单 |
| 收起/展开（尺寸动画）卡顿 | 本轮未单独量（收起是瞬时动画，肉眼无感；需要时用「关」档一键退） |
| 脚本坑 | `verify-stealth.py` 偶发 `OSError: screen grab failed` —— 已定位为 **PIL/Win32 GDI 的瞬时竞争**（同一窗口 12/12 次抓屏正常、整屏抓屏正常），**与 Acrylic/隐身无关**。该脚本的 GDI 抓屏路径仍偏脆，建议后续换成 DWM 抓屏 |

### 11.2 落地形态（与方案 §5.2 的两处偏差，均为更安全的写法）

| 项 | §5.2 原写法 | 实际落地 | 为什么改 |
|---|---|---|---|
| 材质挂载 | 写在 `tauri.conf.json` 的静态 `windowEffects` | **运行时装**：`commands::apply_glass_mode` —— 启动时按配置挂一次，之后每次 `save_config` 检测到档位变化就换（含 `set_effects(None)` 真正卸下） | 静态配置**没法表达"关"**：窗口一建出来材质就挂着，用户点「关」只能关 CSS 那一层 ⇒ P0-6 天然不成立 |
| 三档默认值 | 老配置落 `"css"` | 老配置**按旧 `glass` 布尔折算**：`false ⇒ "off"`、`true/缺失 ⇒ "css"`（`state::migrate_legacy_glass`，JSON 层迁移 + 单测钉死四种输入） | 固定默认值会把用户**明确关过**的模糊偷偷开回来 —— 不报错、只掉帧，正是本项目最判的那种"设的东西没记住" |
| 「关」档的不透明度滑杆 | 暗示 `win-alpha` 归 1.0 那套 | **保留滑杆**：`关`＝实色底 + 外壳仍按滑杆透明（与老 `glass:false` 的界面逐像素一致） | P0-2 的验收写的是「切到关后与**现状**一致」；老用户关的只是玻璃，不是透明度 |
| 系统磨砂档的滑杆 | 隐藏 | 隐藏，且外壳 alpha 固定让位到 **0.22** | 一个意思一个控件；0.22 让材质主导、字仍可读（外壳太实会把磨砂整个盖住） |

### 11.3 ★ 与本文档第 2 节的一处订正：当前工具链**没有** Liquid Glass

§2.1 写的 `effects: ["liquidGlass", "hudWindow"]` 来自官方 JS API 文档，但**本仓库锁定的
`tauri-utils 2.9.3` 的 `WindowEffect` 枚举里根本没有 LiquidGlass 这个变体**（本地
`~/.cargo/registry/src/*/tauri-utils-2.9.3/src/lib.rs` 只有 `AppearanceBased…UnderPageBackground`
+ `Mica* / Tabbed* / Blur / Acrylic`）。

⇒ **拍板 ④ 的落地口径改为：macOS 走 `hudWindow`（经典 vibrancy）**。
Liquid Glass 要等**升 Tauri** 或**引 `window-vibrancy 0.8.1`**（`apply_liquid_glass`），
那是 P1 真机轮的一个前置决定，不该在文档里先写成已有能力。

**教训（已进 `docs/判断基线.md`）：官方 JS 文档会领先于本仓库锁定的 crate 版本；
判断"这个 API 我有没有"要以本地 registry 里那份源码为准，不是以官网示例为准。**
