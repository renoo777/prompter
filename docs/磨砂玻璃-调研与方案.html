2. 调研（全部标注来源；「官方确认」与「未查到」分开）

2.1 技术路径：Tauri v2 内置 windowEffects（官方确认）

Tauri v2 在窗口配置里内置了 windowEffects 字段，不用引第三方 crate：

"windows": [{
  "transparent": true,                 // 官方 schema 原话：Requires the window to be transparent
  "windowEffects": {
    "effects": ["acrylic"],            // 数组：取当前系统支持的第一个
    "state": "followsWindowActiveState", // macOS only
    "radius": 12,                      // macOS only；decorations:false 时必需
    "color": [9, 9, 11, 180]           // Win10 v1903+ 只对 blur/acrylic 有效；macOS 只影响 Liquid Glass
  }
}]

运行时也可用 window.setEffects() 动态切换（设置页开关的落点）。

Effect 支持矩阵（官方 schema + window-vibrancy README 双重确认）：

效果平台磨的是窗口后面吗官方标注的坑
mica（云母）Windows 11❌ 采桌面壁纸，不看窗口后面—
acrylic（亚克力）Windows 10/11✅ 磨窗口后面Win10 v1903+ / Win11 22000 拖拽、resize 性能差
blurWin7/10/11(22H1)✅Win11 22621+ 拖拽性能差
tabbedWin11类 Mica—
NSVisualEffectMaterial（hudWindow 等）macOS 10.10+✅ behindWindow blending—
Liquid GlassmacOS 26+✅radius/tint/opaque/interactive(macOS 27+)

  • Tauri 官方 JS API Effects 接口（effects/state/radius/color/interactive，及"macOS 可同时指定一个 Liquid Glass style + 一个 Visual Effect material 作 macOS 15 及以下 fallback"）：https://v2.tauri.org.cn/zh-cn/reference/javascript/api/namespacewindow/
  • window-vibrancy README（函数支持矩阵 + Tauri 集成三前提：body transparent / transparent:true / macOSPrivateApi）：https://github.com/tauri-apps/window-vibrancy/

2.3 苹果设计规范（HIG + WWDC 2025/2026）

原则内容对提词器的映射来源
分层Glass 属于控件/导航层（toolbar、sidebar、浮动面板），不属于内容层；内容保持清晰天然吻合：那条栏是导航层，稿子区是内容层https://www.brilworks.com/blog/apple-human-interface-guidelines
HUD panel 先例macOS 的 HUD 风格面板＝暗色半透明，就是为浮窗设计的提词器整个就是 HUD——整窗磨砂在苹果体系里是合法形态（HIG「Dark Mode HUD-style panel」）https://github.com/carlosfloriani/hig-mapeado/blob/main/transversal/macos.md
Regular vs ClearRegular 自适应、文本场景用；Clear 恒透明，只给媒体场景，建议 35% 暗化层稿子要读 ⇒ 任何方案都必须保证文本层是高对比的https://developer.apple.com/videos/play/wwdc2025/219/
不叠玻璃父子同时上效果＝视觉噪声 + 浪费 GPU整窗材质之后，栏自己的 CSS 玻璃要退掉（否则两层磨）同上
Tint 克制只标记主要操作大圆按钮的绿保留，其余不染色同上
无障碍Reduce Transparency / Increase Contrast / Reduce Motion 全要验；同一玻璃在不同背景上读起来完全不同已有 no-glass 开关，正好对接同上
活靶子WWDC 2026（v27）已根据反馈降低默认透明度、重做 sidebar 圆角、加了 clearer↔tinted 用户滑杆追 Liquid Glass 像素级复刻 = 追移动目标；取神不取形同上
失焦行为macOS 窗口非激活时不用 materials、自动显得更远与 Windows Acrylic 的失焦行为系统级一致 —— 这其实就是苹果和微软共同的选择https://github.com/carlosfloriani/hig-mapeado/blob/main/transversal/macos.md

3. 目标 / 非目标 / 指标

目标

  1. 窗口外壳呈现苹果式磨砂质感：透得出身后内容、糊得掉细节、有材质的光感（不是一片纯色半透）。
  2. 稿子可读性不降 —— 磨砂是氛围，稿子是命。
  3. 隐身、穿透、性能三项立身之本零回归。

非目标

  • 不做 Liquid Glass 的像素级复刻（折射光、透镜边缘、交互动效）—— 苹果自己 v27 还在改，追它是无底洞。取神（材质分层、圆角、克制 tint）不取形。
  • 不改信息架构、不动控件布局 —— 这一轮只换材质。
  • Linux 不做（官方明确不支持，效果由 compositor 决定）。

可断言指标（验收时逐条打勾）

  1. 开启磨砂后，窗口放在白底 PPT 上：稿子文字对比度 ≥ 现状（拿同一张图前后量，用 scripts/measure-alpha.py 的思路量文字区 alpha/对比）。
  2. 开启磨砂后，窗口放在花背景（桌面壁纸/视频）上：背景细节不可读（糊掉），但能感知颜色与明暗变化（透）。
  3. 隐身实测（verify-stealth.py 流程 + 真实会议抓屏对比）与现状一致。
  4. 穿透实测（verify-click-through.py）与现状一致。
  5. 连续滚动 60s：无明显掉帧（肉眼 + no-glass 开关随时可退）。
  6. 门槛全绿（含 check-hover-silent.py），新增断言全部做过变异测试。

5. 方案设计

5.1 核心架构分叉：Windows 的失焦问题怎么处置

Acrylic 失焦变实色，而提词时提词器永远失焦（焦点在 PPT/翻页软件上）。三条路：

路线做法得失
A. 当特性（推荐）接受系统行为：失焦=实底+CSS 玻璃，聚焦=磨砂提词时稿子对比度最高（正是要的）；摆弄窗口时磨砂最美（正是给人看的）；与 macOS 系统行为一致（苹果失焦也不用 materials）——这不是 bug 是两大系统的共同设计想要"一直磨砂"的人得不到
B. workaround 保持磨砂监听焦点，失焦时自己维持 Acrylic active 态磨砂恒定逆系统设计、提词时对比度反而下降、多一段焦点监听代码
C. 不用 AcrylicWindows 维持现状 CSS 玻璃，只 macOS 上材质零风险Windows 上"磨 PPT"这个核心诉求没解决，等于只做了半个需求

我推荐 A：把"失焦变实"讲成「提词中自动进入高对比模式」——它是系统设计、零代码、还对主场景有利。设置页那句常驻小字正好说这件事（按第十一轮判据：这是"当前口径"，该常驻）。

5.2 设置页落地（合并式布局）

现有「背景模糊」开关（config.glass）升级为一个档位行：

背景磨砂    [关 | 柔光 | 系统磨砂]     ← seg-btn 三档，合并进现有行，不开新面板
            系统磨砂＝透出身后内容但糊掉 · 提词时（失焦）自动变实底
  • 关 = 现状实色（win-alpha 1.0 那套）
  • 柔光 = 现状 CSS 玻璃（现在的 glass=true 行为）
  • 系统磨砂 = windowEffects（Win: acrylic / macOS: liquidGlass+hudWindow）

config 新字段 glass_mode: "off" | "css" | "system"（#[serde(default)]，老配置自动落 "css" 保持现状——遵守不可破第 3 条：Rust AppConfig + Default + types.ts + 桩四处同步）。

  2. P0 落地（档位行 + CSS 玻璃退位 + 桩断言）。
  3. 门槛 + 变异测试 + 出包。
  4. P1 留给 Mac 真机轮（与现有未验证清单合并成一次）。

我的反对意见（PM 必须敢写的那一条）

这个需求的真实价值可能不在 Windows，而在 macOS。 拆开看：Windows 上 Acrylic 是唯一"能磨 PPT"的路，但它失焦失效、拖拽卡、版本行为参差—— 而提词器的典型场景恰恰是失焦。也就是说 Windows 用户拿到的最稳定形态， 其实和现状（实底 + CSS 玻璃）差别不大，磨砂只在"摆弄窗口的那几秒"出现。 真正"一直磨着 PPT"的美好画面，只有 macOS vibrancy/Liquid Glass 能给。 ⇒ 所以我反对把这一轮做成"双平台大改版"。正确姿势是： Windows 只做 spike 验证 + 一个档位开关（小步），真正的体验交付押在 Mac 真机轮。 如果 spike 发现 Windows 侧任何一项立身之本回归，就干脆 Windows 不上材质， 不要为了一个观感功能去动隐身的地基。
